# 0038：更大的地图与更远的矿池

状态：已完成。

## 目标与依据

用户希望把矿池距离拉远、地图变大，即坐标系统整体扩大；并要求矿机必须建在矿池上。

## 范围

服务端 `game/layout.py`：地图边长 100 → 150；矿池离边缘至少 15（原 10）、矿池间距至少 30（原 15）、离收购点至少 30（原 20）；收购点仍在地图中心 (75, 75)；4 名居民的初始位置同乘 1.5。矿池半径 4、收购点半径 5、感知与听力半径 20、行走速度 2.5 不变。脚本机器人的探索点（`agents/scripted_brain.py`）同乘 1.5。

客户端协议与渲染读取服务端给的地图边长，不需要改代码；只更新文档。

矿机必须建在矿池上：服务端 `economy/rigs.py` 已要求建造和安装时站在该矿池半径内（`not_at_pool`），矿机按矿池编号绑定并画在矿池中心，现有测试已覆盖，本次不改。

设计文档：无。

## 关键选择

- 边长取 1.5 倍；矿池间距取 2 倍，使矿池之间明显更远，同时 6 个池子仍放得下。具体倍数由用户的“扩大一点”决定，未经试玩验证。
- 距离变大后走路耗 token 也按比例增加（每单位 1 token），矿池到收购点单程最远约 100 token，开局只有 200，经济平衡待试玩调参。

## 验收条件

- [x] 默认世界边长 150，收购点在 (75, 75)，矿池满足边距、间距、离收购点的新下限。
- [x] 脚本机器人在默认地图快进一局后仍买芯片、采矿并赚到金币。
- [x] 不站在矿池内无法建矿机或安装芯片。

## 验证证据

- 客户端 `npm run verify` 与 `python3 scripts/check_repo.py` 通过。未在浏览器中实测 150 的地图显示（镜头缩放是否合适）；未重新跑 AI 对局。
