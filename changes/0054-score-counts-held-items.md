# 0054：排名计入能量与晶核

状态：已完成；已由 [0057](0057-rank-by-coins-again.md) 撤销。

## 目标与依据

路线图第 ④ 步的第二部分（用户 2026-11-04 要求“开始第四步”，计划中列了“结束时把手里的能量和晶核折算计入排名”）。以前排名只算金币，手里的能量、晶核在结束时一文不值。2026-11-03 的基线对局里，有居民在结束前 5 分钟内买了 8 块 C3，最后排名垫底，见 [经济指标](../docs/design/economy-metrics.md)。另外，晶核改由居民炼制后，炼好还没卖出的晶核也应当有价值。

可观察的变化：

- 排名改按得分：金币总额加持有物估值。能量按收购点当时的单价计，晶核按进口价的一半计（C1 300、C2 1200、C3 3000），晶砂不计。
- 页面排名显示得分和构成（金币 + 估值）；AI 观察里每人有 `item_value`、`score`；系统提示说明得分规则，不再说“剩下的东西一文不值”。
- 经济报告的每名居民多了 `item_value`、`score`，控制台多一行得分。

## 关键选择

- **折算比例沿用计划**：能量按收购价、晶核按进口价的一半，是 Claude 在变更 0051 的计划中提出的。
- **对局中也实时计算**：原计划只在结束时折算。现在页面和 AI 观察的得分都按当时的价格计算，排名口径前后一致，AI 也知道手上的物品有价值，不用在结束前清仓。服务端时钟在结束后不再推进，所以结束那一刻的得分就是最终得分。
- **能量按单价计**：不按“全部卖给收购点能得多少”的积分计算，否则持有越多单位估值越低，反而奖励最后抛售。
- **计入范围**：携带的、报价和卖单中预留的能量与晶核，以及装在汲能塔里的晶核；结束时它们都会退回本人。进行中的汲取、挖砂、炼制不计，因为结束时这些作业作废。出局的居民物品已清空，估值为 0。
- **基尼系数仍按金币**：经济报告的 `coin_gini` 不变，便于和基线比较。

## 验收条件

- [x] 估值 = 拥有的能量 × 收购点当时的单价 + 拥有的晶核 × 进口价 × 0.5，向下取整；没有收购点时能量不计；晶砂不计；报价、卖单中预留的和装在汲能塔里的晶核照样计入；出局后为 0。
- [x] 排名按得分；结束时撤回的挂单物品照样计入，得分不变。
- [x] 协议、页面排名、AI 观察和经济报告都给出估值与得分；系统提示说明规则。

## 验证证据

- 服务端 `make verify`（审查修复后）：ruff、格式检查、mypy strict 通过，1142 项测试通过（原有 1 条 Starlette 弃用警告）。
- 客户端：`npm run typecheck`、`npm run lint` 通过，`npx vitest run` 212 项通过，`npm run build -w apps/web` 通过。
- 独立审查（子 Agent，只读）：脚本构造卖单、买单、晶核出售报价、能量求购报价和装进别人汲能塔的晶核，`end_game` 前后 4 人的估值、得分和名次完全相同；结束后收购价不再变动。确认的问题均已修复：
  - P1：结束前追加给模型的提醒仍写“只有金币算数，去收购点卖掉能量”，与新规则相反：改为“持有的能量和晶核计入得分，不必清仓，最后大量卖出只会压低所有人的估值价”，并加测试。
  - P3：补上收购价涨过基准价时的估值测试；控制台得分的断言拆成单独的测试；`status.md` 的总体设计条目、`crystals.md` 里“结束时物品不计分”的理由、`core/inventory.py` 注释改成新口径；页面排名说明写明得分随服务端推送更新。
  - 未改：脚本机器人结束前仍把能量卖到只剩 1 个，按新规则会降低得分；快进模拟拿它当基线时要注意，留给以后调整机器人策略。
- 浏览器实测（无头 Chrome 1400 px）：用 0053 的脚本世界，排名面板显示“排名”，每行是得分和“（金币 + 估值）”，例如“16,263（9,460 + 6,803）”，名次按得分排列，说明文字写清折算规则。没有实测窄屏。
