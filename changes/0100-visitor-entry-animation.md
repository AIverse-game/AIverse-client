# 0100：访客进城的动画

状态：已完成。

## 目标与依据

用户（2026-11-11）：增加一个游客进入游戏的动画，可以像 `demos/neon_spawn_lobby.html` 那样。

可观察的变化：页面打开后新进城的脚本访客不再在入口处凭空出现，而是在地图中央出生台的光柱里从无长到原大、转两圈停下，光柱随之一亮一暗，然后走向它此刻该在的位置。

## 范围

- 页面：`render/visitorEntry.ts` 进城动画的时间线；`VisitorLayer` 认出新进城的访客、先把它画在入口、再不跳变地走出去，并给出光柱亮度；`LobbyLandmark.update` 接收这份亮度；`characterCrowd.add` 可以按比例缩放单个方块人；`visitorWalk.catchUp` 可以指定跳变距离。
- 设计文档：修改 [脚本访客](../docs/design/visitors.md)（设计思路、争议讨论、暂未实现）。
- 不做：访客出城的动画；协议和服务端不变。

## 关键选择

- 用“上一份 `visitors` 消息里没有”判断刚进城，不扩协议：服务端只有出城（`away`）的访客不在消息里。另加两个条件（`newArrivals`）：离入口不超过 8 个单位；和上一份画过的消息相隔不超过 3 秒。页面打开后的第一份消息、标签页从后台回来后的第一份消息都不播放，免得一批访客从出生台追向全图（独立审查发现）。
- 动画数值照 demo 的出生：1.2 秒，大小线性增长，额外转 4π 线性减到 0，光柱亮度 sin(πk)。这是 Claude 的取舍，用户未逐项确认。

## 验收条件

- [x] 新进城的访客在出生台上长出、转动，光柱变亮（浏览器实测，见下）。
- [x] 时间线的开头、中点、结束与时钟早于首次看到时的处理（`visitorEntry.test.ts`）。
- [x] 从入口走出时不受 8 个单位跳变限制（`visitorWalk.test.ts`）。
- [x] 只把上一份没有、离入口近的访客算作刚进城；首份消息、隔得太久、不知道入口时都不算（`visitorEntry.test.ts` 的 `newArrivals`）。

## 验证证据

- 客户端 `npm run verify`：通过（类型检查、ESLint、32 个文件 315 个测试、构建；在只含本次改动的临时工作树里跑）；`python3 scripts/check_repo.py` 通过。
- 独立审查（子 Agent，只读，两轮）：第一轮确认标签页从后台回来时一批访客会从出生台追向全图（已加时间间隔与距离条件修复）、设计文档一处旧说法、判定逻辑缺单元测试；第二轮确认修复成立，又指出测试没守住“上一份里没有”、文档一句服务端行为说错、本说明未更新，均已处理。
- 浏览器：另起服务端（端口 8011，日志目录在临时目录）和 `npm run dev`（端口 5181），用无头 Chrome（swiftshader）经 CDP 每 120 毫秒截一张出生台附近的图：开局 120 秒内访客陆续进城，光柱持续变亮，新访客在出生台中心出现后走开；没有在入口以外的地方凭空出现的访客。截图分辨率有限，长出与转动的中间帧只能大致辨认。
- 未执行：真实 GPU 上的帧率；访客很多时同时进城的观感只在开局看过。
