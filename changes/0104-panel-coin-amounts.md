# 0104：排名面板的金币照金币特效画

状态：已完成。

## 目标与依据

用户（2026-11-11）：把右边面板上的金币做成类似局内加金币特效的那种样子，加金币的时候在面板上展示数字变化的特效，并且在旁边写上一个红色的 +xxx；把“金币”两个字去掉。

可观察的变化：金币排名里每名居民的金额由像素金币和带描边的金色像素数字组成，后面没有“金币”二字。金额增加时数字在 0.8 秒里跑到新值、放大发亮，金币转一圈，左边浮出红色像素字的“+增加额”，2.4 秒里上浮淡出。

## 范围

- 页面：`render/coinPixels.ts` 像素金币与像素数字的画法（从 `coinSprites.ts` 抽出，不依赖 Three.js，加了逗号字形和红色配色）；`coinSprites.ts`、`CoinBurstLayer.ts` 改用它；`ui/coinCountUp.ts` 数字跑动与金币转动的时间线；`ui/CoinAmount.tsx` 金额组件；`RankingPanel.tsx` 改用它；`styles.css` 的放大与上浮动画（含减少动态效果时关闭）；删除不再使用的 `ui/CoinIcon.tsx` 及其样式。
- 设计文档：修改 [设施收入的金币特效](../docs/design/income-effect.md)。
- 不做：其他面板里的金币文字；减少时的“−”；声音。协议和服务端不变。

## 关键选择

- 理解“右边面板上的金币”为右侧操作面板列最上面的金币排名，那是面板里唯一按居民列出金币余额的地方；“金币”二字指金额后面的单位。标题“金币排名”保留。
- 像素按整数 2 倍放大，保持清晰；红色增加额浮在金币左边、不占行内位置，避免这一行跳动。这些是 Claude 的取舍，用户未逐项确认。

## 验收条件

- [x] 排名里的金额是像素金币和金色像素数字，没有“金币”二字（浏览器实测，见下）。
- [x] 金额增加时数字跑到新值、金币转动，左边出现红色“+增加额”并在约 2.4 秒后消失；未变化的行不动（浏览器实测）。
- [x] 数字跑动的起点、终点、缓动，升降两个方向各自单调、不越界，金币恰好转一圈（`coinCountUp.test.ts`）。
- [x] 连续两次增加时放大发亮各播一次（浏览器实测，见下）。
- [x] 设施上方的金币特效不变：`drawCoin` 原样搬到 `coinPixels.ts`，`drawAmount`、`amountSize` 与原来 `CoinSprites.amount` 的宽高、偏移和两遍上色逐行等价，特效只传 `+金额`、用不到新加的逗号（独立审查逐行核对）；`coinPixels.test.ts` 测了金额图的尺寸。

## 验证证据

- 客户端 `npm run verify`：通过（类型检查、ESLint、35 个文件 345 个测试、构建；在只含本次改动的临时工作树里跑）；`python3 scripts/check_repo.py` 通过。
- 浏览器：另起服务端（端口 8011）和 `npm run dev`（端口 5181），用无头 Chrome（swiftshader）经 CDP 驱动；页面里包一层 WebSocket，把最近一份 `state` 里八名居民的金币分别加 260、37、1240、0、8、0、0、5 后再送给页面。截图：截到的前六行里，增加的几行左边出现红色 +260、+37、+1,240、+8，数字在跑动中途（如 10,250、11,191）并发亮放大，之后停在 10,260、11,240 等；增加额约 2.4 秒后消失；没变的行不动。这是注入的数据，不是真实对局里的收入。
- 浏览器（连续增加）：同样注入，先给第一名加 260，300 毫秒后再加 500、给第二名加 90。第二次增加时第一名的数字在跑动中途（10,751）重新放大发亮，红字换成 +500；之后停在 10,760、10,090，红字约 2.4 秒后淡出。
- 独立审查（子 Agent，只读，两轮）：第一轮没有 P0～P2，确认的 P3 是连续增加时放大不重播且可能卡住、减少动态效果时金币仍转、变更说明的依据与交接不准、测试写法，均已修复；第二轮确认修复成立，只指出本说明的验证证据未写全，已补上。
