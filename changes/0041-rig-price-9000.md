# 0041：矿机建造价从 8000 提到 9000

状态：已完成。

## 目标与依据

用户要求“把矿机的价格再提高一点”，没有给具体数字。[变更 0037](0037-lock-hold-and-rig-price.md) 把价格从 4000 提到 8000；这次取 9000，是比 8000 稍高、又低于 0037 中评估过的 10000 的折中。

## 范围

服务端：`RIG_PRICE` 从 8000 改为 9000。协议字段不变，`rigRules.price` 的值变为 9000，页面和 Agent 提示都读服务端给的值。更新客户端测试数据、服务端 README、状态文档和矿机设计文档。

设计文档：修改 [矿机设计](../docs/design/mining-rigs.md)。

## 关键选择

- 9000 是我按“一点”估的，用户没有给数字，可再调。
- 开局金币 10000：MK1 加矿机（9300）买得起；MK2 加矿机（10200）和 MK3 加矿机（12000）买不起，必须先手工采矿攒钱。与 0037 时 MK2 加矿机开局仍买得起不同。

## 验收条件

- [x] 服务端建矿机花 9000 金币；协议与页面不需要改代码。

## 验证证据

- 服务端：`make verify`，ruff、格式、mypy strict 与 917 个测试通过。几处测试把居民金币写死为 9000（按旧价 8000 剩 1000 做押金），改为 10000；websocket 测试的 `rigRules.price` 期望值改为 9000。
- 客户端：`npm run verify` 通过；`python3 scripts/check_repo.py` 通过。
- 未在浏览器中实测，未重新跑 AI 对局。
