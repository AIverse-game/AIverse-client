# 0077：移植四个 demo 的设施模型，地图渲染迁到 Three.js

状态：已完成（自动检查通过，页面效果已在无头 Chromium 中截图核对；未在真实 GPU 上测过帧率）。

## 目标与依据

用户（2026-11-08）在 `demos/` 放了四个 Three.js 参考 demo，要求按它们给广告位、公共工作空间、出生大厅和 NPC 角色建模，移植到 `aiverse-client` 而不改 demo；出生大厅里的传送门拆出来作为传送门设施的模型，大厅里不再有门。第一版用 Phaser 的 2D 图形手工画成等距多边形，用户随后要求“尽可能还原 demo 的效果，必要时迁移到 Three.js”：Phaser 版还原不了动画、灯光和真正的遮挡，所以整个地图渲染迁到 Three.js（[决策 0007](../docs/decisions/0007-three-js-map-renderer.md)）。

## 范围

- 渲染层整体换成 Three.js：地面（贴图、厚板、网格、产权高亮、选中框）、设施、居民、出生大厅、名字与坐标轴标签、相机、射线点选。React 界面、状态、协议和网络层不变。
- 模型照 demo 的建模与动画移植：广告位（悬浮屏幕、三条广告轮播与噪点、跑马灯、脉冲台、光点）、工作空间（玻璃会议室、两排工位、咖啡吧、休息区、前台、电话间、滚动的代码屏）、传送门（拱门、流动光幕、旋转方块）、出生大厅（不含传送门）、方块角色（居民与 NPC 共用）。游戏厅没有 demo，按变更 0076 的外观用 Three.js 重做。
- 镜头：滚轮平移，Ctrl 或捏合缩放，右键拖动旋转，左键拖动平移。
- 不做：协议和服务端改动；页面显示真正的脚本访客；demo 的昼夜灯光开关和区域标签；保留大厅下的地块。

设计文档：新增 [出生大厅与 NPC](../docs/design/lobby.md)；[虚拟设施](../docs/design/facilities.md)的页面美术一段和“暂未实现”已更新。决策：[0007](../docs/decisions/0007-three-js-map-renderer.md)。

## 关键选择

- 整个地图改用 Three.js，不混用 Phaser：同一个三维场景里居民、设施、地面的遮挡由深度缓冲决定，demo 的代码可以几乎原样使用。依赖 `three` 与 `@types/three`，删除 `phaser`；生产包从约 1.7 MB 降到约 0.9 MB。
- 为让 demo 的颜色与亮度不变，关闭 Three.js 新版的颜色转换，灯光强度乘以 π（r128 的约定）。
- 一个工作空间有几百个方块，`ModelBuilder` 按材质把方块合并成少数网格；静态的工作空间只建一份原型，各地块克隆它；设施只在种类或展示份数变化时重建。
- 点击改为射线：居民和设施用不可见的命中盒，地面用 y = 0 平面；Shift 点击仍按地面点走路，传送门仍不可点击。
- 大厅占中间 3 × 3 块地、不保留地块、商店朝南、NPC 只是页面摆设：见设计文档，都是 Claude 的决定，待用户确认。

## 验证证据

- 客户端 `npm run verify`：类型检查、ESLint、Vitest 19 个文件 155 个测试、生产构建通过。新增测试覆盖相机的位置、拖动、滚动、缩放、旋转与限位，地块尺寸与命中高度，地面贴图的选择，大厅的位置与出生台高度，`ModelBuilder` 的按材质合并、分组变换和未合并物体的放置，NPC 巡游与姿态。旧的 Phaser 专用测试随旧代码删除。
- 页面核对：在会话草稿目录里装了 Playwright 和 Chromium（不是项目依赖），启动独立的服务端（8100 端口）和页面，用 WebSocket 脚本让六名居民走到地块上、买地、按需建设工作空间、广告位、传送门、游戏厅并放入内容，再截图。看过：默认视角、缩放与右键旋转、全景、四种设施各自的近景、点击后的状态（点广告位选中 L9-5，点地面选中 L7-11，点居民选中它，Shift 点击后居民“行走中”）。另把 demo 原件在同一浏览器里截图对照颜色与结构。截图在会话草稿目录，未提交。
- 过程中截图发现并修复：大厅地板底座放错高度，把出生台埋住；游戏厅角柱的顶灯埋在柱子里。
- 未做：无头浏览器用软件渲染，没有量帧率；没有在真实 GPU、触控设备上测；没有同时建很多设施（例如整图二十个工作空间）。
