# 0068：地块份额与自动分账

状态：已完成。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤的第 4 步，用户（2026-11-07）要求开始做：“地块份额与自动分账，份额转让。”

可观察的变化：每块地分成 100 份，买地时全部归买主；广告位每个付款日的收入按份额比例自动分给持有人；持有人可以把份额转给别人（可收费，也可白送）。AI 居民多了 `offer_shares` 工具，观察里能看到每块地的持有人、自己能分到多少，以及收到和发出的份额报价。页面和协议不变。

## 范围

服务端（`aiverse-server`）：

- `core/land.py`：`Parcel` 多了 `shares`（持有人与份数，共 `PARCEL_SHARES` = 100 份，缺省为买主全部持有）和 `held_by`；`core/world.py` 的不变式要求持有人都是已知的居民；`core/ledger.py` 加渠道 `shares`。
- `economy/shares.py`（新）：`split_income`（按份额分账，凑不整的金币按小数部分大的先得）、份额报价事件 `ShareOffer`、已许诺份额统计 `reserved_shares`；`economy/ads.py` 的 `pay_visitors` 改为按份额分给持有人。
- 原语 `OfferShares`；答复和撤回沿用 `RespondToEvent`、`WithdrawEvent`。
- Agent：工具 `offer_shares`、按状态选工具、观察（`MyParcelView` 的持有人和自己的预估收入、`LandView.stakes`、`share_offers_to_me`、`my_share_offers`）、系统提示。

## 关键选择

见设计文档“争议讨论与决定”中第 4 步的取舍：每块地 100 份、按份额分账与凑整规则、份额转让是持有人发出的报价且价格可为 0、已许诺的份额不能再许诺、份额只管收入而建设施和放内容仍归买地的人、出局的持有人照样收款。均为 Claude 的取舍，用户尚未逐项确认。

## 验收条件

- [x] 买地后买主持有全部 100 份；份额不合法（总数不是 100、重复持有人、非整数、持有人不存在）被拒绝。
- [x] 付款日广告位的收入按份额分给持有人，各人所得之和等于总收入，每人一条 `visitors` 流水；凑整规则对所列边界成立。
- [x] 份额报价发出时不动份额和金币；对方同意后份额和价款（如有）转手并记 `shares` 流水；拒绝或撤回后什么都不变，份额可以再次许诺；价格为 0 时不记流水。
- [x] 已许诺的份额不能再许诺；同一人给同一名居民最多同时挂 3 份报价；不持有份额、地块不存在、份数或价格不合法、对象是自己或已出局的居民，都被拒绝且世界不变；对方付不起款时同意失败、报价仍留着。
- [x] 出局撤销该居民的份额报价；出局的持有人照样收款；卖光份额的买地人仍可放内容，没买地的持有人不能。
- [x] AI 居民能发份额报价、答复和撤回；观察里有持有人名单、自己的预估收入和份额报价；没有份额的居民不会被提供 `offer_shares`。
- [x] 页面收到的状态里没有份额报价（`offers` 只含物品报价）。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，982 项测试。新增用例：`tests/unit/core/test_parcel_shares.py`（份额校验、世界的持有人不变式）、`tests/unit/economy/test_shares.py`（分账凑整、付款日分账与流水、报价的发出与同意与拒绝、重复许诺、付不起款、不合法的报价、出局、买地人与持有人的权限）、`tests/unit/agents/test_share_tools.py`（工具、观察、选工具）、`tests/unit/economy/test_land.py`（买地得到全部份额）、`tests/unit/server/test_protocol.py`（页面看不到份额报价）。
- 独立审查（独立子 Agent）：未发现 P0～P2 缺陷。它另外用随机序列（300 个种子 × 60 步：报价、同意、拒绝、撤回、出局、付款日）验证了每块地份额总和恒为 100、付款日居民金币增量恰等于 `visitors` 流水之和、结束后金币总额不变，均通过。采纳的疑点：同一对居民之间的待答复份额报价没有上限，会撑大对方的提示，已加上限 3 份并补测试。保留不处理的疑点：价格 0 的份额报价与总体设计“不提供直接赠送金币”的精神有出入（份额不是金币，已写入设计文档，试玩时留意）；平局的零头总归 id 较小的持有人（至多每个付款日 1 金币）；买地人卖光份额后可以不再放内容，持有人没有办法（已写入设计文档的取舍）；`share_offers_to_me` 里的 `cut_per_payday` 是向下取整的估计，与实际凑整可能差 1 金币。
- 未做：浏览器验证（页面未改）；没有用真实模型跑过份额的玩法，不知道模型会不会用 `offer_shares`。
