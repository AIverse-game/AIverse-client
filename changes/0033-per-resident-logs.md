# 0033：每局覆盖的角色日志

状态：已完成。

## 目标与依据

用户要求服务端在日志目录中按角色分别记录每轮的操作、时间点、记忆和输出，新一局覆盖旧日志。

## 范围

- 默认在服务端项目的 `logs/` 为每名居民创建 `<id>.jsonl`，不需要额外开关；`--log-dir` 可指定位置。
- 新一局（当前即启动服务端）以写入模式覆盖已知角色的日志，不删除目录中的其他文件。同一局内停止或更换 AI 继续追加。
- 保留可选的 `--agent-log FILE` 汇总文件，改为每局覆盖，与角色日志同时记录。
- 记录每个 AI 决策轮的编号、角色、模型、经营方针、现实 UTC 起止时间、游戏起止秒数、动作时间/参数/结果/资源变化、完整观察（含轮前记忆）、轮后记忆、模型返回的文本、最终摘要、异常和取消标记。
- 模型异常及被停止的未完成轮次也落盘；日志文本中的本局已使用的模型 key 在序列化前脱敏，不记录隐藏推理。
- 修改既有 [AI 居民设计](../docs/design/ai-residents.md)。不改协议或页面，不调用真实外部模型。

## 关键选择

JSONL 延续现有记录格式，每轮一行并立即 flush。日志文件在进程生命周期内打开和关闭；没有启动 AI 的角色也有空文件。每轮数据包括私聊和笔记，只保存本地并由 Git 忽略。直接嵌入 `create_app` 的调用方仍可自行选择记录回调，默认落盘由命令行入口提供。

## 验收条件

- [x] 默认命令即创建全部角色文件，重启覆盖，同局重启 AI 不覆盖，角色记录互不混杂。
- [x] 记录完整的时间、动作、记忆、模型输出与异常/取消；每轮写后即可读取。
- [x] 模型 key 不进入文件/控制台记录，特殊字符与 JSON 转义不绕过脱敏。
- [x] 自动检查、日志联动验证和独立审查完成。
