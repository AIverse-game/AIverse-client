# 0069：合买地块

状态：已完成。

## 目标与依据

用户（2026-11-07）在第 4 步完成后提出：买地不只是个人，也可以两人直接买，这样一个人钱不够时可以凑钱合买。并决定：仍然是买地人经营，由提议的人写明对方出多少钱、拿多少份。

可观察的变化：站在没人买的地块里的居民可以向另一名居民提议合买，写明对方出多少金币、拿多少份；对方同意后一起买下，提议的人是买地人。AI 居民多了 `joint_buy_parcel` 工具，观察里能看到收到和发出的合买提议。页面和协议不变。属于[虚拟设施](../docs/design/facilities.md)第 4 步的补充。

## 范围

服务端（`aiverse-server`）：

- `economy/joint_purchase.py`（新）：事件 `JointPurchase`（地块的列和行、对方出的钱、对方拿的份数）、提议人预留的钱统计 `reserved_purchase_coins`。
- 原语 `OfferJointPurchase`（地块取提议人站着的那块）；`game/lifecycle.py` 的 `total_coins` 把预留的钱计入排名。
- Agent：工具 `joint_buy_parcel`、观察（`joint_purchases_to_me`、`my_joint_purchases`、`coins_in_offers` 含预留）、按状态选工具、系统提示。
- README。

文档：设计文档（第 4 步补充）、状态、代码地图。

留给后续：多人合买、改由持股最多的人经营、页面显示（第 8 步）。

设计文档：修改 [虚拟设施](../docs/design/facilities.md)。

## 关键选择

用户已决定：买地人经营；提议人写明对方出多少钱、拿多少份。其余见设计文档“第 4 步补充”：提议人那份预留并计入排名、地块被别人先买走时同意失败而报价留着、同一对居民最多同时 3 份、只做两人。均为 Claude 的取舍，用户尚未逐项确认。

## 验收条件

- [x] 提议时只预留提议人的那份，不买地，排名总额不变。
- [x] 对方同意后地块成立：买地人是提议人，份额按约定分，两人各付镇上一笔（付 0 的一方没有流水），金币守恒。
- [x] 对方出 0 或出全款都可以；拒绝、撤回、提议人出局、对局结束时预留的钱退回，没有流水。
- [x] 地块已被别人买走时提议被拒绝；提议后被别人买走，同意失败而报价留着，撤回可退钱；对方付不起时同意失败而报价留着。
- [x] 份数不在 1～99、出的钱不在 0～地价、不是整数、对象是自己或已出局的人、提议人付不起自己的份、提议人在走路，都被拒绝且世界不变；同一对居民第 4 份被拒绝。
- [x] 合买后只有买地人能在地块上开工建设，对方不能。
- [x] AI 居民能提议、答复和撤回；观察里有合买提议并且预留的钱计入 `coins_in_offers`；在没人买的地块里能选到工具，别人已买的地块里选不到。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，1016 项测试。新增用例：`tests/unit/economy/test_joint_purchase.py`（预留、同意、出 0 与出全款、各种结束方式退款、被抢先买走、付不起、不合法的条款、自己与已出局的人、走路中、上限、买地人经营、对方出局退款、同一块地两份提议、排名不降）、`tests/unit/agents/test_joint_purchase_tools.py`（工具、观察与排名、地块被买走的标记、选工具）。
- 独立审查（独立子 Agent）：未发现 P0～P2 缺陷。它另外跑了随机序列（3000 个种子 × 40 步：合买提议、单人买地、同意、拒绝、撤回、出局、对局结束），每一步居民金币总额加付给镇上的流水恒等于开局金币，生成了 189 块合买的地，所有世界不变式都通过。采纳的疑点：`coins_in_offers` 的字段说明过期，已改；合买提议的视图没有“地块已被买走”的信号，已加 `parcel_taken`；一个测试在断言里改变状态且混了两个行为，已拆开；补了对方出局退款、同一块地两份提议、排名不降的测试。保留不处理的疑点：对方出全款只拿 1 份而提议人一分钱不出（按用户决定，条款在视图里看得到）；没有可合买的对象时仍提供工具（调用会干净地失败）。
- 未做：浏览器验证（页面未改）；没有用真实模型试过会不会用 `joint_buy_parcel`。
