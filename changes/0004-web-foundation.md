# 0004：网页端底层框架

状态：已完成。

## 目标与依据

用户要求先实现项目底层框架：首版运行在网页上并部署到 GitHub Pages，使用框架搭建，做适当分层；最终为前后端分离、前端只渲染服务端状态的架构，但现阶段不实现后端，前端跑通即可。

可观察的变化：本地 `npm run dev` 或 GitHub Pages 页面上能开始一局，看到若干调试用规则居民在小镇五个区域间移动、采集、制作和休息，回合推进到结束；状态全部来自浏览器内的“本地服务端”。

## 范围

- 采用 [0001 网页端技术栈与分层](../docs/decisions/0001-web-stack-and-layering.md)：npm workspaces、TypeScript、Vite、React、Phaser、Vitest、ESLint、zod。
- 新增四个共享包：协议、规则引擎、权威宿主、规则 Agent；新增网页客户端。
- 规则引擎只实现最小生产切片：区域移动（逐跳寻路）、采集、制作面包、两种休息、等待、背包上限、体力不足与材料不足的失败；数值取自总体设计第 4 节。
- 宿主实现回合时钟、决策截止、超时/异常/非法输出转为等待、按观察者裁剪状态并广播。
- 本地模式：宿主运行在 Web Worker 中，消息经 JSON 序列化传递，模拟未来的网络连接。
- GitHub Pages 构建与部署工作流。

留给后续任务：市场委托与撮合、系统收购、公开消息、房间与准备流程、真实模型接入、Node 服务端与 WebSocket 传输、事件记录与复盘、正式美术。

## 关键选择

见决策记录 0001。核心约束：客户端主线程只依赖协议包，不导入引擎、宿主或 Agent；浏览器内的本地服务端是唯一例外，位于 `apps/web/src/local-server/`，由 ESLint 规则强制。

## 验收条件

- [x] `npm run verify` 依次通过类型检查、ESLint、Vitest 测试与生产构建。
- [x] 引擎测试覆盖逐跳移动、采集产出、背包满、体力不足、材料不足、两种休息、相同种子与动作的确定性结算、对局结束后拒绝推进。
- [x] 协议测试覆盖非法结构、未知动作、取值越界（未知区域、错误类型）与超长文本被拒绝；多余字段被剥离而非拒绝，以容忍模型输出的额外键。
- [x] 宿主测试覆盖：超时、抛错、非法输出转为等待；迟到结果被丢弃；观察者只看到自己的私有信息；结束或停止后不再调度；单个连接发送失败只移除该连接；引擎异常时中止对局并上报。
- [x] 本地服务端集成测试：连接、开局、多回合推进，所有下发消息可经 JSON 往返而不变。
- [x] 生产构建使用相对路径，能在任意 GitHub Pages 子路径下加载；本地预览页面实际渲染并推进回合。
- [x] 客户端主线程以静态、动态或相对路径方式导入引擎、宿主或 Agent 时 ESLint 报错；本地服务端无法启动时界面显示错误。

## 验证证据

环境：macOS，Node 22.19.0，npm 10.9.3，Chrome（无头模式）。日期 2026-10-25。

- `npm run verify` 退出码 0：各工作区 tsc（宿主另跑 `tsconfig.test.json`）、`eslint .`、Vitest 7 个文件 47 个测试、`vite build`。
- `python3 scripts/check_repo.py`：PASS，82 个文本文件。
- ESLint 分层探针（`npx eslint --stdin --stdin-filename`）：以下写法均报错——客户端静态、动态、模板字符串导入引擎/宿主/Agent；客户端导入 local-server；任何层用相对路径跨包导入；宿主导入 Agent；协议导入内部包；共享包使用 `Math.random`、`Date.now`、`new Date`、全局计时器、`crypto`、`globalThis`、`self`。同包深层目录的相对导入、本地服务端导入宿主、测试文件使用计时器都不误报。
- 宿主源码使用 `crypto` 或 `globalThis.setTimeout` 时 tsc 报错，测试文件的 Node 类型不会泄漏到源码。
- 构建产物：引擎、宿主、Agent 的特征字符串只出现在 worker 包；index.html 与 Worker 均使用相对路径。
- 无头 Chrome 冒烟：构建放在 `/aiverse/` 子路径下，点击“开始对局”后 7 秒推进到第 5 回合，面板、排行榜、日志正常，无控制台错误；截图确认地图渲染正确（期间修复了区域半透明导致道路透出的问题）。删除 worker 文件后，界面显示“无法连接”和错误原因。
- 独立审查：首轮没有 P0–P2，3 条 P3（宿主发送失败卡住对局、ESLint 分层缺口、Worker 失败时界面静默）均已修复并补测试。复核确认这 3 条已解决，又提出 2 条 P3（相对路径规则误拦深层目录、动态导入绕过）和 2 个疑点（丢弃会话时不通知传输层、错误措辞放在 store），均已处理。二次复核确认这些修复成立，又提出 1 条 P3：连接的 `close()` 抛错会中止整局。已修复，`close` 抛错时只吞掉该错误，对局继续，并改写测试覆盖；同时补上 local-server 的动态导入限制。这最后一处修复只做了自查和测试，没有再交独立复核。
- 已知但保留：`**/src/**` 规则同样会拦截第三方包的深路径导入（如 `phaser/src/...`），目前代码没有这种用法，以后需要时再把规则收窄为只匹配相对路径。
- 未执行：GitHub Actions 实际运行（无远程仓库）、窄屏与移动端实测、浏览器内跑满 60 回合（由假时钟集成测试覆盖）。
