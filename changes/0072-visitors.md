# 0072：脚本访客

状态：已完成（首版，只计人数，不付钱）。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤第 7 步的第一部分。第 7 步（访客与赞助商）很大，开工前向用户确认了范围，用户（2026-11-07）的决定：

1. **全做，但分多次变更**：脚本访客、赞助商按展示付费、工作空间与游戏厅的入场费，都在第 7 步里做，分三个变更。
2. **入场费由系统统一定价**，居民不定价（留给第三个变更）。
3. **去掉“站着的居民给附近加流量”**（留给第二个变更，随占位流量公式一起被替换）。

三个变更的拆法（Claude 的安排，用户只确认了“分多次”）：

- **0072（本次）脚本访客**：一批脚本做的游客在地图上走，按偏好选展示着内容的广告位去看，路过或停留够久算一次展示，累计到各地块；走不走传送门由他们自己选。**不付钱**，广告位的收入仍按占位的流量公式。
- **下一个：赞助商**：赞助商带预算、按展示付费，替换占位的流量公式，去掉居民加流量。
- **再下一个：工作用户与入场费**：访客分类型，工作用户先去工作空间再去游戏厅，系统统一定价的入场费，访客的消费池。

可观察的变化：开局的世界里有 200 个访客（还没进城，开局 120 秒内陆续进来）；广告位展示着内容时，他们会去看，AI 居民的观察里自己每块地多了 `people_seen`，是访客“看过”这块地广告位的累计人数。金币、排名、协议和页面都没变。

## 范围

服务端（`aiverse-server`）：

- `core/visitors.py`：不可变的 `Visitor`（阶段、出发点与目标、起止时刻、经过的传送门、目的、本趟的步数、已逛的广告位）和 `Crowd`（种子、全部访客、各地块被看到的人数）；`World.crowd`，默认空。
- `economy/visitors.py`：规则。`new_crowd`、`visitor_position`（任意时刻的位置，解析地算）、`advance_crowd`（走完或待完一段后的下一步）、`next_visit`、展示计数、按多项 logit 选目的地。
- `economy/portals.py`：`Router`，访客用的路线：直走，或走到一个线路网里最近的门、一步出到离目标最近的门再走，取较短的。
- `game/clock.py`：访客的下一步接进到点结算和 `next_due`；`game/layout.py`：默认世界带 200 个访客；`server/app.py`：只有访客的走动不算新消息，不广播。
- `agents/observation.py`：自己的地块多 `people_seen`。
- README、测试。

留给后续：赞助商与按展示付费、去掉居民加流量、工作用户与入场费（上面的两个变更）；多个入口；访客总量随内容变化；页面显示访客（第 8 步）。

设计文档：修改 [虚拟设施](../docs/design/facilities.md)（第 7 步的拆分、本次的取舍与暂未实现）。

## 关键选择

取舍和首版数值见设计文档“争议讨论与决定”的第 7 步第一部分。要点：访客只在一段走完或待完时才有事件，位置按时间解析地算；随机用“种子 + 访客编号 + 趟数 + 步数 + 用途”的哈希，同一局可重现；选目的地用 Gumbel 噪声加最大效用，等价于多项 logit；展示在走完一段时结算；访客走线路不付过路费；只有访客在动不广播。均为 Claude 的取舍，用户尚未逐项确认。

## 验收条件

- [x] 访客从中央入口进城，选一个展示着内容的广告位走过去，待一段时间后继续选，逛完 2～4 个后走回入口离开，待一阵再来；位置在任意时刻都在走过的线上，离开地图时没有位置。
- [x] 停留或路过够 4 秒算一次展示，计入该地块被看到的人数，每人次的权重随时间增长；同一访客 120 秒内不重复计同一个广告位，也不会再选它，换一趟也一样。
- [x] 没有内容的广告位、游戏厅、传送门不吸引访客也不计展示；没有可看的就在附近随机走一段，不出地图，漫游用掉一个“站”，所以最终会离开。
- [x] 内容越多、离得越近的广告位吸引越多访客；已经很多访客在去或在那里的广告位吸引力下降（拥挤度）；同一刻处理的访客，先走的人腾出的位置对后走的人生效。
- [x] 线路连通时，访客走到最近的门、一步出到离目标最近的门再走；线路没连通不省路；路径上经过的广告位按走过的两段算展示，跳过的那段不算。
- [x] 同一种子同一局走出同样的结果，另一个种子不同。
- [x] 到点结算和服务端时钟会等访客的下一步；只有访客动时不广播，其他变化照常广播。
- [x] AI 居民的观察里自己的地块有 `people_seen`。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，1145 项测试。新增用例：`tests/unit/economy/test_visitors.py`（26 项：进城与选目的地、停留计数、不重复计数、离开与回来、路过算展示、擦边不算、没内容的与非广告位不选、内容与距离的偏好、拥挤度、同刻先走的人腾位置、种子可重现、无处可看时漫游、人次权重、位置解析、传送门路线与跳过的那段不算、时钟、默认世界）、`tests/unit/core/test_crowd.py`、`tests/unit/agents/test_visitor_observation.py`、`tests/unit/server/test_app.py` 里只有访客动时不广播的用例。
- 变异检查：去掉“只有访客动不广播”的判断、去掉计数的重复检查、去掉选目的地时排除刚看过的广告位、去掉拥挤度、去掉离开时的人数回退、去掉停留时间计入展示、换趟清空已逛记录、漫游不用掉站，各自都会让至少一个测试失败（头几次尝试里重复计数、拥挤度与人数回退三处变异没被抓到，补了用例后全部抓到）。
- 快进模拟：默认世界加 6 块展示着内容的广告位（中央两块、其余散在各处），模拟 2400 秒，用时约 5 秒（约每游戏秒 2 毫秒）；中央两块累计约 8500 和 7200 人次，其余 2400～3600，末了约 200 个访客里 70 多个在去广告位、40 多个在待、其余在离开或在城外。这些数只说明机制合理，没有校准过。
- 独立审查（子 Agent，只读）：跑了 150 个随机世界（地图 5～150、0～12 个广告位、传送门与随机线路、各种时钟跳跃）没有死循环、异常、出界或违反 `Visitor` 不变量；拥挤度计数每步都等于重新数的结果；`Router` 和 `effective_distance` 在 300 个随机布局上一致；广播条件不会吞掉游戏结束、公告、付款。发现并已修复：① **换趟时清掉了已逛记录**，26% 的计数是同一访客同一广告位 120 秒内的重复（已改为跨趟保留，加了回归用例）；② 没有内容时访客永远漫游、不离开（漫游现在也用掉一个站，加了用例）。顺手把 `_open_slots` 改用有缓存的地块中心。其余按文档记下：展示按走完那一刻判断；访客的变化不唤醒 AI；广告位建满时 CPU 随广告位数增长（约 6% 一个核）。
- 真实时钟冒烟：用默认世界跑 `Game.run_clock` 6 秒，访客在走，没有广播。
- 未做：浏览器验证（页面未改）；没有用真实模型试过会不会读 `people_seen`。
