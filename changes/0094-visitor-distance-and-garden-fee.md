# 0094：访客更看重距离，花园入场费改回 1

状态：已完成（服务端 `ruff`、`mypy`、`pytest` 通过；协议、页面不变）。

## 目标与依据

用户（2026-11-10）：花园入场费改成每人 1 金币；关键是吸引访客，也许还能带动附近的设施；办法是让选目的地时多考虑距离（其余相同时，近的设施更有吸引力）；加上这个权重，大概也能鼓励居民建传送门。

可观察的变化：访客选下一站时，近的场馆明显更常被选；刚离开某处的访客更常去它旁边的场馆（访客每趟的站数不变，所以是重新分配，不是凭空增加）；一条缩短到远处场馆步行时间的传送门线路，能为远处的场馆多带访客；花园入场费 1 金币。

## 范围

- 服务端：`economy/visitors.py` 的 `WALK_COST` 从 0.05 改为 0.15，`economy/admissions.py` 的 `FEES["garden"]` 从 4 改为 1；AI 系统提示加一句访客重视距离、线路的作用；文档与测试。
- 不做：给花园单独的“带动附近设施”的规则；按距离分段的权重；其它设施的吸引力数值调整。

设计文档：修改 `docs/design/garden.md`（入场费与数值的取舍）、`docs/design/visitors.md`（走路成本）、`docs/design/portals.md`（线路更值得建）。

## 关键选择

整体加重距离的权重，对所有场馆一视同仁，不给花园开特例；走路成本 0.15（原来的三倍）是 Claude 按模拟选的：30 个单位的路（12 秒）的成本 1.8，比一个工作空间的吸引力 1.39 还大。见设计文档“争议讨论与决定”。

## 验收条件

- [x] 其余相同、距离约差一倍（25.5 与 45.3 个单位）的两个工作空间，近的访客远多于远的。
- [x] 刚离开花园的访客，在近邻和地图另一端两个一样的工作空间之间，几乎都去近邻。
- [x] 一条线路缩短到远角场馆的步行时间后，该场馆的访客明显多于同样远但没有线路的场馆。
- [x] 以上三项测试在走路成本为 0.05 时都失败，0.15 时通过。
- [x] 花园入场费为 1，仍低于商场、工作空间、游戏厅。
- [ ] 真实对局里观察访客分布与收入（只做了快进模拟）。
