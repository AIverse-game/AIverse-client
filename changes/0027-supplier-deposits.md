# 0027：供货方押金

状态：已完成。

## 目标与依据

[变更 0025](0025-delivery-contracts.md) 的合约只约束买方：货款签订时托管，供货方交付即得钱；供货方却可以不交付或随时取消，买方最多拿回余款。被占用的金币不能做别的买卖，指望合约补充 token 的买方还可能出局。用户要求给供货方加约束，同意了以下方案，并决定押金由提议方自由填写。

## 范围

- 合约加可选条款“每次押金”（`deposit`，默认 0）。签订时供货方的全部押金和买方的货款一起托管；发件人发出提议时预留自己的一份，收件人同意时扣，不够则同意失败、提议仍待处理。
- 每交付一次，供货方得到价款并拿回这一次的押金。
- 合约提前终止时，没交付的押金按责任处理：到期、供货方取消、供货方出局时赔给买方；买方出局、游戏结束时退回供货方。
- `deliveries` 的含义由“最多交付几次”改为“到期前应交付几次”，押金为 0 时行为不变。
- 世界保留最近 100 份结束的合约（`ContractBook.ended`：原因、由谁造成、没交付的次数、赔付的押金）。Agent 观察新增 `ended_contracts`（自己最近 5 份）；合约不是因自己的行动而结束时唤醒空闲的一方。
- Agent 工具 `propose_contract` 加可选参数 `deposit`；观察中的提议和合约带押金，`coins_in_contracts` 含作为供货方的押金；系统提示说明押金规则，并提示买方可以要求押金。
- 协议 13：合约提议加 `deposit`，合约加 `deposit`、`depositHeld`；客户端校验 `depositHeld = deposit × deliveriesLeft`。“交易与合约”面板显示押金或“无押金”。
- 不包含：违约记录或信用、违约金、按期交付、页面显示已结束的合约、页面发起或答复。

设计文档：修改 [合约](../docs/design/contracts.md) 和 [AI 居民](../docs/design/ai-residents.md) 的唤醒规则。

## 关键选择

- **押金而不是信用或违约金**：与买方托管、报价预留同一套做法，预先拿出来、自动结算，不需要欠款或人工判定。信用会与“约定只给当事人看”冲突，先不做。理由详见设计文档。
- **押金自由填写**：用户决定，不设固定比例，由双方商量。
- **只在供货方有责任时赔付**：买方不能取消、不能拒收交付，无法故意让供货方赔押金。
- **结束记录放在世界里**：唤醒和观察都从同一份记录读，不另加居民记忆字段；只保留最近 100 份，世界不会无限增长。

## 验收条件

- [x] 押金在提议时（发件人）或同意时（收件人）预留，不够时同意失败、提议仍待处理；拒绝或撤回时退回。
- [x] 每次交付退还这一次的押金；交完时记录“completed”，不赔付。
- [x] 到期、供货方取消、供货方出局时，没交付的押金赔给买方；买方出局、游戏结束时退回供货方。
- [x] 押金为负、不是整数或总额超过上限时提议被拒绝；世界拒绝不可能的合约和结束记录。
- [x] 托管的押金计入供货方的金币总额。
- [x] 合约被对方取消时唤醒空闲的买方，观察中有结束原因和赔付；取消的供货方不被唤醒。
- [x] 协议 13 两边同步，页面显示押金；客户端拒绝押金不符或为负的状态。

## 验证证据

- `aiverse-server`：`make verify`（ruff、mypy、pytest）通过，共 594 个测试。新增押金的预留与退回、交付退押金、三种违约赔付、两种不赔付、结束记录上限、非法条款与记录的测试，合约工具测试加入押金和结束记录，新增合约结束唤醒买方而不唤醒取消者的测试，协议测试加入押金字段。
- 本仓库：`npm run verify`（类型检查、ESLint、Vitest、生产构建）通过，共 134 个测试，新增押金的校验与文字测试；`python3 scripts/check_repo.py` 通过。
- 独立审查：没有发现 P0–P2 问题。
  - 审查方另写随机测试：4 名居民、3000 个种子、每个约 60 步随机操作（各种押金的提议、答复、撤回、交付、取消、出局、报价、到期、游戏结束），每步检查金币总额不变，结束后托管全部清零。没有发现不一致，世界校验也没有拒绝合法状态。
  - 确认的 1 条 P3 已修复：设计文档的数值上限补上押金上限。
  - 顺带修正了系统提示：发件人的一份在提议时就预留，不是签订时。
  - 3 个疑点，保持现状：
    - 到期时刻恰好等于游戏结束时刻的合约按“到期”处理，押金赔给买方，因为时钟先结算到期再结束游戏。
    - 买方接受报价、买走供货方最后的 token，使供货方出局时，结束记录算供货方造成，所以买方也会被唤醒。
    - 系统提示中的简化说法，见上一条，已修正。
- 未做：页面没有在浏览器中实测，只有类型检查和文字测试；合约到期和对方出局时的唤醒只读代码确认，自动测试只覆盖对方取消。
