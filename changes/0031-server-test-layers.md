# 0031：服务端测试分层目录与按约定改写

状态：已完成。

## 目标与依据

用户提出两点：服务端测试是否都是单元测试，希望按种类分到不同目录；再按现行的测试约定审查已有测试，不符合的改掉。

此前所有测试都在 `tests/<子包>/` 中，按源码子包分组，不区分层，所以没法只跑单元测试。`tests/agents/test_agents.py` 一个文件里既有工具与设置的单元测试，也有真实运行的 Agent 循环。[变更 0028](0028-testing-conventions.md) 定下约定时统计过，约 21% 的测试在一个测试里交替执行和断言；当时决定不追溯修改现有测试，这次用户要求改。

## 范围

- 服务端 `tests/` 分为 `unit/` 与 `integration/`，层内仍按源码子包分组；包根 `__main__.py` 的测试放在 `tests/unit/test_main.py`。
- 按服务端测试约定的分层定义移动测试：经 WebSocket、运行 Agent 循环或调用大脑的测试放进集成层，其余放进单元层。`test_agents.py` 按内容拆成工具、观察、每轮记录、设置、命令行（单元层），以及循环、大模型大脑、脚本机器人（集成层）。WebSocket 测试文件改名为 `test_websocket.py`，把 `Game`、发件箱和协议视图的测试交给单元层。这一步只移动，不改测试内容，单独提交。
- 按约定改写现有测试：三段按顺序写；一个测试只测一个行为；循环和按参数分支改为参数化；去掉访问私有成员的两处。
- 服务端测试约定补充四条澄清：什么算执行；带 `code` 的异常断言 `code`；可以传入测试用的大脑；“调用大脑”指调用大脑的哪些方法。
- 更新服务端的命名与目录约定、`AGENTS.md`、`README.md`，以及本仓库的代码地图与项目状态。
- 不改源码，不加 pytest marker，不改 `make verify`（它照常跑全部测试）。

设计文档：无。

## 关键选择

- 目录叫 `tests/unit/`、`tests/integration/`，不叫 `unit_tests/`：测试已经在 `tests/` 下，层名不必重复“tests”。这也是 pytest 项目常见的写法。
- 分层看测试怎么测，不看测哪个模块。所以同一模块的测试可以分在两层，例如 `llm_brain.py` 的设置校验在单元层，调用模型的大脑在集成层。
- 改写时遇到约定没写清的地方，按约定的本意补成澄清，不另立新规则：
  - 收 WebSocket 帧、调用只读查询是在观察结果，可以写在断言里；发帧、执行原语、拨时钟才算执行。
  - 现有约 70 处断言 `raised.value.code`；`code` 也是发给客户端的错误码，所以保留这种写法，不改成 `match=`。
  - 测试用的大脑（如 `Recorder`）是决策者接口的替身，不算 mock 本项目的模块。
- 去掉私有成员访问：
  - `game._until_next()` 的断言删去，改在集成层新增“计时器自己把行走者送到”的测试。
  - `brain._client.is_closed` 改为断言大脑关闭后不能再发请求。
- 集成测试里有几条中间断言重复了单元层已测过的数值，改写时删去：采矿中、行走中的 `busy`，以及发言的 token 消耗。几条穿插在流程中的拒绝（`not_at_market`、`no_chip`、`not_enough_coins`）移进已有的参数化拒绝测试。
