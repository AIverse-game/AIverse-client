# 0063：服务器与会议室

状态：已完成。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)的第 3 步，用户（2026-11-07）要求接着做：居民在自己的地块上建服务器，谁都可以往里补算力；服务器承载附近的设施，主人收承载费。服务器只为承载设施而存在，所以第一个要承载的设施会议室也在这一步一起做（原计划在第 4 步，见设计文档的取舍）。

可观察的变化：AI 居民多了 `build_server`、`build_meeting_room`、`supply_server`、`set_hosting_fee` 四个工具；观察的 `land` 里多了会议室收入、会承载的服务器与承载费、自己服务器的算力与承载费，以及附近在营业的服务器；系统提示多了服务器与会议室的规则；流水账多了 `hosting` 渠道。页面不变。

## 范围

- `economy/facilities.py`：建服务器、建会议室、补算力、改承载费；会议室收入与平分；选服务器 `host_for`；结算时扣算力、付承载费；广告位只与广告位分流量。
- 原语 `BuildServer`、`BuildMeetingRoom`、`SupplyServer`、`SetHostingFee`；流水账渠道 `hosting`。
- Agent：工具、工具组 `land`、按状态选工具、观察、系统提示（长度上限从 7000 放宽到 7500）。
- README。

客户端：设计文档、经济指标的渠道列表（顺带补上 0062 的 `land`、`visitors`）、代码地图、架构说明、状态。代码与协议不变。

## 关键选择

- **首版数值**：服务器 10 个素材，最多存 300 算力，承载半径 30；会议室 6 个素材加 1 个 v1 程序，每周期耗服务器 4 算力，收入为收购点处每名访客 2 金币，40 单位内的会议室平分。估算开局每周期约 200 金币，偏远地块上比广告位划算。
- **自动接入**：会议室每周期从半径内存够算力、主人在局的服务器里选：自己的优先且免费（几台里取最近的），再按承载费最低、距离最近。服务器之间靠承载费竞争。同一时刻结算的会议室按买地先后依次选。
- **承载费从收入扣，最多等于收入**：会议室主人不会倒贴，不需要预存。
- **服务器只在承载时耗算力**，自己不结算周期。
- **没接上服务器的会议室仍算在附近同类里**：收入先于承载算出，不受结算顺序影响。

## 验收条件

- [x] 在自己的空地块上能用素材建服务器、用素材和 v1 程序建会议室；材料不够、没有程序、不是自己的地块、已建过都被拒绝。
- [x] 站在服务器地块里的任何人都能补算力；超出容量、数量无效、不是服务器、主人已出局都被拒绝。
- [x] 只有主人能改承载费，负数被拒绝。
- [x] 会议室每 30 秒结算：有服务器承载时按访客付主人金币（`visitors`），承载费付给服务器主人（`hosting`），服务器扣算力；自己的服务器优先且免费，其次最便宜，算力不够或超出半径的不选；没有服务器能承载时没有收入；承载费不超过收入；附近会议室平分；广告位不与服务器、会议室分流量。
- [x] Agent 能通过工具建服务器、补算力、改承载费、建会议室，观察给出收入、承载服务器和费用，工具按状态出现。
- [x] 服务端与客户端检查全部通过。

- 服务端：`ruff check`、`ruff format --check`、`mypy` 通过；`pytest` 1247 项通过（新增 `tests/unit/economy/test_hosting.py`，`test_land_tools.py` 与系统提示的测试）。
- 客户端：`npm run verify`（214 项测试与构建）、`python3 scripts/check_repo.py` 通过。
- 独立审查（子 Agent，只读）：没有 P0～P2。确认的 P3 都已修复：
  - 站在别人的会议室上时，观察按观察者自己而不是房主选服务器、算承载费，会把自己的服务器显示成免费承载。改为按房主算，补测试。
  - 设计与本记录写“结算顺序不影响结果”，实际同时结算的会议室抢一台快空的服务器时按买地先后先到先得。改写文档，补测试。
  - 测试缺：抢服务器、同价取最近、房主出局与对局结束、`last_request_tool_names` 的新分支、新设施的建造拒绝与承载费为负、补满到 300、在别处改承载费。都已补上；执行与断言交替的承载费测试拆开。
  - 服务器已满或主人已出局时仍给出 `supply_server`。两套选工具逻辑都改为只在能补进去时给出。
  - 疑点：主人自己有几台服务器时，原来先比它们对外的承载费；改为自己的几台直接取最近的，与文档一致。README 的“随时可改”改为“在任何地方都能改（忙碌时不行）”。
