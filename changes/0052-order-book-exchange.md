# 0052：挂单交易所

状态：已完成。

## 目标与依据

路线图第 ③ 步（用户 2026-11-03 确认，见 [挂单交易所](../docs/design/order-book.md)）：居民之间只有一对一报价，要先找对象、按整批开价、等对方答复，真实模型很少这样交易。2026-11-03 的基线对局里，三名居民卖光能量后困在收购点，发了约 20 次求购报价，多数没人理。交易所给能量、晶砂和各阶晶核一个公开的匿名挂单簿：价格由居民自己形成，困住的人挂一个买单就能被任何有货的人成交。

可观察的变化：AI 居民多了 `place_order`、`cancel_order` 两个工具，观察里有各商品的挂单簿、自己的挂单与成交；挂单被别人成交时唤醒空闲的居民。页面与协议不变。

## 范围

服务端（`aiverse-server`）：

- 新增 `core/orders.py`：`Order`、`Fill`、`OrderBook`，挂单预留的金币与物品；世界的 `orders` 与一致性校验（订单不能比主人或对局活得久）。
- 新增 `economy/exchange.py`：下单、价格优先与时间优先的连续撮合（成交价为挂单价，买方多预留的差价退回）、撤单、到期、批量撤单，深度、最近成交价与成交量。
- `core/ledger.py`：渠道 `exchange`。`economy/energy.py`：卖单里的能量算作拥有。`game/lifecycle.py`：排名计入买单预留；出局和结束时撤单退回。`game/clock.py`：挂单到期。`game/actions.py`：原语 `PlaceOrder`、`CancelOrder`（撤单在忙碌时也可以）。`server/protocol.py`：页面显示的拥有晶核数含卖单里的。
- `agents/`：工具与状态；观察的 `exchange`（每种商品前 3 个价位、最近成交价、120 秒成交量，自己的挂单和最近 10 笔成交）与 `me.coins_in_orders`；系统提示说明规则；挂单被别人成交时唤醒。
- 测试：`tests/unit/core/test_orders.py`、`tests/unit/economy/test_exchange.py`、`tests/unit/agents/test_exchange_tools.py`，`tests/integration/agents/test_agent_loop.py` 的成交唤醒。
- `README.md`：功能说明、工具与观察、流水账渠道、代码结构。

客户端：只改文档（本说明、[挂单交易所](../docs/design/order-book.md)、[经济指标](../docs/design/economy-metrics.md) 的渠道、设计索引、`docs/status.md`）。

留给后续：页面显示与页面下单（路线图第 ④ 步）；成交进活动日志与成交价历史；手续费、市价单、系统做市。

## 关键选择

- **撮合与预留沿用设计**：连续撮合、匿名、下单要到场、撤单与成交不用到场、系统不挂单，均为用户 2026-11-03 确认的设计。
- **自己的成交列最近 10 笔**，不在记忆里记“上次查看到哪”。
- **单价上限 1000000 金币**，只为防止总额失去意义。
- **订单模型放在 `core/`**：能量拥有量（出局判断）和排名都要统计挂单预留，放在 `economy/exchange.py` 会形成循环导入。

## 验收条件

- [x] 站在收购点下单，买单预留金币、卖单预留物品；不在收购点、未知商品、数量或单价或有效期越界、金币或物品不够、与自己的挂单交叉时拒绝；已有 8 张挂单时，只接受能立刻全部成交的订单。
- [x] 新订单与对面价格最优、同价最早的挂单按挂单价成交，买方多预留的差价退回，可部分成交，剩余部分挂在簿上；每笔成交记流水账渠道 `exchange`。
- [x] 撤单退回剩余预留，在任何地方、行走中也可以；撤别人的或不存在的订单拒绝。到期、出局、对局结束时退回预留。
- [x] 买单预留的金币计入排名；卖单里的能量算作拥有，被买光后照常出局；Agent 不能把手上最后的能量挂出去卖。
- [x] Agent 工具返回成交和挂单情况；观察显示匿名的挂单簿、自己的挂单与成交；挂单被别人成交时唤醒空闲的居民。
