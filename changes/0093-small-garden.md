# 0093：小花园

状态：已完成（客户端 `npm run verify`、服务端 `ruff`、`mypy`、`pytest` 通过；无头 Chrome 里渲染核对了模型；真实对局里没看过）。

## 目标与依据

用户（2026-11-10）：新设施“小花园”，给居民休息的基础设施，比游戏厅便宜、好建；建成后服务端一次性奖励地块的主人；对访客有吸引力但不如游戏厅；给地块上的所有收入加成 10%。模型用 `demos/voxel_floating_garden.html`，保留季节变化和昼夜变化，做成容易管理的渲染层；实现完写设计文档。

可观察的变化：居民和玩家能在自己的空地上建花园（工作量 100）；建成时地主一次性得到 500 金币；之后同街区所有设施的外来收入（赞助商、入场费）多一成；访客也会来花园（每人 4 金币）；地图上画出会随季节和昼夜变化的花园。

## 范围

- 服务端：设施种类 `garden`、建造工作 `build_garden`（`start_build_garden`，只有地主、每街区一座）、奖励与加成（新文件 `economy/gardens.py`，流水账渠道 `garden_reward`、`garden_bonus`）、赞助商和入场费两处加成、访客目的地（`GARDEN_PIECES`、停留、入场费 4）、Agent 工具 `build_garden`、观察 `garden_room`、`garden_in_block`、`compute.garden`、系统提示；协议 32（设施种类 `garden`，`game.elapsedSeconds`）。
- 页面：协议同步，`GameStore.gameSeconds()`，设施面板“建花园”与街区加成提示，世界日志的设施名，渲染层 `render/garden/`（时钟、配色表、共用材质、模型、层），`plotShape` 的花园尺寸，`MapRenderer` 持有花园层。
- 文档：新设计文档 [小花园](../docs/design/garden.md)，更新设计索引、总览、赞助商、访客、金币特效、状态、代码地图，服务端 README。
- 不做：委托建造与许可、夏冬两季、整张地图的昼夜、居民休息的机制、地图上的加成标记。

设计文档：新建 `docs/design/garden.md`。

## 关键选择

见设计文档“争议讨论与决定”。要点：“地块上的所有收入”按街区算（用户的“parcel”有歧义，Claude 的取舍，需确认）；加成由镇上另付、按整笔收入取整；每街区一座；入场费快进模拟后从 1 改到 4；季节与昼夜按游戏时间，所以协议加 `elapsedSeconds`。

## 验收条件

- [x] 在自己的空地上建花园，工作完成后设施出现，地主一次性得到 500 金币（渠道 `garden_reward`），只发一次。
- [x] 只有地主能建；同一街区建成或在建时再建被拒（`garden_exists`）；别的街区不受影响；场馆占用的地块、已承诺给别人的地块被拒。
- [x] 街区里有花园时，赞助商付款和入场费多一成，按份额分给持有人，渠道 `garden_bonus`；过路费不加（加了能自传刷钱）；别的街区不加；在建的不加；不足一枚的费用零头留到下次，加成不重复计。
- [x] 访客会去花园并付 4 金币每人；吸引力在商场与工作空间之间。
- [x] AI 能用 `build_garden`，观察里有 `garden_room`、`garden_in_block`。
- [x] 页面能建花园，街区有花园时显示加成；协议版本 32，客户端与服务端 `game.elapsedSeconds` 一致。
- [x] 季节按游戏时间每 600 秒换（春、秋），昼夜每 180 秒一轮，换季和昼夜不重建模型，全图花园共用材质；`?garden=autumn,night` 可固定查看。
