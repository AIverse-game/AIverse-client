# 0014：行走速度与每轮开始的推进

状态：已完成。

## 目标与依据

用户要求（2026-10-28）：

1. 把“先 tick 再感知”收进一个入口：AI 每轮开始时调用它，不必自己记住顺序（变更 0013 的交接只是写了一段说明）。
2. 加入走路速度，并设计一个合理的速度。此前 `move_to` 即时到达。

用户把速度的数值和规则交给本次设计，以下都没有逐项确认，都是可调的常量或可逆的实现：

- **速度每秒 2.5 地图单位**（`WALK_SPEED`）。依据：
  - 默认地图 100 × 100 上有 6 个矿池，随便站一处，最近的矿池平均约 20 单位，走过去约 8 秒，与一次采矿的 10 秒相当，走路的时间成本和采矿是同一个量级；
  - 走出感知半径（20）要 8 秒，横穿地图要 40 秒，对角线约 57 秒，一局 20 分钟里走不了几趟远路；
  - 设计稿中的一回合是 20 秒，约能走 50 单位，即半张地图。
  - token 仍是体力的约束（200 token 只够走 200 单位），速度是时间的约束。
- **出发时付清整段路费**（规则不变：每单位 1 token，向上取整）。
- **途中忙碌**：与采矿一样，只能退出游戏，不能改道或停下。
- **匀速直线**：别人看到的、感知到的都是此刻在途中的位置。
- **花光最后一个 token 的走路**：到达后才出局，保留以前“走到目的地再出局”的效果。
- **中途出局或游戏结束**：停在当时的位置。出发时已花光 token、途中对局就结束的居民，因此不算出局（`left` 为假、token 为 0、停在途中）；排名只看金币，不受影响。这是有意的：出局只在到达时判定。

## 范围

服务端（`aiverse-server`）：

- `world.py`：新增 `WalkJob`（目标、出发与到达时刻），`Resident.walking`。校验以下情况：出局或采矿时不能在走，到达不早于出发，目标在地图内，对局结束后不能在走。活动种类新增 `started_walking`。
- 新增 `walking.py`：`WALK_SPEED`、`walk_seconds`、`position_at`、`start_walk`、`finish_walks`、`stop_walking`、`next_arrival`。
- 新增 `clock.py`：`settle_due`（发放采矿、接回到达者、到达时花光 token 的出局，并记录活动）、`next_due`。`Game.tick` 用它们代替原来的逐项调用，测试也用它们快进时间。
- `actions.py`：`MoveTo` 扣费后开始行走。
- `mining.py`：`check_not_busy` 同时拒绝行走中的居民。
- `lifecycle.py`：
  - `leave_game` 与 `end_game` 停下行走；
  - `knock_out_exhausted` 跳过仍在路上的居民；
  - 新增 `knock_out_arrivals`。
- `perception.py`：感知者和被看到的居民都用途中位置；`ResidentSighting.walking_to`；出发记为 `started_walking`，到达或中途停下记为 `moved`。
- `app.py`：`Game.begin_turn(resident_id)` 先 `tick`，再感知并存回世界，返回感知；计时任务也等下一次到达。
- `protocol.py`：协议版本 6，居民视图的 `position` 改为发送时的途中位置，新增可选 `walking`（`target`、`remainingSeconds`）。

客户端（本仓库）：

- `packages/protocol`：`walking` 字段及“目标在地图内”的校验，`PROTOCOL_VERSION = 6`。
- `GameStore.isFree`：行走中不空闲。
- `MapScene`：行走中的居民按快照的位置、目标和剩余时间，每帧用 `performance.now()` 算出位置。没有用 Phaser 补间，见“关键选择”。标签显示“行走中”。
- 侧栏标“行走中”；操作面板显示“正在走向 (x, y)，到达前只能退出游戏”，行走中不再显示过时的“现在位于”；按钮改为“走到此坐标”，说明文字同步。

不做：每回合距离、中途改道或停下、寻路与障碍、页面预估到达时间、速度进入协议。

## 关键选择

- **到点的事集中在 `clock.settle_due`**：采矿发放、行走到达、到达后出局、活动记录都在这里。`Game.tick` 只负责读时钟、调用它和结束游戏。测试可以直接设定 `World.time` 再调用它来快进，与服务端走同一条路径。
- **行走期间 `Resident.position` 保持出发点**，途中位置由 `position_at` 按时间算出，不需要时钟不停地改写世界。世界只在出发、到达或中途停下时变化，广播次数不变。
- **页面动画按真实时间计算**：先用 Phaser 补间实测，前台单页在第 7 秒时只走了应走距离的约三分之一。原因是 Phaser 的游戏时钟在帧率低时会限制每帧的步长，后台页更明显。改为每帧按 `performance.now()` 插值后，同一测试在第 7 秒约走到一半，后台页切回前台时也在正确位置。

## 验收条件

- [x] `move_to` 出发即扣费，`Resident.position` 不变，`distance / 2.5` 秒后到达目标；途中位置随时间线性变化。
- [x] 行走中 `move_to`、`mine` 以 `busy` 拒绝，`leave_game` 可以执行，并让居民停在当时的位置；对局结束时同样停下。
- [x] 走路花光 token 的居民到达后才出局；途中卖光 token 的也是到达后出局。
- [x] 感知看到的是途中位置和目的地；出发和到达各记一条活动。
- [x] `Game.begin_turn` 先推进时间（到达、发放都已处理），再感知并把记忆存回 `Game.world`。
- [x] 协议 6：视图中的途中位置与 `walking`；客户端校验目标在地图内、剩余时间非负。
- [x] 页面：出发后两页都显示“行走中”，地图上的小人匀速走动，到达后自动更新位置与按钮状态。
