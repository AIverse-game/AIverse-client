# 0047：模型回复上限可配置，结束前 3 分钟增加公告

状态：已完成。

## 目标与依据

最近一局日志里，34 次可读模型回复有 6 次触及 8192 token 上限；部分模型单轮耗时超过一分钟，60 秒公告来不及影响决策。用户要求让上限可配置，并在结束前 3 分钟再发一条事件公告。

## 范围

- 服务端 YAML 的 `override.max_tokens` 设定所有模型请求的每次回复上限，默认 8192；要求正整数，启动参数与页面交给 AI 的模型均适用。
- 对局结束前 180 秒和 60 秒分别向全体居民公告，每名居民在下一轮观察读到并唤醒等待中的 Agent。对局短于或等于对应时长时不发该条公告。
- 更新服务端说明和现有 AI 居民设计文档。公告仍不进入页面协议。

设计文档：[AI 居民](../docs/design/ai-residents.md)。

## 关键选择

保持默认 8192，以便已有配置行为不变；新增服务端共用上限，不改变页面协议。3 分钟公告沿用 `World.notices`，在游戏时钟到达阈值时发出。正在运行的模型请求不会被中断，公告会在下一轮观察中送达。

## 验收条件

- [x] 配置 `max_tokens: 16384` 时，请求中发送 16384；省略时仍发送 8192；无效数字被拒绝。
- [x] 20 分钟对局在剩余 180 秒和 60 秒各公告一次，并唤醒等待中的 Agent；每名居民在下一轮各读到一次。
- [x] 短局只发送来得及发送的公告，不改变最终结算。

## 验证证据

服务端：`UV_CACHE_DIR=/private/tmp/aiverse-uv-cache UV_NO_SYNC=1 make verify` 通过，ruff、格式、mypy strict 与 949 项测试全部通过。客户端仅改文档，`python3 scripts/check_repo.py` 通过；未重新跑无关网页构建。

独立审查发现跨阈值补发过期提醒、显式 `max_tokens: null` 被静默当作省略、短局提示词不准三项问题，均已修复；复核 31 项相关单元测试通过，未发现新问题。未运行真实模型对局。
