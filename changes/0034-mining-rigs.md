# 0034：矿机与芯片租用

状态：已完成。

## 目标与依据

实现用户认可的矿机经营机制；角色出局后必须停止自动采矿，矿主也不能继续收租。

## 范围

服务端世界、经济、时钟与出局结算；网页与 Agent 共用原语；双端协议、地图和操作面板；测试与文档。设计见 [矿机与芯片租用](../docs/design/towers.md)。

## 关键选择

4 槽、4000 金币、20 秒周期、每 100 token 收 300 金币租金和 20 金币电费，使用预存余额，出局与结束清理。扩充有限矿池储量以容纳持续生产。协议同步升级为 15。

## 验收条件

- [x] 可建机、安装芯片、自动挖矿、向矿主付租金，角色仍能移动与出售 token。
- [x] 容量、距离、余额、芯片和储量校验；费用与产出原子结算，余额不足暂停，充值不补挖。
- [x] 拆回、租客出局、矿主出局、token 耗尽与游戏结束均正确退还并停产，预存计入排名。
- [x] 网页可操作并查看状态、地图与收益估算；Agent 可观察及操作。
- [x] 自动检查、浏览器实测与独立审查完成，记录证据。

## 验证证据

- 服务端：`UV_CACHE_DIR=/tmp/aiverse-uv-cache make verify`，ruff、格式、mypy strict 及 813 个测试通过。新增 31 个矿机规则用例，以及 WebSocket 和 Agent 工具用例。
- 客户端：`npm run verify`，类型检查、ESLint、151 个测试及 Vite 生产构建通过；`python3 scripts/check_repo.py` 通过。
- 浏览器：独立 `127.0.0.1:8765` 测试世界，经内置浏览器实际建机、租客安装 MK1、自动生产、移动到市场后继续产出、远程充值、矿主出局退款。每 30 token 扣预存 96 金币，其中 90 转矿主；累计生产 150 token 后，矿主 6450 金币退出，租客获得退回的 MK1、可用金币 9520、矿机预存 0，矿机列表清空。测试对局与日常对局独立。
