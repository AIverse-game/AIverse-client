# 0090：商场可以横放或竖放

状态：已完成（客户端 `npm run verify`、服务端 `ruff`、`mypy`、`pytest` 通过；无头 Chrome 截图核对了横放的朝向）。

## 目标与依据

用户（2026-11-09）：商场方向应该可以旋转，只分横竖；建造商场由地主说了算：地主提出委托时先说好在哪两个格子上建，建造者提出时地主同意的时候指定。

可观察的变化：商场可以占 1 × 2（竖放，入口朝南）或 2 × 1（横放，入口朝东）；自己建时选朝向；委托建造时地主定朝向，建造者照办。

## 范围

- 服务端：`Orientation`（`north_south`、`east_west`）存在设施、进行中的工作和许可上；占地、放得下、中心、已占、许可承诺都按朝向算；`BuildVenue`、`OfferBuildCommission` 带朝向，`RespondToEvent.orientation` 让地主同意时指定（`commissions.answer_commission`）；错误码 `invalid_orientation`、`wrong_orientation`；AI 的 `build_venue`、`commission_build`、`respond_to_offer` 工具和观察（`mall_orientations`、委托与许可视图）；协议 30。
- 页面：协议与占地算法带朝向；设施面板的朝向选择；模型整体转 90°，选中框和命中体积按朝向；`plotShape` 支持转向。
- 文档：[商场设计](../docs/design/mall.md)、状态、代码地图。
- 不做：四向朝向、建成后改朝向、页面上处理委托、地主同意时换地块。

设计文档：修改 `docs/design/mall.md`（调整已有功能，不另建）。

## 关键选择

见设计文档“争议讨论与决定”。要点：同意时的朝向放在应答原语上，在执行同意前改写队列里的提议，不改事件钩子；许可带朝向，建造者开工只能照办；AI 工具说明的体积上限从 8000 放宽到 8200。

## 验收条件

- [x] 横放的商场占本块和正东一块，放不下（街区最后一列）被拒；竖放行为不变。
- [x] 地主提议时写明朝向，许可带着它，建造者按别的朝向开工被拒，按许可开工成功，设施建成后朝向不变，酬金照付。
- [x] 建造者提议时，地主同意的同时能改朝向；建造者自己改、拒绝时带朝向、同意后放不下，都被拒绝且世界不变。
- [x] 许可期间别人不能在它承诺的两块地上建。
- [x] 页面能选朝向建商场，地图上横放的商场入口朝东，选中框是 20 × 10。
- [ ] 真实对局里点一次横放建造（没有开服务端对局）。
