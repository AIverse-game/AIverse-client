# 0074：工作用户与入场费

状态：已完成（首版）。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤第 7 步的第三部分，接在[变更 0072](0072-visitors.md)（脚本访客）和[变更 0073](0073-sponsors.md)（赞助商）之后。用户（2026-11-07）此前已决定：第 7 步全做、分多次变更；**入场费由系统统一定价，居民不定价**。这次开工时用户又要求：设计文档按功能模块各写一份，把设计细节都记下来。

可观察的变化：一部分访客是工作用户，先去工作空间，再去展示着游戏的游戏厅，在门口付入场费（工作空间 4、游戏厅 6 金币每人），钱来自各自的钱包；入场费在付款日整枚硬币地按份额分给设施地块的持有人，账本渠道 `visitors`。游戏厅和工作空间第一次有了收入。AI 居民的观察里自己的工作空间和游戏厅多 `people_admitted`，`income_last_payday` 含入场费。协议和页面没变。

## 范围

服务端（`aiverse-server`）：

- `core/admissions.py`：`AdmissionBook`（未付的费用、累计进门的人数、上次付款日、上个付款日各设施收到的钱）；`World.admissions`，默认空。
- `core/visitors.py`：访客多 `kind`（游客或工作用户）、`errands`（还要去的设施）、`purse`（钱包）；`goal` 的 `slot` 改名 `place`（去的不一定是广告位）。
- `economy/visitors.py`：每趟进城按 30% 分到工作用户；工作用户按工作空间、游戏厅的顺序去，钱包不够的设施不去，没有候选的一项直接跳过；工作空间按一份内容的吸引力算，没有游戏的游戏厅不是目的地；停留时间按设施种类（广告位 6～14 秒，工作空间 20～40 秒，游戏厅 10～20 秒）；走完一段时在门口收费。
- `economy/admissions.py`：`FEES`、`admit`、`pay_admissions`（付款日整枚硬币地按份额付给持有人，零头留到下次）、`next_admission_payday`。
- `economy/sponsors.py`：付款日的判断抽出 `next_payday_after`，入场费与赞助商共用同一套付款日。
- `core/ledger.py`：渠道 `visitors` 现在表示入场费；`game/clock.py`：付款日接进到点结算。
- `agents`：观察里自己的地块多 `people_admitted`，`income_last_payday` 含入场费；系统提示和 `build_venue`、`place_content` 的说明不再说这两种设施不赚钱。
- README、测试。

文档：新建并拆分设计文档（见下），`docs/design/README.md` 索引、状态、代码地图、变更索引。

## 关键选择

见 [venues](../docs/design/venues.md) 和 [visitors](../docs/design/visitors.md) 的“争议讨论与决定”。要点：入场费由系统统一定价（用户决定）；钱包限制总量（Claude）；入场费在付款日批量付、零头不丢（Claude）；工作用户没有候选的一项直接跳过（Claude）；游戏厅没有游戏就没有访客（Claude）。均为 Claude 的取舍，用户只确认了统一定价。

## 验收条件

- [x] 工作用户先去工作空间，再去展示着游戏的游戏厅；去不了的一项（没有这种设施、游戏厅没有游戏、钱包付不起）跳过，全跳过就离开，不漫游。
- [x] 进门时付费用乘以这个访客代表的人数，从钱包里扣，钱包不够不进；游客不付入场费；工作用户不专程去广告位，但路过够久也算展示（走的是同样的路）。
- [x] 付款日把每个设施这期的入场费整枚硬币地按份额分给持有人，账本渠道 `visitors`，零头留到下次；晚醒的时钟不跳过付款日；出局的持有人照样收款；没有整枚硬币时时钟不为它醒来。
- [x] 钱包总量限制入场费总量，付出的钱不超过进门人数乘最高的价。
- [x] AI 居民的观察里工作空间和游戏厅有 `people_admitted`，`income_last_payday` 含入场费；提示和工具说明与代码一致。
- [x] 每个功能模块有自己的设计文档，facilities.md 只留总览和步骤，设计文档索引同步。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，审查修复后 1176 项测试，全量约 18 秒。新增 `tests/unit/economy/test_workers.py`（12 项：分到工作用户、先去工作空间、按人数收费、费用随人数增长、再去游戏厅、钱包不够不去、跳过没游戏的游戏厅和没建的工作空间、没得去就离开、游客与工作用户互不串、费用不超过钱包、工作用户的占比、走路速度）、`tests/unit/economy/test_admissions.py`（11 项：整枚硬币付款与零头、不足一枚不付也不唤醒时钟、零头留到下次、按份额、出局的持有人、晚醒不跳过、付款日之间不付、记账、账本校验、陌生地块、整条链）、`test_visitor_observation.py` 一项；`test_visitors.py` 里的测试改为固定只有游客；旧测试里 `stops_left` 保持，`goal="slot"` 改名 `place`。
- 变异检查（12 个，审查后又加了广播条件）：去掉钱包检查、不扣钱包、不按人数收费、不更新剩下的去处、改去处顺序、让广告位也走收费分支、让没内容的场所也成为目的地、零头清零、不判断付款日、付款日取实际时间、下一个付款日取错、渠道改错，各自都会让至少一个测试失败（超时算被抓到）。
- 独立审查（子 Agent，只读，代码和设计文档一起审）：发现并已修复一个 P2：工作用户每次进门都会改 `world.admissions`，而广播判断只忽略访客本身，于是每秒约一次广播并唤醒所有等着世界变化的 Agent（审查模拟 600 秒有 648 次广播，628 次只因入场费变化）；现在也忽略入场费状态，付款日的付款改了金币照常广播，补了经过 `Game.tick` 的用例（撤销修复会失败）。P3：文档说工作用户不看广告位，代码里他们路过也算展示——决定路过算，改了文档、验收条件，并把原来空转的测试换成真正走过广告位的；删掉走不到的拒绝分支和回退；代码注释里“游戏厅和工作空间不赚钱”的几处改掉；测试里 `monkeypatch.undo` 的写法改掉。文档：几处把 Claude 的取舍写成用户确认的地方已更正（拆分顺序、消费池、统一定价的理由），补回用户的决定（访客系统留到设施定了再做、合买由提议人写明份额）和被删掉的细节（订阅 144 金币、内容工作的价格、份额数值与理由、权重增长的理由、传送门出局者不再被列出）。审查确认没问题的：付款日不会死循环（60 个随机世界模糊测试）、钱不会凭空多出、访客的不变量、观察的数。
- 快进模拟：8 个居民共 3 个工作空间、3 个游戏厅、5 个广告位，20 分钟入场费共 5949 金币，赞助商共 11894 金币。数只说明量级合理，没有校准过。
- 未做：浏览器验证（页面未改）；没有用真实模型试过 AI 会不会读新字段。
