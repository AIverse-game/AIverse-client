# 0009：事件系统框架

状态：已完成。

## 目标与依据

用户要求：实现游戏的事件系统框架，把部分操作抽象成类似消息队列的机制。例如 A 向 B 请求购买某物品，购买请求先作为一条消息发给 B，B 看到后可以同意或拒绝。暂不实现具体的事件，只实现可扩展的底层系统。

可观察的变化：服务端世界中有一个待处理事件队列。服务端代码可以让一名居民向另一名居民发送事件，收件人同意或拒绝、发件人撤回之后事件离开队列；每种事件按自己的规则决定发送、同意、拒绝时世界如何变化。客户端和协议没有变化。

## 范围

- 新增 `events.py`：
  - `Event`（id、发件人、收件人、内容）与 `EventQueue`（按 id 排列的待处理事件、下一个 id）。
  - `EventPayload`：事件种类的基类，提供三个钩子 `on_send`、`on_accept`、`on_decline`，默认不改变世界。
  - `send_event`、`accept_event`、`reject_event`、`withdraw_event`、`pending_for`（收件箱）、`pending_from`（已发出未答复），错误类型 `EventError`（`unknown_resident`、`unknown_event`、`self_addressed`）。
- `world.py`：`World.events` 默认为空队列；构造时校验事件双方都是世界中的居民且不是同一人。
- `actions.py`：新增原语 `RespondToEvent`（同意或拒绝）与 `WithdrawEvent`（撤回），`perform` 按原语类型分派；钩子抛出的 `EventError`、`InventoryError` 转成 `ActionRejected`，`RejectionCode` 相应扩充。

留给后续：具体事件种类（购买请求等）及发送它们的原语；在协议和客户端中展示事件、发送答复（涉及他人信息的可见粒度，尚待设计）；事件过期（需要回合时钟）；居民出局时如何处理与其有关的事件；事件记录与复盘。

## 关键选择

均为可逆的实现选择：

- **队列放在世界里**：事件和物品栏一样是不可变世界的一部分，每个函数返回新世界，出错时世界和队列都不变。以后提交、广播、回合结算都沿用世界的现有路径，不需要另一份可变状态。
- **一种事件 = `EventPayload` 的一个子类**：子类是冻结的 dataclass，保存这类请求的细节（例如商品、数量、价格），只覆盖需要的钩子。不用全局注册表，新增种类不需要改动框架。
  - `on_send`：校验请求能否发出，并预留它承诺的东西（例如冻结买方金币）；不得改动事件队列，否则抛 `ValueError`，保证 id 递增有序。
  - `on_accept`：执行请求。事件先离开队列再执行；执行失败时整体不变，事件仍待处理，收件人还可以拒绝。可以发送后续事件或答复别的事件，但不得把本事件放回队列或让 id 回退，否则抛 `ValueError`。
  - `on_decline`：释放 `on_send` 预留的东西，拒绝和撤回共用，约束同上。以后的过期也可以复用。它是离开队列的唯一出口，契约是不应失败；失败的事件会一直待处理。
- **id 是世界内递增的整数，永不复用**：答复不会误落到后来的事件上；有序、确定，便于以后回放。
- **只有收件人能答复，只有发件人能撤回**：对别人的事件操作一律报告 `unknown_event`，不泄露事件是否存在。
- **不能给自己发事件**（`self_addressed`）。
- **加入撤回**：用户点名了同意与拒绝；没有回合时钟就没有过期，若无撤回，发件人预留的东西可能永远取不回来，因此一并提供。
- **答复是原语，发送不是**：同意、拒绝、撤回对所有事件种类相同，所以现在就是原语；发送依赖具体种类，由以后每种事件自己的原语（如“发起购买”）调用 `send_event`。新原语尚未进入协议，客户端还不能发送。

## 验收条件

- [x] 新世界的事件队列为空。
- [x] 发送的事件进入队列，id 从 1 递增；收件箱与已发列表按先后排列，只含与该居民有关的事件；原世界不变。
- [x] 已答复事件的 id 不再使用，旧 id 不能答复新事件。
- [x] `on_send` 的预留在同意后交付、在拒绝或撤回后退回；`on_send` 拒绝时不入队。
- [x] `on_accept` 失败时世界与队列不变，事件仍可拒绝，条件满足后可以同意。
- [x] 答复只移除该事件；非收件人不能答复、非发件人不能撤回，都报告 `unknown_event`；未知居民报告 `unknown_resident`；不能给自己发事件。
- [x] `on_send` 改动队列、`on_accept`/`on_decline` 把事件放回队列或让 id 回退时抛出 `ValueError`；答复钩子可以发送后续事件；`EventQueue` 拒绝乱序、重复或尚未发放的 id；`World` 拒绝涉及未知居民或自己发给自己的事件。
- [x] `RespondToEvent`、`WithdrawEvent` 经 `perform` 生效，失败转为对应代码的 `ActionRejected`，世界不变。
- [x] 服务端 `make verify` 通过。
