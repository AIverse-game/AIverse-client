# 0026：在页面上显示报价与合约

状态：已完成。

## 目标与依据

[变更 0025](0025-delivery-contracts.md) 之后，用户选择先在页面上显示合约和报价。在此之前，交易报价和合约只存在于服务端和 AI 居民的工具中，试玩时页面上看不到 AI 之间做了哪些约定。

## 范围

- 协议 12：状态的 `world` 增加 `offers`（交易报价）、`contractProposals`（合约提议）、`contracts`（生效的合约）。三者都只包含 `view_as` 所选居民参与的部分，没选居民时为空。服务端 `server/protocol.py` 与客户端 `packages/protocol` 同步修改，客户端校验参与者是已知居民、不能与自己交易、提议的双方与收发件人一致、托管等于单价乘剩余次数。
- 页面新增只读的“交易与合约”面板（`DealsPanel.tsx`，条款文字在 `dealText.ts`），位于“操作”面板之下。显示所选居民的生效合约（角色、条款、剩余次数、托管、到期倒计时），以及收到和发出的报价与合约提议。`GameStore.countdown` 按本地时钟倒数合约的剩余时间。
- 金币排名面板的说明改为“含报价和合约中预留的金币”。
- 不包含：页面发起、答复、交付或取消（原语仍不在协议中）。

设计文档：新建 [交易报价](../docs/design/trade-offers.md)（交易功能此前没有设计文档，按规则在这次调整时补写），修改 [合约](../docs/design/contracts.md)。

## 关键选择

- **只给当事人看**：报价和合约是两人之间的约定，和私聊用同一个可见范围。理由见 [交易报价](../docs/design/trade-offers.md)。
- **只读**：用户这次要求的是显示。页面操作需要新增原语和表单，留给后续。
- **三个列表而不是一个**：报价和合约提议的字段不同，分开定义，校验更清楚。页面按事件 id 把两者合并成一个“等待答复”列表，顺序与发出的先后一致。

## 验收条件

- [x] 选中某名居民时，页面列出该居民参与的生效合约、收到和发出的报价与合约提议；选中其他居民时，换成那名居民的；没选居民时提示先选择。
- [x] 不参与的居民看不到别人的报价与合约；不以任何人身份查看的连接收到空列表。
- [x] 合约的到期时间随本地时钟倒数。
- [x] 协议两边同步，版本升到 12；客户端拒绝参与者未知、与自己交易、提议双方不符、托管不符的状态。
- [x] 390 px 宽时面板不产生横向滚动。
