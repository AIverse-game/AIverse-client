# 0020：AI 居民循环

状态：已完成。

## 目标与依据

用户同意（2026-10-29）下一阶段先接通“AI 驱动居民”这条主线，调度采用事件驱动，第一家模型服务商用 OpenRouter 上的 NVIDIA 模型，见 [决策 0003](../docs/decisions/0003-event-driven-agents-and-openrouter.md)。

可观察的变化：用启动参数指定居民由 Agent 驱动后，不需要任何人操作，这些居民会自己买芯片、采矿、卖 token、说话和交易，页面上能看到他们行动；每轮决策写入日志。

## 范围

服务端（`aiverse-server`）：

- `app.py`：`Game.act` 推进时间、执行原语、提交并广播；`Game.commit` 供 WebSocket 与 AI 共用；`Game.subscribe` 让 Agent 在世界变化时被唤醒。`create_app` 可接收 Agent，随应用启动和停止。
- 新增 `agents` 子包：
  - `observation.py`：把感知、自己的状态、公开排名、报价收件箱整理成一份观察，可转成 JSON 给模型。
  - `tools.py`：绑定到一名居民的工具（走路、采矿、卖 token、买芯片、说话、报价买卖、答复和撤回报价、记笔记、忘掉笔记），参数校验与 JSON Schema 来自同一份 pydantic 模型。
  - `runner.py`：事件驱动的循环与唤醒规则、每轮记录。
  - `scripted.py`：固定策略的脚本机器人。
  - `openrouter.py`：OpenRouter 模型大脑，带请求上限和出错重试间隔。
  - `rules.py`：给模型的规则说明，数值取自代码常量。
- `__main__.py`：`--agent 居民=scripted` 或 `--agent 居民=openrouter[:模型]`，可重复；`--agent-log 文件` 把每轮记录写成 JSONL。

不做：页面上的 AI 行动日志面板、玩家配置界面与自带 key、经营方针、加速的无界面模拟、回放、按模型延迟补偿。协议不变。

## 关键选择

见决策 0003。另外几项可逆的选择：

- 观察里只有感知半径内的居民位置，但所有居民的名字、id、金币和名次都给出（页面上本来就公开），以便私聊和报价。
- 工具执行后返回成功与否、拒绝代码和原因，以及执行后自己的简要状态，让模型知道结果。
- 模型每轮最多调用 8 次工具，每名居民每局最多 400 次模型请求。

## 验收条件

- [x] 网页的操作照旧可用，原有测试全部通过；Agent 与网页的操作经同一个 `Game` 入口执行并广播。
- [x] 工具只作用于绑定的居民；参数缺失、类型错误、未知工具时返回错误而不抛出，世界不变；原语被拒绝时返回拒绝代码。
- [x] 唤醒规则：行走或采矿结束（包括在大脑思考期间就结束的）、收到新报价、听到新话、空闲超时时唤醒，两轮间隔不少于设定值；居民出局或游戏结束后循环停止。大脑或记录抛出的异常不影响游戏和其他 Agent。
- [x] 脚本机器人在默认地图上能自己完成买芯片、找矿池、采矿、卖出 token 的流程，不出局。（原写“金币超过开局”：实测多数机器人买 MK3 后亏本，这是数值问题，改为验证流程，见交接。）
- [x] OpenRouter 大脑：按 OpenAI 工具调用格式发请求，执行模型返回的工具调用并把结果交回；没有 key 时启动报错；HTTP 出错时记录并等待后重试；达到请求上限后停止调用。用模拟的 HTTP 传输测试。
- [x] `uv run aiverse-server --agent ...=scripted` 启动后居民自己行动。（以控制台与 JSONL 记录验证，未在浏览器中打开页面，见验证证据。）

## 验证证据

环境：macOS，Python 3.12，日期 2026-10-29。

- `aiverse-server` 下 `make verify`：ruff、ruff format --check、mypy strict、pytest 全部通过，503 passed（原有 464 个加新增的 `tests/test_agents.py`）。
- `aiverse-client` 下 `python3 scripts/check_repo.py`：通过。本次客户端只改文档，未运行 `npm run verify`。
- 真实服务器对局：`uv run aiverse-server --port 8791 --duration 150 --seed 7 --agent r1=scripted ... --agent r4=scripted --agent-log ...`。150 秒内 4 个机器人共决策 44 轮，没有报错；它们自己买芯片、走到矿池采矿、回收购点卖 token。终局金币为 9435、7000、8072、7054：局太短，MK3 来不及回本。第一次尝试因 8765 端口被占用而没有跑起来，换端口后成功。
- 快进模拟（假时钟，每轮所有机器人行动后跳到下一个到点时刻，20 分钟整局，脚本在会话临时目录）：种子 1、2、7、42 都无人出局，6 个矿池全部挖空。16 个机器人里只有种子 7 的 r1 高于开局（10372），其余在 7000～9727。
- 回归验证：去掉“思考期间行走结束也唤醒”的修复后，对应测试失败，恢复后通过。
- 未验证：没有发真实的 OpenRouter 请求（没有 key），只用 `httpx.MockTransport` 测试；没有在浏览器中观看 Agent 行动。

独立审查：发现 2 个 P2、4 个 P3 和 2 个疑点。已修复：思考期间结束的行走或采矿不唤醒（P2）；超长整数参数让 `call` 抛出异常；记录或观察出错时循环悄悄退出；`create_app` 不校验 Agent 的居民 id；JSONL 中出现 NaN；文档状态不一致。验收条件与实测不符（P2）一项按上文改写了验收条件。未处理：OpenRouter 的 `httpx.AsyncClient` 不在关闭时 `aclose()`，只会在退出时可能出现资源警告。

## 交接

- **先用真实 key 试玩**：`export OPENROUTER_API_KEY=...` 后运行 `uv run aiverse-server --agent r1=openrouter --agent r2=scripted --agent-log game.jsonl`，读 JSONL 看模型是否理解规则、常犯什么错，再调整 `agents/rules.py` 和工具说明。免费模型（`:free`）有速率限制，出错时每 10 秒重试一次。
- **经济数值**：芯片价格相对矿池总储量偏高，矿池在 20 分钟内被挖空，机器人买 MK3 多数亏本。待模型试玩后与矿池储量、收购点参数一起调。
- **页面**：AI 行动日志面板（每轮的观察摘要、模型的话、工具调用与结果）需要协议改动，留给下一个变更。
- **其他限制**：响应速度会影响胜负；没有玩家配置界面、自带 key 和经营方针，Agent 由启动参数指定；没有加速的无界面模拟，真实对局要等真实时间；OpenRouter 客户端不关闭。
