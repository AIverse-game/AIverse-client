# 0019：发言消耗 token，页面不显示别人的私聊

状态：已完成。

## 目标与依据

用户要求（2026-10-29），在变更 0018 的基础上：

- 发言消耗少量 token，当众说和私聊都要。用户选定当众说每句 2 token、私聊每句 1 token。
- 页面上不显示别人的私聊。目前没有“玩家拥有哪名居民”，用户选定：页面选中居民时告诉服务端，服务端只把与该居民有关的私聊发给这个页面。

## 范围

服务端（`aiverse-server`）：

- `speech.py`：`SPEECH_COSTS`（当众 2、私聊 1），`say` 在其他检查都通过后从携带的 token 中扣除，不够时以 `not_enough_tokens` 拒绝。
- `tokens.py`：把走路的扣除提成通用的 `pay_tokens`，走路与发言共用。
- `protocol.py`：协议升到 10；客户端消息 `view_as`（`residentId` 为居民 id 或 `null`）；`world_view` 带 `viewer`，私聊只放进说话人或对象是 `viewer` 的，最近 50 句在过滤后计算。
- `app.py`：每个连接记住自己的 `viewer`（`Outbox.viewer`）；`view_as` 回复新的 `state`，居民不存在时回复 `bad_message`；广播按不同的 `viewer` 各编码一次。

客户端（本仓库）：`ClientMessage` 加 `view_as`；`GameStore.select` 发送 `view_as`，选中的居民消失时发送 `null`；对话面板在按钮上显示消耗，token 不够时禁用并提示，花光最后一个 token 前确认。

不做：居民归属与权限检查、按消耗显示预估的剩余 token、群聊。

## 关键选择

- **扣的是携带的 token**，出售报价中预留的不算，与走路相同；花光最后一个照常出局（`knock_out_exhausted`），行走中的到达后出局。先做文字、对象检查再扣，被拒绝的发言不花钱。
- **过滤在服务端**，不相关的私聊不会出现在浏览器收到的帧里；但尚无归属，任何页面选中谁就能看到谁的私聊，安全性与以前“任何页面能操作任何居民”相同。有了归属后，`view_as` 只应允许选自己的居民。
- **只藏内容和对象，不藏“有过私聊”**：发言序号 `seq` 是全局的，过滤后会有空号；每人的 token 数对所有页面公开，没有对应的当众发言却少了 1 个，也能看出谁私聊过。别的页面因此能推断出私聊发生过、有几句，但看不到内容和对象。token 公开时这无法藏住，所以没有为每个页面重新编号。
- **页面再按选中居民过滤一次**：服务端已经只发选中居民的私聊；面板渲染时再过滤一次，在换选后新状态到达前、或连接断开后（`view_as` 发不出去），也不会把上一个选中居民的私聊显示在新选择下。
- **没选居民时看不到任何私聊**，包括刚刚自己发出的那句（发送需要先选居民，所以正常操作碰不到）。
- **最近 50 句在过滤后计算**，别人的大量私聊不会把自己能看到的话挤出视图。
- **协议升到 10**：新页面依赖 `view_as`，旧服务端会回复 `bad_message`；用版本号让不匹配在握手时暴露。

## 验收条件

- [x] 当众说扣 2 token，私聊扣 1 token；携带的不够时以 `not_enough_tokens` 拒绝且世界不变；预留在报价中的 token 不算；花光最后一个出局。
- [x] 页面选中居民后，状态里只有当众说的话和该居民发出或收到的私聊；没选居民时没有私聊；换选后立即收到对应的新状态。
- [x] `view_as` 在 `hello` 前、居民不存在或格式错误时回复 `bad_message`，原选择不变。
- [x] 对话面板显示每句的消耗，token 不够时不能发送。

独立审查（只读子 Agent，review-change）：无 P0–P2，3 个 P3 与 1 个疑点：

- P3：换选后新状态到达前、或连接断开后，面板会把上一个选中居民的私聊显示在新选择下。面板渲染时改为再按选中居民过滤。
- P3：最后一个 token 的确认对采矿中的居民误报“之后出局”（已挖出的 token 算拥有，不会出局）。采矿中不再弹出确认，文字注明行走中的到达后出局。
- P3：别的页面能从序号空号和 token 变化推断出有过私聊。只记入关键选择，不改，理由见上。
- 疑点：`Outcome.viewer` 有默认值，以后新分支漏传会悄悄清空连接的选择。已去掉默认值，由 mypy 强制每个分支都传。

审查者另外实测了扣费与出局：站着花光最后 2 个当即出局；行走中花光到达后出局；采矿中只带 1 个私聊一句不出局，再说以 `not_enough_tokens` 拒绝。
