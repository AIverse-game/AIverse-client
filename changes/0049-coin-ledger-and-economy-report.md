# 0049：金币流水账与经济报告

状态：已完成。

## 目标与依据

用户（2026-11-03）希望游戏往社会与市场模拟发展，并确认按 [经济指标](../docs/design/economy-metrics.md)、[芯片与芯片制造](../docs/design/chips.md)、[挂单交易所](../docs/design/order-book.md) 三份设计的建议推进，第一步是记账与经济指标：先用现有规则测出基线，之后每次改经济规则都能比较居民之间的交易是否变得更活跃。

## 关键选择

- **在世界里记账，不从日志事后推算**：每名居民的 JSONL 只有每轮前后的余额，矿机租金、合约到期赔付发生在游戏时钟里，不在轮内，事后推算不准（见设计文档）。
- **记账与转账分开**：`record_transfer` 只记一笔，由结算点自己移动金币，现有的 `add_coins`、`take_coins` 不变，所以预留和退回天然不记。
- **渠道细分合约**：交付付款与押金赔付分成两个渠道，报告可以直接数出交付次数和赔付次数。
- **报告结束时写一次**：没到时间就停掉服务端时不写。启动时删掉旧报告，避免把上一局的报告当成本局的；`--agent-log` 与报告同名时拒绝启动。
- **租金不记物品**：token 来自矿池，租金只是固定费率的矿机使用费，记物品会让报告出现没有意义的“租金价格”（审查疑点，采纳）。

## 验收条件

- [x] 收购点收 token、买芯片、建矿机、矿机租金与电费、报价成交（买方或卖方发起）、合约交付与押金赔付、信息成交，各记一笔，付款方、收款方、金额、渠道、物品与数量正确。
- [x] 报价撤回或被拒绝、合约提议撤回、矿机预存、充值、拆回芯片退款不记账；合约因买方出局或游戏结束而终止、矿机因租客或矿主出局或游戏结束而退款时也不记账。
- [x] 合约到期、供货方取消、供货方出局时，记一笔供货方付给买方的押金赔付，金额为未交付部分的押金。
- [x] 流水账满了丢掉最早的一条并计数；金额小于 1、自己付给自己、物品与数量不一致的记录被拒绝。
- [x] 报告算出居民之间、系统付出、付给系统的金币与居民间占比，各渠道、按物品的价格统计、合约统计、基尼系数与收入集中度；没有金币流动时占比为空。
- [x] 对局结束时 `on_end` 只调用一次并拿到最终世界；回调出错只记日志，游戏照常结束。
- [x] 命令行启动时删掉旧的 `summary.json`，对局结束后写出新报告并打印摘要。

## 验证证据

- 服务端 `make verify`（审查修复后）：ruff、格式检查、mypy strict 通过，1001 项测试通过（原有 1 条 Starlette 弃用警告）。新增测试：`tests/unit/core/test_ledger.py`、`tests/unit/economy/test_coin_ledger.py`、`tests/unit/game/test_economy_report.py`，以及 `tests/unit/server/test_app.py` 中的两项结束回调测试。
- 命令行实测：在空闲端口用 4 个脚本机器人跑 25 秒一局（`--seed 7`，日志目录放在临时目录，预先放一个内容为 `stale` 的 `summary.json`）。启动时旧文件被删除，结束时写出新报告，控制台打印 `economy at 25s: ... resident share -` 和 `chip_import 4 transfers 12000 coins`。
- 基线（估算，非流水账）：按 2026-11-01 真实模型对局的日志粗算，收购点付给居民约 108469 金币，成交报价约 11600 金币，居民间占比约 9.7%。矿机租金不在调用记录里，所以这是下限估计。正式基线要等下一局真实模型对局的 `summary.json`。脚本机器人之间不交易，快进模拟的占比为 0，不作基线。
- 客户端：`python3 scripts/check_repo.py` 通过。只改了文档，未运行 `npm run verify`。
- 独立审查（子 Agent，只读）：未发现 P0～P2 问题。
  - 审查者另做了模糊测试：300 个种子 × 120 步随机原语，逐步核对每人金币总额等于开局金币加流水账收入减支出，0 处不一致，9 个渠道都覆盖到。
  - 确认了 3 项 P3，均已修复：`--agent-log` 指向 `summary.json` 时汇总日志会被删掉并覆盖（改为拒绝启动，已实测报错）；合约测试一个测试测两个行为（已拆开）；押金赔付与退回路径缺测试（已参数化补上取消、供货方出局、买方出局、游戏结束、报价被拒、矿机出局与结束退款）。
  - 采纳了 2 项疑点：租金不再记物品；设计文档的价格指标措辞与实现对齐，价格走势列入暂未实现。
  - 保留的疑点：提前停服不写报告（有意为之，已写入 README）。
