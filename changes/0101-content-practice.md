# 0101：做内容的熟练度

状态：已完成（服务端 `make verify` 通过；协议与页面不变）。

## 目标与依据

用户（2026-11-11）为促进居民之间的交易，要求加熟练度：每做一份内容，下一份就快 10%。用户随后确定：广告和游戏分开计数；最低到原来的 1/4。这样先做了很多份某种内容的居民，做这种内容比别人快、也便宜，向他买比自己从头做划算，分工由居民自己选出来，不靠提示词指派。

可观察的变化：同一居民第 n 份（从 0 数）广告或游戏的工作量是基础工作量 × 0.9ⁿ，不低于 1/4；用时和按需雇用的金币随之下降；AI 的观察里给出自己做过几份、下一份要多久多少金币。

## 范围

服务端（`aiverse-server`）：

- `core/compute.py`：`ComputeBook.practice` 记录每名居民每种内容做成的份数。
- `economy/compute.py`：`PRACTICE_SPEEDUP`、`PRACTICE_FLOOR`、`making_workload`；开工时按份数算工作量，做成时加一。
- `agents/observation.py`：`compute.content`、`compute.game` 按自己的熟练度给出用时和金币，`compute.practice` 给出份数和下一份的工作量占第一份的百分比。
- `agents/system_prompt.py`、`agents/tools.py`：说明熟练度。
- README、测试。

不做：建设施的熟练度（用户选了只算内容）；页面和协议显示熟练度；公开别人的熟练度。

设计文档：修改 [内容](../docs/design/content.md)、[算力与节点](../docs/design/compute-and-nodes.md)。

## 关键选择

- **按做成计数**（Claude）：工作做完、内容到手才加一。同时开工排队的几份互不加速，开工时的工作量就定下来，之后不再变。
- **工作量打折，而不是速度加快**：用时和按需雇用的金币都按折算后的工作量算，订阅节点做得更快，订阅到期后的尾巴也短。
- **份数记在 `ComputeBook.practice`**：出局时 `cancel_compute` 原来按位置重建账本，改成 `replace`，免得新字段被清掉。出局后份数保留，没有用处，只是不清掉。
- **观察里用整数百分比**：观察的 JSON 把小数都舍到一位，倍数 0.25 会显示成 0.2，所以写成 `next_workload_percent`（100、90、……、25）。
- **只给自己看自己的份数**（Claude）：别人的熟练度不公开，要靠交谈或交易价格判断。
- **工具说明的预算**：`make_content` 的说明按“第一份”的数字写，加一句熟练度并指向 `compute.practice`；为了不超 8200 字符的预算，删掉了与别的工具重复的“走路时也行”，用词压紧，信息不变。

## 验收条件

- [x] 第一份广告、游戏的工作量与原来相同；每做成一份，同种下一份的工作量 × 0.9；最低基础工作量的 1/4；广告和游戏分开计数，居民之间互不影响。
- [x] 用时和按需雇用的金币按折算后的工作量计。
- [x] 份数在做成时加一；开工后未做成（出局、对局结束）不算。
- [x] AI 观察给出自己做过几份、下一份的倍数，以及按此折算的用时和金币。

## 交接

- 熟练度只在 AI 观察里，页面不显示；别人的熟练度不公开。
