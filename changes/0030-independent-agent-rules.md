# 0030：每个仓库独立的 Agent 规则

状态：已完成。

## 目标与依据

[变更 0029](0029-agent-rules-in-both-repos.md) 让两个仓库的规则与 Skill 逐字相同。用户认为没必要搞共用：两个仓库应当各自独立，各有一套规范，其中通用的软件开发规范内容可以一致。

## 范围

- 本仓库的 `.agents/rules/` 与 `.agents/skills/` 改为只描述客户端：去掉“规则如何同步”和服务端内容，链接恢复为指向本仓库的文档，命名约定只保留 TypeScript、仓库脚本、资源与文档，测试约定换成客户端的分层与示例。
- 服务端仓库的同名文件改为只描述服务端：Python 命名与子包、`make verify`、服务端的测试分层与示例；写明状态、设计与决策记录在客户端仓库。
- `scripts/check_repo.py` 去掉跨仓库比较，保留新规则文件的必需检查。
- 写 [决策 0006](../docs/decisions/0006-independent-agent-rules-per-repo.md) 替代决策 0005，并更新状态、代码地图与索引。

设计文档：无。

## 关键选择

- 任务闭环、独立审查、提交约定、测试分层与准备—执行—断言这些通用内容，两边措辞保持一致，以后不强制同步。
- 客户端测试分层按现有测试划分：纯函数为单元层，`GameStore` 接假连接与 WebSocket 连接接 `FakeSocket` 为集成层，端到端仍靠浏览器人工实测。

## 验收条件

- [x] 两个仓库的规则与 Skill 都只描述本仓库，本地链接都能打开。
- [x] 客户端规则中没有“两个仓库共用”“规则如何同步”等说法，检查脚本不再比较服务端。
- [x] 仓库检查通过。
