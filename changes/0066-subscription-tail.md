# 0066：订阅到期后的工作按自带速度做完

状态：已完成。

## 目标与依据

用户（2026-11-07）指出 [变更 0065](0065-compute-and-nodes.md) 里“订阅的工作必须在节点到期前做完，否则不让开工”没有必要：订阅结束了，工作恢复到原来的速度继续做就好。

可观察的变化：订阅节点上开的工作，即使快到期也能开；节点到期时还没做完的部分，之后每秒做 1（自带算力的速度）。

## 范围

服务端：`economy/compute.py` 开工时按“节点速度做到到期、之后按自带速度”算结束时刻（`subscription_job_end`），节点到期时把还在做的工作从节点上摘下（`node_id` 变为 None），已到期的节点不能再开工（错误码 `node_expired` 取代 `node_too_short`）；`core/compute.py` 去掉“工作不得晚于节点到期”的校验，订阅的工作可以没有节点；Agent 的工具说明和系统提示同步。README、设计文档、状态。

设计文档：修改 [虚拟设施](../docs/design/facilities.md) 第 2 步的取舍。协议和页面不变。

## 关键选择

- 尾巴不占用居民自带算力“一次一件”的名额，否则已经有自带工作的居民就得让这件工作排队，规则会复杂得多；代价是居民可以多出一条每秒 1 的并行工作，量很小。
- 开工时一次算出结束时刻，不在每一刻重新计算进度；节点只在到期时被摘掉，所以结束时刻不会变。

## 验收条件

- [x] 订阅节点只剩 6 秒时开工，结束时刻为到期时刻加上剩下的 60 工作量按每秒 1 做的 60 秒。
- [x] 节点到期后工作仍在，不再挂在节点上，到点完成；不占居民自带算力的名额。
- [x] 能在节点到期前做完的工作速度不变；已到期的节点开不了工。

## 验证证据

2026-11-07：服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，873 项测试；新增用例在 `tests/unit/economy/test_compute.py`。独立审查（独立子 Agent）未发现缺陷；采纳了三条小意见：观察里节点的 `free_for` 不超过剩余订阅时间、补两条测试（工作恰在到期时做完；工作带着尾巴时出局）、0065 加上被取代的指引。保留：载入时不再限制挂在节点上的工作的结束时刻（只能由手工构造的世界触发）。

## 交接

数值不变。0065 里写的“必须在到期前做完”已被本变更取代。
