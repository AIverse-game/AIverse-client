# 0071：游戏厅与工作空间

状态：已完成（首版，不产生收入）。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤的第 6 步，用户（2026-11-07）要求开始做。设计文档对这一步只有一句话（“更多设施：游戏厅、工作空间等，各有自己的内容和收费”），所以开工前向用户确认了三点，用户的决定：

1. 这次做**游戏厅 + 工作空间**，虚拟花园留到以后。
2. 游戏厅里放的“游戏”是**新的内容物品 `game_content`**，与广告位的 `ad_content` 并列。
3. 第 7 步之前这两种设施**只建出来，不产生收入**，收费等第 7 步的访客入场费，像第 2 步的广告位那样先证明“算力 → 设施”这条链通了。

可观察的变化：居民可以用生成式工作在自己的空地块上建游戏厅或工作空间；渲染式工作可以做游戏（`game_content`），游戏可以交易，也可以放进自己的游戏厅展示，保鲜期同广告；工作空间不展示内容。局里的收入来源仍然只有广告位。页面和协议不变，只是交易所多一本 `game_content` 的挂单簿。

## 范围

服务端（`aiverse-server`）：

- `core/land.py`：设施种类加 `game_hall`、`workspace`；`CONTENT_KINDS` 为展示内容的设施（广告位、游戏厅）；只有广告位有付款时刻。`core/compute.py`：工作种类加 `build_game_hall`、`build_workspace`、`make_game`。
- `economy/ads.py`：`GAME_ITEM`、`ITEM_FOR`（设施种类 → 它收的内容物品）；`place_content` 按设施种类取对应的物品；付款、分流、下一个付款日只认广告位；错误码 `no_ad_slot` 改为 `no_content_facility`。
- `economy/compute.py`：`start_build_venue`、`start_make_content` 加 `content` 参数（广告或游戏），工作量与完工逻辑。`economy/exchange.py`：商品表加 `game_content`。
- 原语 `BuildVenue`；`MakeContent` 加 `content`（`game/actions.py`）。
- Agent：工具 `build_venue`，`make_content` 加 `content` 参数，`place_content` 按设施种类放；选工具（`build_venue` 与 `build_ad` 同条件，`place_content` 看手里的物品与有没有收它的、未满的设施）；观察里 `compute.venue`、`compute.game`；系统提示一句。
- README、测试。

文档：设计文档（第 6 步的取舍与暂未实现）、状态、代码地图。

留给后续：虚拟花园与景观；游戏厅、工作空间的收费（第 7 步，访客入场费）；协议与页面显示（第 8 步）。

设计文档：修改 [虚拟设施](../docs/design/facilities.md)。

## 关键选择

见设计文档“争议讨论与决定”中第 6 步的取舍：游戏厅与广告位同容量同保鲜期；游戏厅和工作空间不分走附近广告位的流量；工作量 240（设施）与 90（游戏）；工作空间不展示内容；`build_venue` 一个工具管两种设施；错误码改名。均为 Claude 的取舍，用户尚未逐项确认。

系统提示有 6000 字符上限（`test_the_base_prompt_stays_compact`），加了一句后超出，删去了三句不影响规则的提示语（观察里列出工作与节点、`land.stakes` 的说明、做内容不需要地）。这些信息本来就在观察字段名和工具描述里。

后续（同日，用户决定）：不再给系统提示设长度上限，删掉 `test_the_base_prompt_stays_compact`，上面的字数限制和“又只剩几十个字符”的说法不再适用。删去的三句没有恢复。

## 验收条件

- [x] 游戏厅和工作空间由生成式工作建在自己的空地块上，自带算力、雇节点、订阅节点三种来源都行；用错节点种类、地块已建、不是自己的地、未知种类都被拒绝，世界不变。
- [x] 渲染式工作可以做游戏，进物品栏的是 `game_content` 而不是 `ad_content`；用错节点种类、未知内容种类被拒绝。
- [x] 游戏放进自己的游戏厅，展示 300 秒后过期，一个游戏厅至多 5 份；广告放不进游戏厅，游戏放不进广告位；工作空间和空地块不收内容。
- [x] 游戏厅不付钱，不产生付款日（时钟不会因它醒来），也不分走附近广告位的流量。
- [x] AI 居民能用 `build_venue` 建设施，用 `make_content` 的 `content` 选做广告还是游戏，用 `place_content` 放进对应的设施；`build_venue`、`place_content` 在适用时自动出现，`compute` 组里有 `build_venue`；观察里有两种设施的工作量、用时与花费；系统提示仍不超过上限。
- [x] 交易所多一本 `game_content` 的挂单簿。

## 验证证据

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，1106 项测试。新增用例：`tests/unit/economy/test_venues.py`（两种设施的建造与各种拒绝、游戏的渲染、游戏厅展示与过期与上限、各设施只收自己的内容、工作空间与空地不收内容、游戏厅不付钱不产生付款日、不分走广告位的流量）、`tests/unit/agents/test_venue_tools.py`（工具、观察、选工具含最后一次请求）。已有测试里随改动调整的：错误码改名、交易所多一本挂单簿、`compute` 组多一个工具、传送门不展示内容的错误信息。
