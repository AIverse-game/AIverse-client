# 0096：访客的过路费按每条线路收

状态：已完成（服务端 `ruff`、`mypy`、`pytest` 通过；协议、页面不变）。

## 目标与依据

变更 0095 让访客走一趟线路网付一次 1 金币，不论中间走过几条线路，所以一串线路和一条直达的线路收得一样，网的形状在收入上没有区别。用户（2026-11-10）要求改成按段收：“Add the per-hop toll”。

可观察的变化：访客在线路网里每走过一条线路，每人付 1 金币，一半给线路一端的传送门地块、一半给另一端；中间的门同时是两条线路的一端，收两份一半。

## 范围

- 服务端：`economy/portals.py` 的 `Router.path` 给出一趟线路网里依次经过的传送门（线路最少的路，一样多时先取编号小的）；`economy/visitors.py` 对相邻两座门之间的每条线路记账；`economy/admissions.py` 的说明、AI 的系统提示与工具说明、README；文档与测试。
- 不做：让访客因此改路（访客不看金币）；每段的时间成本或段数上限；给一趟的过路费设上限。

设计文档：修改 `docs/design/portals.md`、`docs/design/visitors.md`。

## 关键选择

- **走线路最少的路，同样多时先取编号小的。**访客只决定进哪座门、出哪座门（走路最短），门之间不花时间，没有“走哪条线路”的选择，所以用最少线路数定一条确定的路，结果可重现。
- **每条线路收满 1 金币，一半给每一端**，和居民传送的分法一致，所以中间的门收到两份。
- **仍不影响选路。**访客不看金币，线路网在访客眼里还是同一网里任意两座门之间不花时间；这次只改变谁收钱、收多少。让形状影响访客怎么走，需要每段时间成本或段数上限，留待用户决定。
- **没有为一趟的总过路费设上限。**是否需要，见交接。

## 验收条件

- [x] 三座门 A–B–C 由两条线路相连、访客从 A 进、C 出时，A 和 C 各记半份、B 记一份（两条线路各一半），都乘访客代表的人数。
- [x] A、C 之间另有一条直达线路时，只走一条线路，B 不收钱。
- [x] 经一条线路时仍是两端各半份（0095 的用例不变）；主人定的过路费不改变付的钱和走的路；只步行不付钱。
- [x] 两条一样短的路（菱形）时，编号小的中间门收两份，线路的列出顺序不影响。
- [x] 把路径换回只算进门和出门两座，新增的链用例失败；去掉按编号排序，菱形用例失败；恢复后通过。

## 交接

- 过路费随链的长度线性增加，没有上限。每人每座门至多 3 条线路、每人至多 4 座门，一个网里可以有很多座门；一趟走过的线路数多于入场费 8～12 时，过路费比进场馆还贵。如果试玩中出现，可对一趟的总过路费或走过的线路数设上限。
- 数值是试玩前的估计。
- 协议、页面不变；服务端重启后生效。
