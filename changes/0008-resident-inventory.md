# 0008：居民持有物品

状态：已完成。

## 目标与依据

用户要求：实现角色物品持有功能，容量无限，只在局内有效、出局清零；并实现存入物品、移出物品、列出物品等基本的增删改查接口，这些接口不是 AI 操作原语。

可观察的变化：服务端的居民带有物品栏，服务端代码可以给居民存入、移出、计数、列出和清空物品。客户端和协议没有变化。

## 范围

- `world.py`：新增不可变的 `Inventory`（物品种类 → 数量，数量至少为 1），`Resident.inventory` 默认为空。
- 新增 `inventory.py`：`store_item`、`take_item`、`item_count`、`list_items`、`clear_items`，以及错误类型 `InventoryError`（`unknown_resident`、`not_enough_items`）。
- `actions.py` 文档首行改为：原语是“玩家与 AI”改变世界的唯一入口；服务端内部规则可以直接使用物品接口，这一点写在 `inventory.py` 的文档字符串和 `docs/architecture.md` 中。

留给后续：物品种类的定义（谷物、木材、面包等）、采集与交易等使用物品的原语、在协议和客户端中展示物品、房间与对局生命周期（何时调用 `clear_items`）。

## 关键选择

均为可逆的实现选择：

- **接口是服务端内部函数，不是原语**：客户端和 AI 都不能直接调用，否则任何连接都能凭空变出物品。以后的原语在 `actions.py` 中调用它们，并把 `InventoryError` 转成 `ActionRejected`。
- **与世界一样不可变**：每个函数返回新的世界，原世界不变；出错时什么都不改。物品栏挂在 `Resident` 上，随世界一同替换，以后提交和广播都沿用现有路径。
- **局内有效**：物品栏只存在于内存中的世界，没有持久化；新开一局时由 `create_default_world()` 生成，物品栏为空。`clear_items` 供居民出局时清空，目前没有房间和对局概念，因此暂无调用方。
- **物品种类是任意非空字符串**：种类表尚未设计，先不限定，定下来后再收紧。
- **移出全有或全无**：数量不足时抛出 `not_enough_items`，一件都不移出；数量归零的种类从物品栏中删除，列表里不会出现数量为 0 的项。
- **容量无限**：不检查总数或种类数；数量必须恰好是 `int` 且至少为 1，拒绝 0、负数、布尔值、小数和 NaN；所有接口的种类都不能为空（`ValueError`，属于调用方的编程错误）。
- **“改”由存入与移出组合**：用户点名的是存入、移出、列出，没有提供直接设定数量的接口；需要时再加。

## 验收条件

- [x] 新居民和默认世界的物品栏为空。
- [x] 存入累加数量，只影响目标居民，原世界不变；大量物品不受容量限制。
- [x] 移出减少数量，归零的种类被删除；数量不足或未持有时拒绝，世界不变。
- [x] 列出结果按种类排序，修改返回值不影响世界；未持有的种类计数为 0。
- [x] 清空只影响目标居民。
- [x] 所有接口拒绝未知居民；数量必须为正整数，种类不能为空；`Inventory` 拒绝重复种类和非正数量，相等比较与顺序无关。
