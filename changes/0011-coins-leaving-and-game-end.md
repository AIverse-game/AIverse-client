# 0011：金币余额、出局与对局结束

状态：已完成。

## 目标与依据

用户要求（2026-10-27）：金币从物品中拆出来；初始金币每人 10000；居民允许出局，但整局游戏不因此结束；游戏只在开始后一定时间自动结束。

就未定之处向用户确认后的决定：

- 出局方式：居民可以用原语主动退出，服务端也提供同一个内部接口，以后断线、违规等情况可调用。
- 出局之后：居民留在世界中并标记为已出局，不能再行动或交易；物品清零（沿用变更 0008 的“出局清零”），金币保留并参与最终排名。
- 时长：20 分钟，启动参数可改。尚无房间与开局流程，“开始”定为服务端创建这局世界（即启动）的时刻。
- 展示：进协议并在页面显示金币、出局状态、剩余时间和排名。

可观察的变化：页面顶栏显示剩余时间，侧栏新增金币排名；选中居民后可以退出游戏，出局的居民在地图上变淡、在列表中标“已出局”；到点后所有页面显示“游戏已结束”和最终排名，操作被拒绝。

## 范围

服务端（`aiverse-server`）：

- `world.py`：`Resident.coins`（非负整数）与 `Resident.left`；`World.ended`；构造时拒绝结束后或涉及出局居民的待处理事件。
- `inventory.py`：`coin_balance`、`add_coins`、`take_coins`，新错误代码 `not_enough_coins`。
- `trade.py`：报价改用金币余额，去掉 `"coin"` 物品种类；新增 `reserved_coins`（待处理购买报价中预留的金币）。
- `events.py`：出局的居民不能发出或收到事件（`resident_left`）。
- 新增 `lifecycle.py`：`GAME_DURATION`（1200 秒）、`check_can_act`、`leave_game`、`end_game`、`total_coins`、`ranks`，错误类型 `GameError`（`unknown_resident`、`resident_left`、`game_over`）。
- `actions.py`：新原语 `LeaveGame`；`perform` 先检查行动者，出局或游戏结束时拒绝一切原语。
- `layout.py`：`STARTING_COINS = 10_000`。
- `app.py`：`Game` 持有截止时间；应用的 lifespan 启动计时任务，到点结束游戏并广播；每帧处理前也检查一次，计时任务稍有延迟时也不会多放进一个操作。`create_app` 增加 `duration`、`clock` 参数；`__main__` 增加 `--duration`。
- `protocol.py`：协议版本 4。居民视图增加 `coins`（总额，含预留）、`left`、`rank`；世界视图增加 `game`（`ended`、`remainingSeconds`）；客户端可发送 `leave_game`。

客户端：

- `packages/protocol`：对应的视图校验、`LeaveGameAction`、协议版本 4。
- `GameStore`：按本地单调时钟记录截止时刻，`remainingSeconds()` 供倒计时。
- 界面：顶栏倒计时（`ui/format.ts`）；新增 `RankingPanel`；居民列表的“已出局”标签；操作面板的“退出游戏”按钮（先确认）；`GameStore.canAct` 统一判断能否操作，出局或结束后面板按钮禁用、点击地面不再发出移动；地图上出局居民半透明。

留给后续：房间与开局流程（目前重启服务端即新开一局）；回合制；交易与答复事件的原语进入协议；居民物品在协议中的展示；设计稿中的其余初始条件（面包、体力）；断线等情况由系统调用 `leave_game`。

## 关键选择

- **金币是居民的独立余额**：排名只看金币，出局时金币保留、物品清零，两者规则不同，拆开后更直接。收付函数放在 `inventory.py`，沿用“不足时整体拒绝”和 `InventoryError`。
- **公开的是金币总额**：设计稿要求排行榜把冻结金币计入总额，所以视图中的 `coins` 和排名都用余额加待处理购买报价中预留的金币。出售报价预留的是物品，不计入。
- **名次并列**：设计稿规定金币相同则并列；采用 1、1、3 的竞赛排名。出局者照常参与排名。
- **出局时先撤销报价**：与出局者有关的待处理事件都由发件人撤回，运行与拒绝相同的退回逻辑，双方预留各自退回；然后清空物品。因此出局者的金币包括退回的预留，别人发给他的报价也会退回。
- **结束时同样撤销所有报价**：符合设计稿“撤销未成交委托、退回冻结金币，再计算排名”。之后世界冻结，`perform` 一律拒绝。
- **截止时间在服务端进程中，用单调时钟**：`World` 只记录是否结束；剩余时间在发送状态时计算。客户端以收到状态的本地时刻为起点倒计时，不依赖两台机器的时钟一致；到点后以服务端推送的 `ended` 为准，在此之前显示“即将结束…”。
- **剩余时间随状态发送，不另设心跳**：状态只在变化或结束时推送，客户端本地倒计时足够，不增加消息量。

## 验收条件

- [x] 默认世界中每名居民有 10000 金币；金币不是物品，清空物品不影响金币。
- [x] 交易用金币余额完成，金币不足报告 `not_enough_coins`；前一变更的买卖两个方向的行为不变。
- [x] 出局：撤销与其有关的报价并退回双方预留，清空物品，保留金币，标记已出局；之后其所有原语以 `resident_left` 拒绝，别人也不能向其发报价；其他居民照常行动。
- [x] 结束：撤销所有报价并退回预留，世界冻结，所有原语以 `game_over` 拒绝；到点后无需任何操作即推送最终状态；截止后到达的第一帧先结束游戏再处理。
- [x] 排名按金币总额（含预留）计算，相同并列，出局者保留名次。
- [x] 协议 4：状态中有 `coins`、`left`、`rank`、`game`；`leave_game` 可经 WebSocket 发送，缺少或错误的 `residentId` 回复 `bad_message`；客户端拒绝不符合的状态。
- [x] 页面：倒计时、排名、出局标记与禁用、退出确认、结束后的最终排名，两页面同步。
- [x] 服务端 `make verify`、客户端 `npm run verify` 与 `python3 scripts/check_repo.py` 通过。

环境：macOS，Python 3.12，Node 22.19，Chrome 156 无头模式（swiftshader），经 DevTools 协议驱动。日期 2026-10-27。

- 服务端 `make verify`：ruff、`ruff format --check`、mypy strict 通过；pytest 193 个测试通过（新增 `tests/test_lifecycle.py` 8 个，世界、物品栏与金币、交易、接口测试相应增改）。1 条 starlette 关于 httpx 的弃用警告来自依赖。
- 客户端 `npm run verify`：tsc、ESLint、Vitest 6 个文件 58 个测试、`vite build` 通过；`python3 scripts/check_repo.py` 通过。
- 端到端：`uv run aiverse-server --port 8765 --duration 45` 加 Vite 开发服务器（`AIVERSE_SERVER_PORT=8765`），同时打开页面 A、B，1400 × 1000：
  - 开局两页都显示“剩余 0:42”左右并逐秒减少，排名四人均为 1、10,000 金币。
  - A 选中阿青，点“退出游戏”，确认框文字正确；A、B 的排名和居民列表都给阿青加上“已出局”，名次与金币不变，地图上阿青变淡；A 的移动与退出按钮禁用，显示“阿青 已出局，不能再操作”。
  - B 选中小麦移动到 (40, 40)，执行成功，A 同步；游戏照常进行。
  - 到点后两页无需操作都变为“游戏已结束”和“最终排名”，操作按钮禁用。

保留的疑点：
- 计时任务从不被 await；若 `end_game` 抛异常（目前的事件种类不会），计时任务静默结束，之后每帧前的 `expire()` 也会抛，使连接的接收循环中断。新增事件种类时须遵守 `on_decline` 不失败的契约，届时可考虑给计时任务加日志。
- `leave_game` 的内部接口目前只到世界这一层；以后断线处理需要在 `Game` 上写回世界并广播，与“把执行、提交、广播收进 `Game`”的后续工作一起做。
- `test_the_clock_ends_the_game_without_any_action` 的 `receive_json()` 没有超时，计时器回归时测试会卡住而不是失败。
