# 0087：自带算力排队、降速，份额持有人也能放内容

状态：已完成（服务端；页面未接入，协议未变）。

## 目标与依据

用户（2026-11-09）针对“居民之间看不到建造和内容的分工”的分析（见[算力与节点](../docs/design/compute-and-nodes.md)的分工决定）给出三点：

1. 让自带算力排队，并降低它的建造力，让自己做比外包更费时间，从而有外包的理由。
2. 让地块的共有人（份额持有人）也能把内容放进设施。
3. 定价参考或现货市场：只问了“怎么做”，本次不实现，设计写在[内容](../docs/design/content.md)的“暂未实现的功能”。

另一项：把交易的成交情况写进观察，让居民知道外包有没有真的发生（本次只做了居民之间的转账笔数与金额）。

## 范围

- 服务端（`aiverse-server`，提交 `1f4d702`）：`core/compute.py` 的 `SELF_JOBS = 3` 与 `ComputeBook` 不变量；`economy/compute.py` 的 `SELF_RATE` 0.5、排队与 `self_queue_full`；`economy/ads.py` 的 `place_content` 允许份额持有人；`agents/observation.py` 的 `recent_payments` 与 `land.mine`；`agents/system_prompt.py`、`agents/tools.py` 与文档字符串里的规则文字。
- 设计文档：[算力与节点](../docs/design/compute-and-nodes.md)、[地块份额](../docs/design/parcel-shares.md)、[内容](../docs/design/content.md)、[土地](../docs/design/land.md)。
- 协议不变，页面不变。

## 关键选择

- 排队上限：一件在做，最多排 2 件，共 3 件（`SELF_JOBS`）。用户没有给数字，Claude 选的。
- 速度：自带算力从每秒 1 减到 0.5（用户只说“降低”，没有给数字，Claude 选的，试玩后调）。
- 排队的结束时刻 = 前面最晚结束的自带工作的结束时刻 + 自己在自带速度下的用时；`started_at` 仍是下单时刻，所以排队中的工作也能被校验。
- 订阅到期的尾巴不进排队（已知限制，见设计文档的“暂未实现”；待产品决定是否修）。
- 份额持有人和地主都能放内容；卖光份额的地主仍能放。
- `ScriptedBrain`（服务端的脚本机器人）因 `land.mine` 包含共有地块，现在也会为共有广告位做内容（副作用，待确认是否接受）。
- 定价参考与现货市场：未决定，只写了设计思路。
