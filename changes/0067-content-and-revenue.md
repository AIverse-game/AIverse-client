# 0067：内容与收入

状态：已完成。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤的第 3 步，用户（2026-11-07）要求开始做：“内容：渲染式节点与渲染工作做内容，放进广告位，保鲜期，按流量和内容数付钱。”

可观察的变化：局里有了收入来源。居民可以订阅渲染式节点、用渲染工作做内容（物品 `ad_content`），内容可以交易，也可以放进自己地块上的广告位；广告位展示内容时，每 30 秒按流量和内容数付金币给地块主人；内容放进去 300 秒后消失。AI 居民多了 `make_content`、`place_content` 两个工具和 `buy_node` 的 `kind` 参数，观察里多了广告位的内容和预估收入。页面和协议不变。

## 范围

服务端（`aiverse-server`）：

- `core/compute.py`：节点种类加 `render`，工作种类加 `make_content`，内容工作没有地块；`core/land.py`：`Facility` 记展示中的内容的过期时刻和下一次付款时刻，`AD_SLOT_CAPACITY`；`core/world.py` 的不变式跟着改。
- `economy/ads.py`（新）：内容物品、放进广告位、按流量付钱、附近广告位分流、下一个付款日；`economy/compute.py`：`start_make_content`，把开工抽成共用的 `_start_job`，节点种类与工作种类要对上，完工时内容进物品栏；`economy/exchange.py`：`ad_content` 有挂单簿。
- 原语 `MakeContent`、`PlaceContent`（走路时也能用）；`game/clock.py` 把付款接进结算和下一个到点时刻。
- Agent：工具、按状态选工具、观察、系统提示、脚本机器人、完成内容工作时唤醒。

## 关键选择

见设计文档“争议讨论与决定”中第 3 步的取舍：内容是一种可交易的物品、渲染式与生成式节点并列、谁都能做内容、放进广告位的保鲜期与容量、整点付款与附近分流、出局的地主照样收款、首版数值。均为 Claude 的取舍，用户尚未逐项确认。

## 验收条件

- [x] 自带算力做内容，1 分钟后物品栏多一份，不花金币；雇节点 6 秒、180 金币；渲染式节点按秒收费、一次一件；用错种类的节点被拒绝。
- [x] 内容放进自己的广告位后展示 300 秒，到期消失；一个广告位至多 5 份；不是自己的地块、没有广告位、没有内容、已满都被拒绝且世界不变。
- [x] 每 30 秒整点，展示内容的广告位按“流量 ÷ 附近展示内容的广告位数 × 份数 × 0.2”付给主人，流水账记 `visitors`；没有内容的广告位没有收入也不分流量；新放内容的广告位从下一个整点开始领。
- [x] 内容可以在交易所挂单、报价、签合约买卖。
- [x] AI 居民能做内容、放内容；观察里有广告位的内容和预估收入；内容工作完成时被唤醒。
- [x] 脚本机器人快进一局后，访客付的钱超过地价。

- 独立审查（独立子 Agent）：未发现 P0/P1。确认并已处理：P2 唤醒会漏（内容到期使数量下降，再有工作做完时净增为 0），改为比较居民正在运行的工作 id，做完的工作消失就唤醒；P3 `build_ad` 的错误码顺序在抽出共用函数后变了，已恢复；P3 观察里的预估收入按“现在”而不是下个付款日算，改为按下个付款日；P3 若干过期的文档与注释；P3 设施的 `next_pay_at` 补校验；补了相邻广告位同次付款、付款时刻正好过期、隔一块分摊等测试。保留未处理：一轮之内开始又做完的工作不触发唤醒（空闲时有 20 秒兜底，走路时要等走到）；`Facility` 的 `next_pay_at` 默认 0 配合手工构造的世界可以触发补付，正常游戏路径到不了。
