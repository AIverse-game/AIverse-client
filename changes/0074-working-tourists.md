# 0074：工作游客与入场费

状态：已完成（首版）。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤第 7 步的第三部分，接在[变更 0072](0072-visitors.md)（脚本访客）和[变更 0073](0073-sponsors.md)（赞助商）之后。用户（2026-11-07）此前已决定：第 7 步全做、分多次变更；**入场费由系统统一定价，居民不定价**。这次开工时用户又要求：设计文档按功能模块各写一份，把设计细节都记下来。

可观察的变化：一部分游客（工作游客）这一趟走一条大致的路线，先去工作空间，再去展示着游戏的游戏厅，在门口付入场费（工作空间 4、游戏厅 6 金币每人）；入场费在付款日整枚硬币地按份额分给设施地块的持有人，账本渠道 `visitors`。游戏厅和工作空间第一次有了收入。AI 居民的观察里自己的工作空间和游戏厅多 `people_admitted`，`income_last_payday` 含入场费。协议和页面没变。

## 用户的纠正

这个变更第一次提交（`89fe2c2`）时，把“工作用户”做成了访客里单独的类型，带一个每趟 6～14 金币的钱包，付不起的设施不去。用户（2026-11-07）随后指出：**“工作用户”其实是工作游客，除了有一个大致的路线之外，和普通游客没有任何区别，也不应该有一个所谓的“钱包”**。这两点都是 Claude 的误解（“消费池”“类型”原是 Claude 自己写在设计里的，不是用户的），已改：去掉 `kind`、`purse` 和钱包相关的所有规则，访客只有一种，走工作路线的游客只多一条 `route`。下文按改正后的样子写；第一次提交里的相关内容以此为准。

## 范围

服务端（`aiverse-server`）：

- `core/admissions.py`：`AdmissionBook`（未付的费用、累计进门的人数、上次付款日、上个付款日各设施收到的钱）；`World.admissions`，默认空。
- `core/visitors.py`：访客多 `route`（这一趟还要去的大致路线，空表示普通游客逛广告位）；`goal` 的 `slot` 改名 `place`（去的不一定是广告位）。
- `economy/visitors.py`：每趟进城按 `ROUTE_SHARE = 0.3` 走工作路线；走路线的游客按工作空间、游戏厅的顺序去，没有候选的一站直接跳过，不去逛广告位；工作空间按一份内容的吸引力算，没有游戏的游戏厅不是目的地；停留时间按设施种类（广告位 6～14 秒，工作空间 20～40 秒，游戏厅 10～20 秒）；走完一段时在门口收费。
- `economy/admissions.py`：`FEES`、`admit`、`pay_admissions`（付款日整枚硬币地按份额付给持有人，零头留到下次）、`next_admission_payday`。
- `economy/sponsors.py`：付款日的判断抽出 `next_payday_after`，入场费与赞助商共用同一套付款日。
- `core/ledger.py`：渠道 `visitors` 现在表示入场费；`game/clock.py`：付款日接进到点结算。
- `agents`：观察里自己的地块多 `people_admitted`，`income_last_payday` 含入场费；系统提示和 `build_venue`、`place_content` 的说明不再说这两种设施不赚钱。

## 关键选择

见 [venues](../docs/design/venues.md) 和 [visitors](../docs/design/visitors.md) 的“争议讨论与决定”。要点：入场费由系统统一定价（用户决定）；工作游客除了路线和普通游客没有区别、没有钱包（用户纠正）；入场费在付款日批量付、零头不丢（Claude）；路线上没有候选的一站直接跳过（Claude）；游戏厅没有游戏就没有访客（Claude）；走路线的游客路过广告位也算展示（Claude）。除统一定价和上面的纠正外，均为 Claude 的取舍。

## 验收条件

- [x] 走工作路线的游客先去工作空间，再去展示着游戏的游戏厅；去不了的一站（没有这种设施、游戏厅没有游戏）跳过，全跳过就离开，不漫游；除了路线，和其他游客一样，没有类型、没有钱包。
- [x] 进门时付费用乘以这个访客代表的人数；其他游客不付入场费；走路线的游客不专程去广告位，但路过够久也算展示（走的是同样的路）。
- [x] 付款日把每个设施这期的入场费整枚硬币地按份额分给持有人，账本渠道 `visitors`，零头留到下次；晚醒的时钟不跳过付款日；出局的持有人照样收款；没有整枚硬币时时钟不为它醒来。
- [x] 付出和未付的入场费不超过进门人数乘最高的价。
- [x] AI 居民的观察里工作空间和游戏厅有 `people_admitted`，`income_last_payday` 含入场费；提示和工具说明与代码一致。
- [x] 每个功能模块有自己的设计文档，facilities.md 只留总览和步骤，设计文档索引同步。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过。第一次提交（`89fe2c2`）时 1176 项；按用户的纠正去掉类型和钱包后仍是 1176 项（去掉钱包的几个用例，换成路线的用例），全量约 16 秒。`tests/unit/economy/test_working_tourists.py`（原 `test_workers.py`，13 项：走路线先去工作空间、按人数收费、费用随人数增长、再去游戏厅、路线走完就离开、跳过没游戏的游戏厅和没建的工作空间、没得去就离开不漫游、路过广告位算展示但不专程去、不走路线的游客逛广告位不付费、费用不超过进门人数乘价、走路线的比例、走路速度）、`test_admissions.py`（11 项）、`test_visitor_observation.py` 一项、`test_app.py` 里两条广播用例。
- 变异检查（纠正后 7 个，加纠正前 13 个里与钱包无关的）：改站的顺序、不更新剩下的站、走路线的游客仍去逛广告位、不按人数收费、进门不记入场、让没内容的场所也成为目的地、不走路线，各自都会让至少一个测试失败。
- 独立审查（子 Agent，只读，代码和设计文档一起审）：发现并已修复一个 P2：走路线的游客每次进门都会改 `world.admissions`，而广播判断只忽略访客本身，于是每秒约一次广播并唤醒所有等着世界变化的 Agent（审查模拟 600 秒有 648 次广播，628 次只因入场费变化）；现在也忽略入场费状态，付款日的付款改了金币照常广播，补了经过 `Game.tick` 的用例（撤销修复会失败）。P3：文档说工作游客不看广告位，代码里他们路过也算展示——决定路过算，改了文档、验收条件，并把原来空转的测试换成真正走过广告位的；删掉走不到的拒绝分支和回退；代码注释里“游戏厅和工作空间不赚钱”的几处改掉；测试里 `monkeypatch.undo` 的写法改掉。文档：几处把 Claude 的取舍写成用户确认的地方已更正（拆分顺序、消费池、统一定价的理由），补回用户的决定（访客系统留到设施定了再做、合买由提议人写明份额）和被删掉的细节（订阅 144 金币、内容工作的价格、份额数值与理由、权重增长的理由、传送门出局者不再被列出）。审查确认没问题的：付款日不会死循环（60 个随机世界模糊测试）、钱不会凭空多出、访客的不变量、观察的数。
- 快进模拟：8 个居民共 3 个工作空间、3 个游戏厅、5 个广告位，20 分钟入场费共 8331 金币（去掉钱包前约 5949：付不起游戏厅的游客不去），赞助商共 11769 金币。数只说明量级合理，没有校准过。
