# 0086：授权建造与长期订阅

状态：已完成。服务端提交 `8bdf02e`。

## 目标与依据

用户（2026-11-08）发现居民之间看不到明显分工，比如有人建造、有人制作内容。原因是自带算力免费、每个人都能自己包办、规则里没有让分工更划算的东西。用户的决定：

1. 让按需雇节点变得很贵，订阅节点单位成本低但要一次订很久，可以做很多件；提示词写明这个机制，并鼓励居民合作共赢。
2. 改规则，允许在别人授权的地块上建，必须地主同意；地主也可以主动提出请人来建。
3. 订阅不能一秒一秒地订，要订很长时间。

## 范围

- 服务端（`aiverse-server`，单独提交）：
  - `ON_DEMAND_PRICE` 3 → 15；`NODE_SECONDS` 30～600 → 300～1200；订阅单价不变（每秒 12，约为雇用每工作量价格的 1/12.5）。
  - 新增建造委托 `BuildCommission`（`economy/commissions.py`）：地主或建造者任一方提议某块地、某种设施（广告位、游戏厅、工作空间）和酬金，对方同意才生效。同意后地主的酬金预留（计入排名），建造者得到 300 秒有效的许可 `Permit`，用 `build_ad` / `build_venue` 在那块地上开工；建成时酬金付给建造者（流水账渠道 `commission`）。
  - 许可过期没开工、建造者或地主出局、对局结束时酬金退回地主；拒绝、撤回同理。许可期间地主自己不能在那块地上开工。
  - AI 居民多了 `commission_build` 工具，观察里多了 `build_commissions_to_me`、`my_build_commissions`、`build_permits`；系统提示词写明订阅与雇用的成本、一次要订多久、委托机制与合作。
- 不做：传送门不能委托建；脚本机器人不使用委托；页面和协议不显示许可和委托（协议版本不变）；建成后的收入仍按地块份额分给持有人，想让建造者分成要另用 `offer_shares`；地主不能提前撤销已同意的许可（等 300 秒过期）。

设计文档：修改 [算力与节点](../docs/design/compute-and-nodes.md)。

## 关键选择

- **“求购”的理解**：用户说“执行者也可以主动求购”，实现为双向——地主可以主动请人来建（出酬金），建造者也可以主动申请到别人地上建（要酬金），都要对方同意。（Claude 的理解，待用户确认。）
- **酬金建成才付、同意时托管**：建造者不会白干，地主也不会在建好前把钱花掉；建造者中途出局时钱退回。
- **订阅最短 300 秒**：起步 10000 金币下订一台要 3600，逼居民先想好有多少活再订；上限 1200 即一局的长度。数值是估计，试玩后调。
- **许可期间地主不能自己开工**：避免同一块地上两份承诺。
