# 0070：传送门、线路与传送

状态：已完成。

## 目标与依据

[虚拟设施](../docs/design/facilities.md)实施步骤的第 5 步，用户（2026-11-07）要求开始做：“交通：传送门、线路、缩短有效距离、居民传送。”依据是设计文档“交通：传送”一节：地块偏远时辅以传送，流量更容易到达，自己的几块地之间也更有联动。

可观察的变化：居民可以用生成式工作在自己的空地块上建传送门；两座传送门连成线路（两端主人都同意），线路带过路费；线路让偏远地块到地图中央的“有效距离”变短，这个距离先算好备用（第 7 步的访客用它算走路时间），占位的流量公式不用它，所以线路目前不影响流量（用户 2026-11-07 决定：流量应由模拟的访客决定，不预设访客走门）；站在传送门所在地块的居民可以传到线路另一端，不花行走的时间，付过路费，由两端地块的份额持有人分。AI 居民多了 `build_portal`、`link_portals`、`teleport` 工具，观察里能看到传送门、线路和线路提议。页面和协议不变。

## 关键选择

见设计文档“争议讨论与决定”中第 5 步的取舍：传送门占掉地块唯一的设施位、线路要两端主人同意且至多 3 条、间距至少 30、有效距离按最短路算（不只算门所在的地块）、过路费一半一端并按份额分账、居民之间的流动用渠道 `toll`。均为 Claude 的取舍，用户尚未逐项确认。系统提示有 6000 字符的上限（`test_the_base_prompt_stays_compact`），所以只加了一句，机制写在工具描述里。

## 验收条件

- [x] 传送门由生成式工作建成，建好后地块的设施是传送门；每人至多 4 座（在建的也算）；传送门里不能放内容，也不付款。
- [x] 两座都是自己的门立即连通；连别人的门要对方同意，拒绝、撤回、提议人出局、对局结束后没有线路；同意时再检查一次条件；同一对居民至多同时 3 份线路提议。
- [x] 不合规的线路被拒绝且世界不变：连到自己、没有传送门、不是自己的门、重复连、间距不足 30、一座门已有 3 条线路、过路费不在 0～1000 或不是整数。
- [x] 传送：站在有线路的传送门里、没在走路，传到另一端的地块中心；没有门、没有线路、走路中、付不起都被拒绝且世界不变；过路费一半一端、各自按份额分给持有人，旅行者自己的那份不记流水，金币守恒。
- [x] 有效距离：无线路时等于直线，有线路时偏远地块的门接近中央，线路可以连着走，永远不比直线远；占位的流量不受线路影响。
- [x] AI 居民能建门、连线、传送，观察里有传送门和线路提议，`link_portals`、`teleport` 在适用时自动出现，`transport` 组可展开；系统提示仍不超过上限。

## 验证证据

2026-11-07，macOS：

- 服务端 `make verify`（ruff、ruff format --check、mypy strict、pytest）通过，1082 项测试。新增用例：`tests/unit/economy/test_portals.py`（建门与每人上限、不能放内容也不付款、连线的各种拒绝、提议的同意拒绝撤回与再检查、出局与结束时撤销、传送与过路费分账含奇数币与自付与部分份额、有效距离、线路不影响流量、世界不变式）、`tests/unit/agents/test_transport_tools.py`（工具、观察、选工具、`transport` 组）。
- 独立审查（独立子 Agent）：未发现 P0～P2。它另外跑了随机序列（250 个种子 × 400 步：建门、连线、提议、同意、拒绝、撤回、传送、走路、出局、推进时间、结束），每一步居民金币总额与流水中付给系统的净额吻合、`World` 可重新构造、有效距离不大于直线、每人门数不超过 4，共 747 次成功传送、474 条线路，无违反；另用约 3900 次观察核对 `selected_tool_names` 与 `last_request_tool_names` 一致；32 座门、15 条线路下 225 次有效距离计算约 6 毫秒（审查时流量还按它算）。三个 P3 已处理：出局者的门不再被当作可连的目标（观察和工具选择过滤，设计文档写明）、节点工具的描述补上传送门、补了连向出局者、渲染式节点建门、旅行者持有部分份额三条测试。保留不处理的说明：同一对门可同时挂多份提议，一份被同意后其余的同意时报 `already_linked`、留着等撤回（沿用“失败则留着”的做法）；传送在回合内产生 `moved` 流水，会让居民比空闲更早被唤醒（到了新地方，视为合理）。
- 后续改动（同日，用户决定）：用户指出占位的流量公式不该预设访客会走传送门，要求线路只管居民传送、不影响流量。`footfall` 恢复为只用直线距离，`effective_distance` 留作备用，相关的工具描述、系统提示、测试和文档同步改过。再次交给同一审查 Agent 复核：无改变行为的缺陷，几处残留的旧说法（代码注释、设计文档里线路上限的理由）已改；`make verify` 通过，1082 项测试。
- 未做：浏览器验证（页面未改）；没有用真实模型试过会不会用 `build_portal`、`link_portals`、`teleport`；随机序列没有覆盖合买和合约。
