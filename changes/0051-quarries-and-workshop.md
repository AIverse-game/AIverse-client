# 0051：晶矿、晶砂与工坊炼制

状态：已完成。

## 目标与依据

路线图第 ② 步（用户 2026-11-03 确认，见 [晶核与炼制](../docs/design/crystals.md)）：让晶核从只向系统购买的商品，变成居民能用人力原料炼出来的商品，使居民之间出现原料、中间品和成品的买卖，并让“汲取”和“炼制”成为可以分工的两种营生。用户要求改名（变更 0050）和本步在同一次会话分两步完成。

基线（2026-11-03）显示居民间流量占比只有 4.0%，金币几乎都来自收购点；本步之后，晶砂只能在居民之间流通，晶核有了居民自己的供给。

可观察的变化：AI 居民的观察里出现晶矿、工坊与配方，多了 `dig_shards`、`refine_crystal` 两个工具；收购点卖的晶核涨到原价两倍。页面与协议不变（只是收购点价目随服务端变为 600、2400、6000）。

## 关键选择

- **晶矿公开**：能量泉的发现、记忆与视野内才看得到储量牵涉多处代码。首版让晶矿和工坊、收购点一样公开，储量随时可见，所以不需要改感知与记忆。
- **出局和结束不退原料**：出局本来就清空物品，结束时物品不计分，所以炼制直接作废，不必记原料；挖砂退回晶矿，保持储量守恒，与汲取一致。
- **最后的能量**：核心原语与汲取、卖出一样，不另设限制（花光能量照常出局）；Agent 工具沿用通用的 `last_energy` 保护，炼制不会花掉手上最后的能量。
- **计分折算推迟**：会改变排名，页面排名要一起改，放到协议与页面那一步。
- 这些取舍写进了设计文档的“争议讨论与决定”。

## 验收条件

- [x] 站在晶矿里挖砂，10 秒后得 6 个晶砂，从晶矿扣除；储量不足时只得剩下的；两人同挖不重复。未知晶矿、不在范围、晶矿已空、正在忙时拒绝。出局或结束时晶砂退回晶矿。
- [x] 站在工坊里按配方炼制，开工扣晶砂、能量与上一阶晶核，到时得到晶核，已炼数加一；每炼一块用时减 10%，最低一半。未知阶、不在工坊、晶砂或能量不足、缺上一阶晶核时拒绝；报价中预留的晶砂不算；炼制期间不能走。出局或结束时炼制作废。
- [x] 默认地图有 3 座晶矿和 1 座工坊，离收购点至少 30，离能量泉、晶矿至少 20；同一种子的能量泉位置不变。
- [x] Agent 工具能挖砂、炼制，状态里显示任务；炼制会花掉手上最后的能量时以 `last_energy` 拒绝；观察列出晶矿（由近到远）、工坊配方（按自己的熟练度）、自己的晶砂与任务、每人已炼晶核数。
- [x] 收购点晶核价格为 600、2400、6000。
