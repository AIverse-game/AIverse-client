# 0013：感知与发现

状态：已完成。

## 目标与依据

用户要求（2026-10-28）：加入感知与发现机制，每当 Agent 开始新一轮工作，先注意到所在位置周边一定范围内的物品和事件。

现状与需求之间有三处空白，已向用户确认：

- 尚无 AI 驱动居民，也没有回合时钟，没有“新一轮”可以挂接。用户选择先做服务端接口 `begin_turn(world, resident_id)`，由日后的 AI 循环在每轮开始时调用；不改协议和客户端。
- 地图上没有掉落的物品，可感知的物体只有矿池和其他居民。
- 代码中的“事件”（`events.py`）是居民之间不带位置的请求，且有意不向他人泄露。用户确认这里的“事件”指附近发生的事：新增带位置的世界活动日志，每轮报告自上次查看以来范围内的活动。
- 用户确认见过的矿池要记住（“发现”）：走远后仍记得位置和当时的储量。其他居民的位置按设计文档本来公开，不做记忆。

未向用户确认、由本次自行决定的部分（都是可调的常量或可逆的实现细节）：

- 感知半径 20 地图单位（`PERCEPTION_RADIUS`），按到矿池中心或居民位置的直线距离计算，边界上算在范围内。地图 100 × 100、矿池 6 个，开局时不一定能看到矿池，需要走动探索。
- 范围以感知者**当前**位置为准，不是事情发生时的位置；移动的起点或终点任一在范围内就算看到。
- 活动种类：移动（`moved`）、开始采矿（`started_mining`）、完成采矿（`finished_mining`）、出局（`left_game`）。因出局而中断的采矿只记出局。报价、答复这类不在地图上改变什么的原语不记录。对局结束时停止的采矿不记录。
- 自己的活动不报告给自己。日志只保留最近 500 条（`ACTIVITY_LIMIT`），很久不查看的居民会漏掉最早的。
- 正在采矿的居民也可以感知；出局者、不存在的居民和结束后的对局以 `GameError` 拒绝，与行动相同。

## 范围

服务端（`aiverse-server`）：

- `world.py`：新增 `PoolSighting`（矿池 id、位置、半径、看到时的储量与时刻）、`Memory`（记住的矿池、已看过的最后一条活动序号）、`Activity` 与 `ActivityLog`（条目与下一个序号，最多 `ACTIVITY_LIMIT` 条）；`Resident.memory`、`World.activity`；校验记忆和日志只引用已知的矿池和居民、序号递增、记忆不超前于日志。
- 新增 `perception.py`：`PERCEPTION_RADIUS`、`Perception` 与 `ResidentSighting`、`begin_turn`（返回更新了记忆的世界和这一轮的感知）、`record_activity`（比较前后两个世界写入日志，无事可记时原样返回）。
- `actions.py`：`perform` 执行后调用 `record_activity`，包括 token 耗尽导致的出局。
- `app.py`：`Game.tick` 发放采矿后记录，再判断对局结束。
- 测试 `tests/test_perception.py`；README 的功能说明和代码结构。

不做：协议与页面展示、AI 循环与回合时钟、他人背包等私有信息、地面物品、其他居民的位置记忆、感知范围随地形或状态变化。

## 关键选择

活动日志用“比较前后世界”的方式生成，与 `knock_out_exhausted` 相同：无论移动、采矿、出局由哪条路径引起（原语、时钟、token 耗尽），都在 `perform` 和 `Game.tick` 两个入口统一记录，各规则模块不需要知道日志的存在。代价是同一次比较里只能看出状态差异，不能区分同一居民在一次变化中的多步（目前每个原语最多一步，不受影响）。

感知会改变居民的记忆，因此 `begin_turn` 返回新的世界，调用方需要像提交原语结果一样提交它。它不是原语：不消耗 token，不受忙碌限制，也不广播（记忆不在协议中）。

## 验收条件

- [x] 范围内的矿池与其他居民出现在感知中，范围外的不出现，边界算在内。
- [x] 首次看到的矿池列为新发现；走远后仍记得，储量保持上次看到的值；回来后更新。
- [x] 他人在范围内的移动、开始与完成采矿、出局各报告一次；自己的不报告；范围外的不报告；范围按当前位置计算。
- [x] 时钟发放的采矿被记录；对局结束时停止的采矿不记录；采矿中出局只记出局；走路花光 token 记移动和出局；报价不记录。
- [x] 出局者、不存在的居民、结束后的对局不能感知；采矿中可以。
- [x] 日志超过上限时丢弃最早的，序号继续递增；世界拒绝引用未知矿池、居民或超前序号的记忆与日志。

## 交接

- AI 接入时：每轮开始先 `Game.tick`（推进 `World.time`，否则活动与看到的时刻会停在上次推进时），再在同一段无 await 的代码里对最新的世界调用 `begin_turn` 并提交返回的世界，与 `app.py` 处理一帧的方式相同；用过时的世界提交会覆盖期间别人的改动。然后把 `Perception` 整理进给模型的状态。半径、日志上限都未经试玩调参。
