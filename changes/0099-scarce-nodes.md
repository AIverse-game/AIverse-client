# 0099：全镇算力节点有限

状态：已完成（服务端 `make verify` 通过；协议与页面不变）。

## 目标与依据

上一局真实对局（2026-11-10，40 分钟，8 名 AI 居民）居民之间的金币流量只占 0.9%：地、算力都向系统买，收入由系统付，谁都不需要别人。用户（2026-11-11）要求算力节点数量有限，并且要让 AI 知道有限、总共有多少、现在还剩多少；数量定为每种“居民数 × 2/5，向下取整”，8 人时生成式、渲染式各 3 台。

可观察的变化：某种节点全被占用时，订阅和按需雇用这种节点都被拒绝（`no_node_free`），要等一台回来；AI 的观察里有全镇节点的总数、空闲数、谁订着几台和最近一台多久后回来；系统提示写明总数。

## 范围

服务端（`aiverse-server`）：

- `economy/compute.py`：`NODE_SUPPLY_SHARE`、`node_supply`、`nodes_in_use`、`nodes_free`；`buy_node` 和按需开工检查空闲节点，新错误码 `no_node_free`。
- `agents/observation.py`：`compute.town_nodes`（每种节点一项：`total`、`free`、`held_by`、`hired`、`next_free_in`）。
- `agents/tool_selection.py`：两种节点都没有空闲时不给 `buy_node`。
- `agents/system_prompt.py`、`agents/tools.py`：说明节点有限。
- README、测试。

不做：页面和协议显示全镇节点（页面没有节点界面，选“按需节点”时服务端拒绝并给出原因）；预约下一台空出的节点；居民之间转租节点。

设计文档：修改 [算力与节点](../docs/design/compute-and-nodes.md)。

## 关键选择

- **按需雇用也占一台节点**（Claude）：雇用的节点代表同一批厂商机器，不占就能绕过限量。做完那件工作即归还。
- **订阅到期的尾巴不占节点**：尾巴按自带算力的速度做完，节点已经还回去了。
- **至少 1 台**（Claude）：2 人的小世界按公式是 0 台，谁都用不了节点。
- **人数按开局的居民算**，出局的也算，整局不变。
- **公开谁订着几台**（Claude）：让居民能找到持有节点的人代工（`commission_build`）或买内容。
- **工具说明只写一句**：工具说明有长度预算（`test_the_brain_advertises_tools_for_the_residents_current_state` 要求小于 8200 字符），规则写在系统提示里，`buy_node` 只加“只有空闲的能拿到，见 compute.town_nodes”。

## 验收条件

- [x] 8 名居民时每种 3 台；不同人数按公式取整，至少 1 台。
- [x] 某种节点全被订走时，订阅和按需雇用这种节点都被拒绝（`no_node_free`），另一种照常。
- [x] 按需的工作做完、订阅到期时节点归还；订阅到期后继续的尾巴不占节点。
- [x] 观察给出每种节点的总数、空闲数、持有人、按需占用数和最近归还时间。
- [x] 两种节点都没有空闲时 `buy_node` 不出现在两个工具选择器里，真实调用被拒的原因相符。
- [x] 系统提示写明 8 人时每种 3 台（测试按 `node_supply` 断言）；工具说明不超过 8200 字符的预算（系统提示没有长度测试）。
