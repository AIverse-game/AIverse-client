# 游戏画面与世界日志

状态：首版已实现。
更新：2026-11-10。
相关：[变更 0091](../../changes/0091-pixel-hud-and-world-log.md)、[决策 0008](../decisions/0008-pixel-fonts.md)；页面 `apps/web/src/ui/App.tsx`、`TopBar.tsx`、`WorldLogPanel.tsx`、`worldLogText.ts`、`apps/web/src/styles.css`；服务端 `aiverse_server/game/world_log.py`，协议 31 的 `worldLog`。

## 问题背景

用户（2026-11-10）提出三点：

1. 世界不再放在一个框里，而是占满整个屏幕；右侧仍是操作面板，整体是科幻像素风，字体尽量用像素字体。
2. 增加一个同样风格的“世界日志”面板：打开后输出每个人做的每一件事，包括当众说话、私聊、建造、买地等，尽量写成自然语言，如“A 对 B 说：内容”。
3. 日志像终端一样，从上到下越来越新，新事件追加在最下面，把旧的顶上去。

当时的现状：地图画在页面左侧一个圆角框里，下面是所选居民的 AI 行动时间线，右侧一列圆角面板，用系统无衬线字体。页面能看到的“发生了什么”只有对话面板：所有当众说的话加上所选居民自己的私聊，其余私聊、报价、开工与建成都不发给页面（服务端按 `view_as` 过滤）；居民附近的活动日志只给 AI 感知用，不进协议。所以世界日志不能只在页面拼，需要服务端记一份全镇的记录。

## 设计思路

### 全屏画面与面板

- 页面根（`.app`）用 `position: fixed` 铺满视口，地图（`.stage`）绝对定位铺满它；渲染器原本就用 `ResizeObserver` 跟随容器大小，不需改动。
- 其余界面都浮在地图上：左上是顶栏（标志、连接状态、倒计时、“世界日志”“操作面板”两个开关），右侧是 380px 宽、可单独滚动的操作面板列，左下是世界日志窗口。
- “操作面板”开关可以收起整列面板，只看地图；收起后顶栏和日志的宽度随之放宽。AI 行动时间线从地图下方移入面板列（放在“AI 驱动”后面），面板顺序其余不变。
- 窄屏（≤ 900px）时面板列改为贴底、最高 45% 屏高，世界日志放在它上方。
- 坐标读数（`.map-cursor`）从地图左上角移到可见地图的右上角（面板列左边，收起面板时贴右边），避开左上的顶栏（可能换行）和左下的日志；面板列展开且窗口不超过 1040px 时会和顶栏相撞，这时不显示（收起面板时仍显示），≤ 900px 时一律不显示。

### 科幻像素风

- 色板：深海军蓝底、霓虹青（主色，边框、标题、按钮）、品红（次色，标题方块、私聊、日志）、金色（金币与倒计时）、绿色（成功）、红色（错误、出局）。变量都在 `styles.css` 的 `:root`。
- 面板是直角的半透明深色盒子，2px 暗青边框外加一圈黑边，四角用伪元素画出霓虹青的直角括号；标题栏带渐变底色和品红小方块。
- 按钮、输入框都是直角，按钮有 2px 黑色投影，按下时位移 2px、投影消失；滚动条也做成方块。
- 全屏叠一层很淡的扫描线和暗角，`pointer-events: none`，不挡操作。
- 字体：正文用 Fusion Pixel 12px（简体中文像素字体，含拉丁字母和数字），标志用 Silkscreen。像素字体只在设计尺寸的整数倍时清晰，所以界面文字统一 12px，标志和交易所价格 24px，并关闭字体平滑。两种字体都从 npm 的 `@fontsource` 包打进构建，见[决策 0008](../decisions/0008-pixel-fonts.md)。

### 世界日志

服务端：

- `World.world_log` 保存最近 200 条 `WorldLogEntry`（`core/world.py`），每条有序号、游戏时间、种类、行动者，以及按种类填写的字段：对方居民、话、地块、另一地块、设施、物品、数量、金币、交付次数、位置、请求种类（`deal`）、买卖方向。
- `game/world_log.py` 的 `perform_logged` 执行原语后，按原语和前后两个世界写一条记录；页面操作、Agent 的 `Game.act` 和 Agent 工具都改用它。被拒绝的原语不改世界，也就不记。时钟在 `clock.settle_due` 里用 `record_finished_jobs` 记下完成的工作（设施建成、内容做好），时间是工作完成的那一刻。
- 记录的种类：说话（当众说带听到的人数，私聊带对象）、出发行走、传送（记线路的过路费，不是传送者的净支出：持有两端份额的人会分回一部分）、退出、买地（街区的块数与花费）、订阅节点、开工建设施、开始制作内容、设施建成、内容做好、放入内容、发出请求、接受、拒绝、撤回、按合约交付、取消合约、挂单、撤单、自己连通两个传送门。请求和对它的答复记下同样的条款（报价的物品、数量、金额，合约的供货方向与次数，委托由地主还是建造者发起等），答复的“对方”是发起人，撤回的“对方”是接收人。
- 协议 31 在 `state` 里加 `worldLog`，每条连接都一样，不按 `view_as` 过滤；字段只发该种类用到的。

页面：

- `ui/worldLogText.ts` 把一条记录写成中文句子，居民以 id 留在句子里，由面板按名字和居民颜色显示。例如“甲 对 乙 说：卖你算力”“甲 当众说（2 人听到）：有人吗？”“甲 花 2,400 金币 买下 L3-4 所在街区（9 块地）”“乙 接受了 甲 的收购报价：出 30 金币 买 2 个广告内容”。
- `ui/WorldLogPanel.tsx` 是终端式窗口：每行前面是 `[分:秒]` 游戏时间，新记录追加在最下面；停在底部时自动跟随最新一行，往上翻看时不打断，翻回底部后继续跟随。末尾有闪烁的 `> _` 光标；对局结束时加一行“== 对局结束 ==”。不同种类的行用不同颜色：私聊品红、建成与成交绿色、买地和报价金色、移动与开工浅蓝、拒绝与撤回灰色、退出红色。
- 日志默认关闭，点顶栏的“世界日志”打开，右上角 × 关闭。

## 争议讨论与决定

- **日志的数据从哪来**：只在页面上比较前后两个快照 → 拿不到别人的私聊和报价，也分不清接受和拒绝；由服务端记录（Claude，2026-11-10）。用户明确要求私聊也要出现。
- **私聊是否公开给所有页面**：对话面板和交易面板仍只给所选居民看自己的私聊与报价；世界日志则给所有页面看全部（用户要求，2026-11-10）。服务端目前没有身份认证，`view_as` 本来就能看任何居民，所以这不改变实际的保密程度；以后有了玩家身份，要重新考虑日志对玩家是否只给观战者看。AI 居民的感知不读世界日志，它们之间的信息差不变。
- **句子在哪一端拼**：服务端直接发中文句子 → 服务端其余面向模型的文字都是英文，界面文字一直在页面拼（如 `dealText.ts`）；服务端发结构化记录、页面拼句（Claude，2026-11-10）。代价是协议多一个字段较多的结构，新增种类要两边一起改。
- **记录挂在哪里**：在 `actions.perform` 里直接记 → `world_log.py` 要导入原语类型，会和 `actions.py` 循环导入；改为 `perform_logged` 包一层，三个调用处改用它（Claude，2026-11-10）。直接调用 `perform` 的地方（多为测试）不会记日志。
- **每个状态都带完整日志**：每次广播都发最近 200 条，按每条约 150 字节约 30KB；本地对局可以接受，省去页面累积和补发的逻辑（Claude，2026-11-10）。
- **交易所成交不记**：交易所设计为匿名，日志记谁挂了单、撤了单，不记谁和谁成交（Claude，2026-11-10）。
- **字体**：Google Fonts 等外链 → 离线不可用；DotGothic16 → 日文字形，缺少“说”“买”等简体字；Fusion Pixel 12px 简体版 → 覆盖所需字形，OFL 许可，单个 woff2 约 600KB，选它（Claude，2026-11-10），见[决策 0008](../decisions/0008-pixel-fonts.md)。
- **商品显示名**：日志里会出现 `ad_content`、`game_content`，在 `exchange.ts` 的商品名表里补上“广告内容”“游戏内容”，交易所面板一并受益（Claude，2026-11-10）。

## 暂未实现的功能

- 日志不记时钟引起的其他变化：付款日的设施收入、合约到期、挂单过期、许可失效、行走到达，以及服务端的结束通知；对局结束只在页面加一行。
- 交易所成交（匿名）和 AI 记笔记、忘笔记（`remember`、`forget`，不经原语）不记；挂单立即成交时日志只有“挂单”一句。
- 退出游戏顺带撤销的报价、终止的合约只记一句“退出了游戏”。
- 日志满 200 条后，往上翻看时每来一条新记录顶部就删一条；Chrome 的滚动锚定能保持位置，没在 Safari 等浏览器里看过是否跳动。
- 页面不累积超过服务端保留的 200 条；中途打开页面只看到最近 200 条。
- 日志窗口不能拖动或改大小，也没有按居民或种类筛选、搜索。
- 面板列的开关状态和日志的开关不记在 localStorage，刷新后恢复默认。
- 面板列的宽度固定 380px；没有在真机手机上试过窄屏布局，只在 420px 宽的无头 Chrome 截图中看过。
