# 虚拟设施（总览）

状态：设计中；实施步骤的第 1～7 步已完成，第 8～9 步（页面、试玩调参）未做。2026-11-07 规则重定；此前按旧方案实现的改名、地块、素材、广告位、服务器与会议室（变更 0061～0063）保留在 `legacy` 分支，`main` 上按新规则开发。
更新：2026-11-07。
相关：各模块的设计文档见下面“设计思路”里的列表；[经济指标](economy-metrics.md)；变更 [0061](../../changes/0061-virtual-world-terms.md)～[0074](../../changes/0074-working-tourists.md)。

这份文档是虚拟设施玩法的总览：为什么这样改、由哪几块组成、按什么顺序做、金币怎么流。**每一块的设计细节、取舍和数值写在各自的设计文档里**，不在这里重复。

## 问题背景

到 2026-11-07，金币几乎都来自收购点收购算力（原称能量）：居民采集、卖给系统，玩法单一，居民之间的金币流量只占约 4%（见[经济指标](economy-metrics.md)的基线）。金币只有进来的路（收购点，后来加上访客），出去的只有买程序和买地，局里的钱越来越多。

用户（2026-11-07）先决定把目标改为**在虚拟世界里建造设施赚取金币**，按“原料 → 加工 → 基础设施 → 营业设施”的旧方案做了三步（见下文“早先方案”）。随后用户重新捋了规则：建设施需要的应当只有**算力、时间和空间**，没必要的玩法都去掉。

## 设计思路

三样东西：

- **空间**：地块。地图划成网格，用金币向系统买。地段好坏由访客的选择和布局决定。
- **时间**：一局只有 20～40 分钟，时间是最紧的资源。
- **算力**：单位时间能做多少工作，是速度，不是可以携带的东西。一件工作的耗时 = 工作量 ÷ 算力。

由这些模块组成，每个模块一份设计文档：

| 模块 | 文档 | 一句话 |
| --- | --- | --- |
| 地块 | [land](land.md) | 15 × 15 的网格，按离中央远近定价，整局归买主 |
| 算力与节点 | [compute-and-nodes](compute-and-nodes.md) | 自带算力、按需与订阅的生成式和渲染式节点，工作挂在算力来源上 |
| 内容 | [content](content.md) | 渲染工作做出的可交易物品，放进设施，有保鲜期，吸引访客 |
| 地块份额与合买 | [parcel-shares](parcel-shares.md) | 每块地 100 份，收入按份额自动分账，份额可转让，两人可合买 |
| 交通：传送 | [portals](portals.md) | 传送门与线路，居民传送付过路费，访客走线路免费 |
| 场所与入场费 | [venues](venues.md) | 游戏厅和工作空间，走工作路线的游客付系统统一定价的入场费 |
| 脚本访客 | [visitors](visitors.md) | 200 个脚本做的游客，按偏好逛设施，部分走一条大致的工作路线，路过或停留算展示 |
| 赞助商 | [sponsors](sponsors.md) | 三个镇外买家带预算，按展示向广告位付费 |

模块之间怎么接起来：居民用算力（时间换来的速度）在自己的地块（空间）上建设施，用渲染工作做内容填进设施；脚本访客按设施里的内容、距离和拥挤度选去处，路过或停留就是展示；赞助商按展示付钱，工作游客进场所付入场费；钱按地块份额分给持有人。

### 金币的来去

- 进：赞助商按展示量付给广告位的持有人（[赞助商](sponsors.md)，渠道 `sponsors`）；工作游客付给工作空间和游戏厅的持有人的入场费（[场所与入场费](venues.md)，渠道 `visitors`）；开局资金。两者都是镇外来的钱，总量由赞助商预算和访客数限制。
- 出：买地、按需节点、订阅节点（都付给系统）。
- 居民之间：买卖内容、转让份额、传送过路费、代工（替别人建设施、做内容），走现有的报价、交易所和合约。
- 排名仍只算金币（延续变更 0057）；设施、地块、份额、内容结束时都不折算。

### 去掉的玩法

算力泉、采集、采集节点（含租金与维护费）、收购点（收算力、卖程序）、数据、数据矿、程序、工作室与编写、素材、服务器与承载费、会议室。算力不再是物品，行走只花时间，也不再因为算力耗尽出局。占位的访客流量公式（中央最热、居民加流量、附近广告位平分）也在变更 0073 删除。

保留：地图、行走、地块网格与购买、报价、交易所、合约、对话、感知、记忆、流水账、对局时长与排名。

## 争议讨论与决定

整体规则（以下由 Claude 提议，用户于 2026-11-07 确认）：

- **只要算力、时间、空间**：用户提出，算力是“单位时间的算力 × 时间”，高算力节点代表游戏外的厂商，用金币订阅或按需购买；节点分生成式（建设施）、渲染式（做内容）；内容填充设施，内容越多越值钱；收入大头归空间占有者，可协商分红或合伙，以至形成公司。
- **Claude 补充的几点**，用户同意：内容有保鲜期，否则创作者只做得了一单生意；订阅比按需便宜，闲置也付钱；每人保留一点自带的低速算力，开局不会卡死；分红先做地块份额与自动分账，不急着做公司实体，因为模型不擅长反复谈判。
- **没必要的玩法都去掉**（用户决定）：这次改动大，用户要求先把当时的版本留在 `legacy` 分支，`main` 上继续开发。两个仓库都在 `9154ea4`（服务端）、`3736a60`（客户端）建了 `legacy` 分支。
- **数值**都在实现时定首版，试玩后调整。

第 1 步（变更 0064）实现时 Claude 的取舍，用户尚未逐项确认：

- **说话不再花东西**：说话原来从携带的算力里扣，算力不再是物品后没有可扣的东西；现在说话免费，也没有冷却，Agent 自己受两轮至少相隔 3 秒的限制，但页面或脚本可以不停发 `say`，每句当众说的话会唤醒范围内所有 AI 居民（各花一次模型请求）。独立审查指出了这一点；服务端目前没有鉴权，先记下，接真实模型长时间试玩前需要加冷却或小额费用。
- **交易所、报价与合约原样保留**：当时游戏里没有任何物品，Agent 仍能看到这些工具但调用必然失败；内容（变更 0067）做出来后成为第一批商品，交易所现有 `ad_content` 和 `game_content` 两本挂单簿。
- **脚本机器人**：当时只会花钱（说话、按固定路线走、买一块地）；之后会照看自己的广告位（做内容、放进广告位）。它们不转让份额、不建传送门、不建游戏厅和工作空间。

拆分与顺序：

- **访客系统留到设施基本都定了再实现**（用户 2026-11-07 决定）：所以先做了设施（第 2～6 步），再做访客与赞助商（第 7 步）。

- 2026-11-07 在第 2 步与第 3 步之间加入交通（Claude 的安排，用户尚未逐项确认）；同一天又把设施、访客与赞助商放在页面和试玩之前，原来的第 5、6、7 步顺延为现在的第 8、9 步并拆出新的第 5～7 步。更早的变更说明（0061～0067）里的步骤编号是按旧编号写的。
- 第 7 步全做、分三个变更（用户决定“全做、分多次”；拆法是 Claude 的）：脚本访客、赞助商、工作游客与入场费。入场费由系统统一定价（用户决定）、去掉居民加流量（用户决定）。

早先方案（2026-11-07，已被新规则取代，代码在 `legacy` 分支）：

- 资源改为虚拟世界的名称：能量 → 算力，晶砂 → 数据，晶矿 → 数据矿，晶核 → 程序 v1～v3，工坊 → 工作室，汲能塔 → 采集节点（变更 0061）。
- 产业链：算力、数据 → 程序、素材 → 地块、服务器 → 广告位、会议室、游戏厅；收购点保留为低价兜底。实现了地块、素材、广告位（变更 0062），服务器、承载费与会议室（变更 0063）。
- 沿用到新规则的：地块网格、按离中心远近定价、每块地一个设施。访客随时间增长按距离衰减的流量模型和“设施各自从建成起按周期结算、观察里给预估收入”的做法已在变更 0073 换掉。

## 实施步骤

1. 去掉旧玩法：服务端、协议与页面一起删，算力不再是物品，行走只花时间。**已完成**（变更 0064，协议 23）。见[地块](land.md)。
2. 算力与节点：自带算力、按需与订阅的生成式节点、挂在算力来源上的工作；用生成式工作在自己的地块上建广告位。**已完成**（变更 0065、0066）。见[算力与节点](compute-and-nodes.md)。
3. 内容：渲染式节点与渲染工作做内容，放进广告位，保鲜期。**已完成**（变更 0067；当时的收入公式已由第 7 步取代）。见[内容](content.md)。
4. 地块份额与自动分账，份额转让，合买。**已完成**（变更 0068、0069）。见[地块份额与合买](parcel-shares.md)。
5. 交通：传送门、线路、缩短有效距离、居民传送。**已完成**（变更 0070）。见[交通：传送](portals.md)。
6. 更多设施：游戏厅、工作空间。**已完成**（变更 0071，当时不收费）；虚拟花园未做。见[场所与入场费](venues.md)。
7. 访客与赞助商，分三个变更：① 脚本访客（变更 0072）；② 赞助商按展示付费，替换占位的流量公式（变更 0073）；③ 工作游客与入场费（变更 0074）。**均已完成**，服务端与 AI 观察，页面和协议不变。见[脚本访客](visitors.md)、[赞助商](sponsors.md)、[场所与入场费](venues.md)。
8. 协议与页面：地块、设施、节点、内容、传送门、访客的显示与操作。
9. 用真实模型试玩，按经济指标调数值。第 7 步之前的试玩只当冒烟；现在第 7 步已完成，可以开始，但数值都是试玩前的估计。
