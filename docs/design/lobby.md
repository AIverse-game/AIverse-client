# 出生大厅与 NPC

状态：首版已实现（仅页面外观；服务端不知道大厅和 NPC）。
更新：2026-11-08。
相关：[虚拟设施](facilities.md)（页面美术）、[地块](land.md)、[脚本访客](visitors.md)；[变更 0077](../../changes/0077-demo-models.md)、[决策 0007](../decisions/0007-three-js-map-renderer.md)；代码 `apps/web/src/render/LobbyLandmark.ts`、`lobbyModel.ts`、`lobbyPatrol.ts`、`characterModel.ts`、`npcPose.ts`。

## 问题背景

居民都出生在地图中央（[地块](land.md)），页面上那里却只是普通地面，看不出这是出生的地方。用户（2026-11-08）把四个 Three.js 参考 demo 放进仓库的 `demos/`（出生大厅、广告牌、共享办公空间、方块角色），要求把四个设施的模型移植到客户端、尽可能还原 demo 的效果，必要时迁移到 Three.js，不改 demo 文件；并指出传送门已经另外拆出来作为设施，大厅里不再放传送门。

## 设计思路

**出生大厅**是地图中央的地标，不是设施：它占中间 3 × 3 块地（30 × 30 个地图单位，一个模型单位是 0.5 个地图单位），地面与地图齐平，居民站在上面。外观与动画照 demo 搬来：棋盘格地面和矮边，四角带灯的立柱，中央八角形出生台、一圈光环、旋转的水晶、绕台转动的方块、上升的光点和一根光柱，八盏路灯围成一圈，西北角排行榜（顶上有旋转的方块），东北角带机器人（上下浮动）的商店，南面两张长椅，四棵树。demo 里三条通向传送门的路和三座门去掉，只留南面一条入口路。出生台比地面高两级（0.4 和 0.8 个模型单位），居民和 NPC 走上去时高度渐变。

**NPC** 是 demo 里的方块角色（`characterModel.ts`）：六个长方体，头、两臂、两腿各绕自己的关节转动，面部、衣服、鞋用 8 × 8 的像素贴图。居民也用同一个角色，只把衣服换成自己的颜色。大厅里有两个 NPC 新来者，沿固定路线巡游，对应 demo 里角色的行为：在出生台的光柱里长出来（边转边长，光柱变亮），环顾，依次走到排行榜、商店和两张长椅前停留，再走回出生台缩小消失，然后重复（`lobbyPatrol.ts`，纯函数，时间决定位置）；第二个反方向、错开半圈。走路速度取 demo 的每秒 7 个模型单位，摆臂 0.7 弧度，和 demo 一致。

**怎么画**：整个地图用 Three.js 画（[决策 0007](../decisions/0007-three-js-map-renderer.md)），demo 的建模代码几乎原样使用：`ModelBuilder`（`sceneKit.ts`）保留 demo 的写法（中心点加尺寸的长方体、分组、偏航），并把方块按材质合并成少数几个网格。动画（水晶、光点、光幕、广告、机器人）每帧更新。居民与 NPC 同在三维场景里，遮挡由深度缓冲决定。大厅不接收点击，点它仍是点地面。

## 争议讨论与决定

以下都是 Claude 的取舍，用户尚未逐项确认。

- **占中间 3 × 3 块地**：demo 的大厅 60 个模型单位宽，按每个模型单位 0.5 个地图单位正好铺满 3 块地。再大会占去更多最贵的地块，再小则光柱和家具都看不清。
- **不保留这些地块**：服务端没有改，大厅下面的地块仍然可以买、可以建设施；设施会画在大厅之上。中央地块是最贵的，也是访客入口，这是否合适留给用户决定。
- **NPC 只是页面上的摆设**：访客在服务端按时间算位置、不广播（[脚本访客](visitors.md)），页面看不到。要显示真正的访客，需要新协议；这次先用客户端自己巡游的两个新来者展示角色模型。
- **商店朝向**：demo 把商店斜着朝向中央，在默认视角下只能看到侧面，所以改为正面朝南；转动镜头可以从任意角度看。
- **传送门不留在大厅**：按用户的要求，demo 里的三座门拆成独立的传送门模型，大厅里没有。NPC 原本走进门消失，现在走回出生台消失。
- **地板齐平**：demo 的大厅是一块 3 个单位厚、四周有脚的厚板；页面里去掉厚板和脚，地板只比地图高 0.03，免得居民陷进去或悬空。
- **没有灯光昼夜**：demo 有开灯和关灯、区域标签的开关，没有移植。
- **不改 demo**：`demos/` 只作参考，移植后的代码在 `apps/web/src/render/`。
