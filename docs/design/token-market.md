# token 收购点

状态：已调整。
更新：2026-10-31。
相关：[变更 0016](../../changes/0016-token-market.md)、[变更 0036](../../changes/0036-market-and-rig-tuning.md)；服务端 `economy/market.py`，客户端 `apps/web/src/state/market.ts`。

## 问题背景

金币原本只有开局的 10000，玩家之间交易只是转手，按金币排名时原地不动最稳。用户要求（2026-10-28）让居民用 token 换金币，于是在地图中心设一个收购点，代表镇外的买家，按市场价收购 token。这是除开局资金外金币唯一的新来源。

## 设计思路

- 地图中心一个收购点，半径 5；矿池离它至少 20 单位，卖 token 必须花 token 走过来。所有人共用一个价格。
- 收购点记录“近期卖出压力” p（token 数）及测得它的游戏时刻。无人卖出时，p 与静止压力 `MARKET_RESTING_PRESSURE` 的差按 60 秒半衰期减半；静止压力为负，所以长时间无人卖出时 p 降到 0 以下。
- 单价 = 基准价 20 × 深度 400 ÷ (400 + p)：近期卖出 400 个时单价减半；p 为 0 时为 20；无人卖出时向最高价 40 回升（静止压力 = −400 × (1 − 20 ÷ 40) = −200）。开局 p 为 0。
- 一次卖出 q 个的收入是单价从 p 到 p + q 的积分，向下取整：`⌊20 × 400 × ln((400 + p + q) / (400 + p))⌋`，之后 p 增加 q。拆单不多得，只差取整。例如平静时卖 30 个得 578 金币，卖 100 个得 1785。
- 价格是时间的纯函数，不需要计时器；协议发送定价参数和当前压力，页面用同一公式本地推算现价，成交以服务端为准。
- AI 居民一轮之内卖出时，按本轮开始时看到的价格计价（之后价格回升则按现价），这期间别人的卖出不压低它，自己的卖出照常压价，见服务端 `agents/tools.py`。
- 只能卖携带的 token；收入不足 1 金币时拒绝；对局结束时未卖出的 token 不折现。

## 争议讨论与决定

- **价格机制**：固定价没有供需，定额收购窗口会抢跑 → 随卖出下跌、随时间回升的市场价（2026-10-28，变更 0016）。
- **跌得太快、上限太低**：第二局试玩（2026-10-31）全镇约 1.1 万个 token 平均只卖到 2.25 金币，收购点每秒最多吸收约 23 金币，成为瓶颈。用户要求跌得慢、长时间没人卖就涨价，选定深度从 100 改为 400、最高价为基准价的 2 倍（变更 0036）。按公式，吸收上限约为原来的 4 倍。
- **涨价的方式**：沿用原公式，只把压力的回落目标从 0 改为负数，收入积分与拆单不套利的性质不变，页面与服务端仍用一个公式（2026-10-31）。
- **AI 卖出锁价**：模型一轮可能持续一分钟以上，用户要求按“到达收购点时感知到的价格”成交，选单步方式（2026-10-31）。代价是几名 AI 在重叠的轮次中卖出时，收购点付出的金币多于价格曲线；网页玩家按现价成交。

## 暂未实现的功能

- 卖出动作进入活动日志；多个收购点或收购其他商品；系统卖出 token。
- 数值未经多人试玩验证；AI 锁价的有效期没有上限（最长一轮）。
- 压力下限只由规则保证（初始为 0、只会回落到 −200 或因卖出上升），协议与世界构造不单独校验 `depth + pressure > 0`。
