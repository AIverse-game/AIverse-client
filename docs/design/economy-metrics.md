# 经济指标

状态：设计中。
更新：2026-11-03。
相关：[芯片与芯片制造](chips.md)、[挂单交易所](order-book.md)、[按角色的当前对局日志](../../changes/0033-per-resident-logs.md)；计划放在服务端 `core/ledger.py` 与 `game/` 的对局结束流程。

## 问题背景

用户（2026-11-03）希望游戏往社会与市场模拟发展。目前判断一局“好不好”只能看金币排名和逐轮日志，回答不了这些问题：居民之间到底交易了多少？钱主要来自系统还是来自别的居民？有没有出现分工？每次改规则后，也没法比较社会和市场有没有变得更活跃。

2026-11-01 的对局日志只能看出结论：四人共发 6 次报价、1 份合约，金币几乎都来自收购点。要准确知道居民之间的金币流量，需要在每次金币变动时记下渠道。

## 设计思路

### 记账

- 世界中新增一本流水账：每次金币变动记一条（游戏时间、付款方、收款方、金额、渠道）。付款方或收款方可以是 `system`。
- 渠道：`market`（收购点卖 token）、`import`（系统卖芯片）、`rig_build`、`electricity`、`rent`（矿机租金）、`offer`（报价成交）、`contract`（合约付款与押金赔付）、`information`、`exchange`（交易所成交）。预留和退回不记，只记真实转手。
- 在各结算点记账：`economy/` 里的每处金币转移都带上渠道。流水账只追加，上限 20000 条，满了丢掉最早的，并在汇总里标明不完整。

### 指标

对局结束时算出以下指标，运行中也可以随时计算：

| 指标 | 含义 | 目标方向 |
| --- | --- | --- |
| 居民间流量占比 | 居民之间转手的金币 ÷（居民之间 + 系统付给居民）的金币 | 越高越好，这是最核心的指标 |
| 各渠道成交额与笔数 | 按上面的渠道分别统计 | 居民之间的渠道增多、增大 |
| 各商品成交价与波动 | 交易所、报价中每种物品的单价走势与标准差 | 有成交、价格可被发现 |
| 合约 | 签订数、按时交付比例、押金赔付次数 | 有人签、多数履约 |
| 金币基尼系数 | 最终金币分布的不平等程度 | 观察用，不设目标 |
| 收入集中度 | 每人收入来源的赫芬达尔指数，越高表示越专于一门营生 | 平均越高，说明分工越明显 |

### 输出

- 对局结束时写 `logs/summary.json`，并在控制台打印一张摘要表。
- 页面赛后复盘先不做，等指标稳定后再加。

### 用法

- **先测基线**：在硅矿、芯片厂、交易所上线前，用现有规则跑一局真实模型对局和若干局脚本机器人快进模拟，记下各项指标作为基线。
- 之后每次改经济规则或数值，都对比这些指标，不只看谁赢。

## 争议讨论与决定

以下为提议（Claude，2026-11-03），**待用户确认**：

- **事后从日志算还是在世界里记账**：每名居民的 JSONL 只有每轮前后的余额，分不出钱从谁来、经过什么渠道；矿机租金、合约付款也是在游戏时钟里发生的，不在轮内。提议在世界里记账。
- **先做指标还是先做玩法**：先做玩法能更早玩到，但改动前后就没法比较。提议先做指标，用现有规则测出基线。
