# 挂单交易所

状态：设计中。
更新：2026-11-03。
相关：[交易报价](trade-offers.md)、[能量收购点](energy-market.md)、[晶核与晶核制造](crystals.md)、[经济指标](economy-metrics.md)；计划放在服务端 `economy/exchange.py`。

## 问题背景

现在居民之间只能用一对一的买卖报价交易（[交易报价](trade-offers.md)）：先要找到对象，按整批总价开价，再等对方答复。2026-11-01 的真实模型对局里，四名居民一共只发了 6 次报价。模型很少主动去找交易对象，但会对着一个公开价格做决策，例如它们常常围绕收购点的现价来规划。

晶核改成由居民制造后（[晶核与晶核制造](crystals.md)），硅、各级晶核和能量都需要一个居民之间的公开市场：能看到别人愿意出多少钱，价格由买卖双方自己形成，而不是由系统公式给出。

## 设计思路

### 范围与地点

- 收购点同时是交易所，范围相同（半径 5）。可交易商品首版限定为 `energy`、`silicon`、`C1`、`C2`、`C3`，每种商品一本挂单簿。
- **下单必须站在交易所范围内**，和收购点卖能量、买晶核一致，让地点与行走仍然有意义。**撤单和成交在任何地方都可以**：成交的金币或物品直接进入物品栏。

### 订单

- 原语 `PlaceOrder`（工具 `place_order`）：方向（买或卖）、商品、数量（1～10000）、**单价**（整数，至少 1 金币）、有效期（30～600 秒，默认 300，最晚到对局结束）。挂单簿需要逐单位比较价格，所以用单价，不用报价那样的整批总价。
- 下单时预留：买单预留“数量 × 单价”的金币，卖单预留物品。预留的金币计入排名，和报价一致。
- 每名居民最多 8 张未成交订单。下单、撤单不耗能量。
- 不能与自己的挂单成交：新订单与自己反方向的挂单价格交叉时以 `self_cross` 拒绝。
- 原语 `CancelOrder`（工具 `cancel_order`）撤掉自己的一张订单，退回剩余预留。行走、汲取、制造中也能撤。

### 撮合

- 连续撮合：新订单先与对面价格最优的挂单成交，同价按先挂先成交；成交价为挂单方的价格，买方多预留的差价退回。可以部分成交，剩余部分挂在簿上。
- 选连续撮合而不是定时集中撮合，是因为下单结果能在同一个工具调用里返回给模型，模型当轮就知道成交了多少、还剩多少。
- 到期、出局（先撤单退回预留，再按出局清空）、对局结束（全部撤单）时退回预留。

### 公开信息

- **匿名**：挂单簿只公开价位和每个价位的总量，成交记录只有时间、商品、数量和价格，不显示双方是谁。想建立具名关系的居民仍可以用报价和合约。
- 感知（在任何地方都能看到，和收购点现价一样）：每种商品买卖各前 3 个价位、最近成交价、最近 120 秒成交量；自己的未成交订单；自上次查看以来自己的成交。
- 自己的订单成交（含部分成交）时唤醒空闲的居民，受现有“两轮至少相隔 3 秒”约束。
- 成交记入活动日志（匿名），每种商品记成交价历史，供页面画走势。

### 与收购点的关系

- 收购点仍按原公式收购能量，和交易所互不相干。居民可以在两者之间套利，例如收购点价格被压低时在交易所挂高价卖单。
- 系统不在交易所挂单。

### 页面

- 首版页面只读：按商品显示前几个价位和最近成交、价格走势、所选居民的订单（按 `view_as` 只发给对应页面）。
- 之后补上页面下单和撤单，让手动玩家与 AI 能做的事一致。

## 争议讨论与决定

以下由 Claude 提议，用户于 2026-11-03 全部确认：

- **要不要交易所**：只靠一对一报价时模型很少交易，也没有公开的价格。提议新增交易所，报价和合约照常保留，用于具名、非标准的交易。
- **在哪下单**：任何地方都能下单 → 地图位置不再重要；必须在交易所 → 多走路，但和现有的收购点一致。提议下单要到场，撤单和成交不用到场。
- **连续撮合还是定时集中撮合**：集中撮合（例如每 15 秒一次、同一个出清价）能减少响应快的模型占的便宜，但模型要等下一轮才知道结果。提议首版用连续撮合，观察快模型是否明显抢单再决定。
- **匿名还是具名**：具名有利于建立社会关系，但挂单簿会和信用、私聊纠缠在一起。提议交易所匿名，具名关系走报价和合约，之后做信用系统时再考虑。
- **系统是否挂单**：让收购点变成交易所里的一张常驻买单，可以统一两套价格，但会改动已经调好的收购点公式。首版不做。
