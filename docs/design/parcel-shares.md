# 地块份额与合买

更新：2026-11-07。

## 问题背景

用户（2026-11-07）的规则：收入大头归空间的占有者，可协商分红或合伙，以至形成“公司”。基础设施的建造者想要分红，就向地主要份额；几个人合伙就共同持有一块地。钱不够时，用户又提出买地也可以两个人凑钱合买（同日）。

## 设计思路

- **每块地分成 100 份**，买地时全部归买主，每个持有人至少 1 份。设施的收入（赞助商的付款和入场费）按份额比例自动分给持有人。凑不整的金币按小数部分大的先得，小数相同按持有人编号先后，所以各人所得之和总等于总收入；应得不足 1 个金币的人这一次没有。每人一条账（渠道 `sponsors`、`visitors`）。
- **份额转让是一种报价**（事件 `ShareOffer`，原语 `OfferShares`，工具 `offer_shares`）：持有人向另一名居民提出“把某块地的若干份给你，要多少金币”，对方同意并付款后生效。价格可以是 0，即白送，用份额抵工钱或请合伙人。发出时不预留，但已许诺的份额不能再许诺；同一人给同一名居民最多同时挂 3 份；对方付不起款时同意失败、报价留着；出局时报价撤销，已转出的份额不收回。
- **份额只管收入**：建设施和放内容仍只有买地的人能做，卖光份额的买地人仍然是唯一的经营者，合伙人只收钱。
- **合买**（事件 `JointPurchase`，原语 `OfferJointPurchase`，工具 `joint_buy_parcel`）：甲站在没人买的地块里，向乙提议“乙出 X 金币、拿 S 份，剩下的价款我出、其余份额归我”，X 从 0 到地价、S 从 1 到 99，两个数都由甲写明（用户 2026-11-07 决定由提议的人写明对方出多少钱、拿多少份；不按出资比例自动算，所以能表达“乙出得少，但地段是乙看中的”）。甲的那份发出时预留（计入排名）；乙同意并付款后，两人各付镇上一笔（渠道 `land`），地块成立，买地人是甲。对方不必在场，甲走动时不能提议；拒绝、撤回、出局、结束时预留的钱退回。
- **地块被别人先买走时**，乙同意失败，报价留着，甲撤回即可；观察里带 `parcel_taken`。同一块地可以同时有多份合买提议，谁先被同意谁成交；同一人给同一名居民最多同时挂 3 份，因为乙出全款时甲不预留任何金币，没有这条上限就能无限刷屏。
- **出局的持有人照样收款**，金币留在排名里。
- **AI 观察**：每块自己的地有持有人名单、上个付款日的收入和自己的那份；别人的地上自己持有份额的列在 `land.stakes`；收到和发出的份额报价、合买提议各有一栏。脚本机器人不转让份额、不合买。

## 争议讨论与决定

- **先做份额和自动分账，不做公司实体**（Claude 补充，用户同意）：自动分账是门槛最低的合作方式，不需要反复谈判，模型不擅长反复谈判。
- **100 份**（Claude）：足够分出 1% 的小股，又不至于让分账碎到没有意义。
- **价格可以是 0**（Claude）：与报价、合约至少 1 金币不同，份额常用来抵工钱。报价金额上限同交易的 10 亿；每块地的持有人数不限（至多 100 人）。代价是串通的玩家能借白送份额把收入归到一人名下，排名只算金币，首版不防，试玩时留意。
- **只有持有人能发份额报价，求购份额暂不做**：想入股的人用对话向持有人开价。
- **仍然只有买地人经营**（用户 2026-11-07 决定，合买时）：乙出了钱也没有决定权。是否改为“持股最多的人经营”留给以后；份额卖光的买地人没有了经营的动力，只能靠合约和对话约束。
- **只做两人合买**：三人及以上可以由买地人之后用份额报价分出去。
