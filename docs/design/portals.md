# 交通：传送

状态：首版已实现（服务端与 Agent 工具；页面和协议未接入）。
更新：2026-11-07。
相关：[虚拟设施](facilities.md)（总览）、[脚本访客](visitors.md)、[地块份额与合买](parcel-shares.md)；[变更 0070](../../changes/0070-portals.md)、[变更 0072](../../changes/0072-visitors.md)；服务端 `economy/portals.py`、`core/land.py`。

## 问题背景

用户（2026-11-07）提出：地块偏远时，辅以传送，流量更容易到达，自己的地块之间也更有联动。一局只有 20～40 分钟，走路要花时间。同一天用户又指出：流量要由模拟出的访客决定，不该预设访客会走传送门，所以线路对流量的影响要等访客做出来，由他们自己选。

## 设计思路

- **传送门**是设施的一种，由生成式工作建在自己的空地块上（`build_portal`，工作量 180，雇节点 540 金币，比广告位贵，因为它自己不收钱）。它占掉地块唯一的设施位，不能既是传送门又是广告位；每人至多 4 座（建好和在建的合计）。
- **线路**连两座门，要两端的主人同意：两座都是自己的立即连通，否则向另一座门的主人提议（事件 `LinkProposal`，沿用报价的发出、同意、拒绝、撤回），过路费由提议的人写明、定下后不改。同意时再检查一次条件，不满足则失败、提议留着；同一人给同一名居民最多同时挂 3 份。“主人”指买地的人，不是份额持有人。
- **线路的限制**：两座门的地块中心相距至少 30 单位（三块地，更近的线路省不了什么）；每座门至多连 3 条线路，免得一座中央的门把全图拉到中央；两座门之间至多一条线路；过路费 0～1000 金币。没有拆线路和拆门。
- **居民传送**（`Teleport`）：站在传送门所在地块里、没在走路，传到线路另一端的地块中心，不花时间。任何人都能用任何线路，不需要主人同意；一次只过一条线路，想走多段就连着传，每段各付一次；不带走别人，走路中不能传送。
- **过路费**：旅行者付给两端地块的持有人，一半归出发端、一半归到达端（奇数的一枚归出发端），各自按份额分给持有人；渠道 `toll`；旅行者自己是持有人时那一份不记账不动余额。这是居民之间的金币，不是镇外来钱。
- **线路和门留在地块上**：主人出局后仍在、仍可用、持有人照收过路费；但出局者不会再答复提议，所以他的门不能再被连新线路，观察里也不再列他的门。
- **有效距离** `effective_distance`：从某处到地图中央的距离取直线，和“走到一座门、过线路不花时间、再从同一线路网里离中央最近的门走”里较短的那个，线路可以连着走（甲乙、乙丙相连就是一张网）。任何地方都按最短路算，门旁边的地块也沾光。它只是算出来，没有人用。
- **访客用的路线** `Router`：同样的想法用于一次从甲到乙的走：直走，或走到某个线路网里离自己最近的门、一步出到离目标最近的门再走，取较短的；一次只走一个线路网。**访客走线路不付过路费**，走不走由他们的选择决定，所以线路才真正影响流量，见[脚本访客](visitors.md)。
- **AI**：`build_portal`、`link_portals`、`teleport` 三个工具属于 `discover_tools` 的 `transport` 组，`link_portals` 在有两座门（或一座加别人的一座）时、`teleport` 在站在有线路的门里时自动出现；观察里有 `transport`、`link_proposals_to_me`、`my_link_proposals`、`compute.portal`。脚本机器人不建门。

## 争议讨论与决定

- **“借流量”改成缩短“有效距离”**（Claude，随访客改成实体）：原来的 50% 借用比例作废；不再需要“只算一跳、不递归”的防放大规则。
- **线路先只管居民传送，不影响占位的流量**（用户 2026-11-07 决定）：现在占位的流量公式已删，访客自己选。
- **有效距离按最短路算，不只算“门所在地块”**（Claude）：门占掉地块唯一的设施位，广告位只能建在门旁边的地块上，所以旁边的地块也该沾光。
- **取舍**：中央的门最值钱，会有人抢，也可能垄断线路；这正好和地块份额连起来，想借中央流量的人得换份额或付线路费。数量和间距的限制防止全图连成一片。
- **访客走线路免费**（Claude，变更 0072）：过路费是居民之间的钱；访客的钱来自各自的钱包，只用于入场费。
