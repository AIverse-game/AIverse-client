# Agent 居民的机器人形象

状态：首版已实现（协议 28 的 `agent` 增加可选字段，版本号不变）。
更新：2026-11-08。
相关：[AI 居民](ai-residents.md)、[出生大厅与 NPC](lobby.md)；[变更 0085](../../changes/0085-agent-robot.md)；`demos/floating_ai_agent_movement.html`；页面 `render/agentRobot.ts`、`render/agentMood.ts`、`render/ResidentLayer.ts`；服务端 `game/cues.py`。

## 问题背景

居民无论由页面操作还是由 Agent 驱动，都画成同一个方块人，看不出谁是 Agent，也看不出 Agent 在做什么。用户（2026-11-08）要求只给 Agent 居民换成 `demos/floating_ai_agent_movement.html` 的悬浮机器人（普通游客和手动居民仍是方块人），机器人比方块人稍大，并有待机、思考、说话、开心四个状态。

## 设计思路

**形象。** `agentRobot.ts` 照 demo 移植：方盒身体与头、屏幕脸（像素画布，随状态换表情）、双手、推进环与光柱、天线；去掉 demo 里的点光源、尾迹粒子和鼠标注视。强调色用居民自己的颜色，所以同时有几个机器人时仍能分辨。大小是 `ROBOT_SCALE = 0.2`，约 2.8 个地图单位高（连悬浮高度），方块人约 2.1；名字标签和点选框随之抬高。居民有没有 `agent` 变了，就把方块人换成机器人（或反过来）。

**四个状态。**

| 状态 | 何时 | 表现 |
| --- | --- | --- |
| 待机 | 没有别的状态时 | 缓慢起伏、眨眼；走路时前倾、转弯侧倾、手后摆、推进环加速 |
| 思考 | Agent 在等大脑回答 | 一只手托在下巴处，头微歪，脸上三点循环，一圈方块绕头旋转，天线变色 |
| 说话 | 说话、发出报价与提议、拒绝别人 | 脸上声波，双手前伸挥动，核心随声音脉动 |
| 开心 | 报价或提议被同意（双方）、设施建成（主人） | 弯眼笑脸，双手上举，整体蹦跳摆动，金色方块绕头上升 |

优先级：开心 > 说话 > 思考 > 待机。

**服务端给信号。** 页面原先拿不到这些：别人的报价与回应只有当事人看得到，“等大脑”更是只在服务端。所以 `AgentView` 增加两个可选字段（旧页面忽略，不升协议版本）：`thinking: true`，`runner.py` 在大脑一轮前后设置；`cue: {kind, seq}`，由 `Game.act` 按原语生成（`game/cues.py`），设施建成则在到点结算时比较前后的地块。提示不属于世界，只记在 Agent 名下。

**页面按 `seq` 播放。** `agentMood.ts` 记着每个居民见过的 `seq`，见到新的就播固定时长（说话 2.6 秒、开心 2.4 秒）；页面刚打开时已有的提示不重播。思考至少显示 0.7 秒，免得脚本机器人几乎不等的一轮闪一下就没了。

## 争议讨论与决定

- **信号放在哪**（用户选定前后端都改）：另两个方案是只用现有数据推断（“思考”无从得知，别人的报价成交也看不到），或前端先做、服务端后补。选用服务端给信号，四个状态才都是真的。
- **提示用 `seq` 而不是一个“当前状态”**：说话和开心都很短，快照可能一次跨过；用递增的 `seq` 页面不会漏，也不会重播。
- **提示只来自 `Game.act`**：Agent 的所有原语走这条路；页面手动操作的居民不是 Agent，不需要。副作用是手动替 Agent 居民操作时不产生提示。
- **取舍（Claude 的，用户未逐项确认）**：拒绝别人算说话；买地、下单、做内容不算开心；成交算开心的只有报价、提议被同意和设施建成。

## 暂未实现的功能

- 交易所成交、买地成功、内容放入广告位等“成功”时刻不触发开心。
- 手动用页面操作 Agent 居民时不产生提示。
- 机器人没有尾迹粒子和 demo 里的鼠标注视，也没有点光源。
- 出局的 Agent 居民会变回方块人（出局后 `agent` 消失）。
- 没有在真实大模型对局里看过；开心状态只在代码上核对，没有截图。
