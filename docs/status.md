# 当前项目状态

更新：2026-10-31。阶段：权威逻辑改由 Python 服务端负责，已实现正方形坐标地图的生成与渲染、移动与退出游戏的原语、居民之间的买卖报价（服务端内部）、定时结束的一局与金币排名、token 体力、按速度行走与矿池采矿，以及每轮开始时的感知与发现、由 Agent 自选的长短期记忆（服务端内部）、按市场价收购 token 的收购点、采矿必须用的芯片、安装芯片后自动生产的矿机及租金结算，以及居民之间的对话和由服务端执行的交付合约（服务端内部）；居民已可由服务端里的 Agent（脚本机器人，或玩家在页面上配置的任意 OpenAI 兼容模型接口）驱动；生产等其余玩法规则尚未在新服务端中实现。

## 已具备

- 收购价与矿机数值调整（[变更 0036](../changes/0036-market-and-rig-tuning.md)）：近期卖出 400 个 token 单价才减半，长时间无人卖出时单价涨过 20、最高 40；矿机内芯片每 20 秒产出单次产量的 2 倍，租金降为每 100 token 50 金币；Agent 建机后得知新矿机编号。协议 16。数值待试玩验证。

- 矿机贴图（[变更 0035](../changes/0035-mining-rig-sprite.md)）：地图使用用户提供的蓝色双风扇透明 PNG，保留四个插槽状态灯，按透视缩放、机身透明度检测点击。地面仍为原有草地。

- 矿机与芯片租用（[设计](design/mining-rigs.md)，[变更 0034](../changes/0034-mining-rigs.md)）：8000 金币建 4 槽矿机（[变更 0037](../changes/0037-lock-hold-and-rig-price.md)，原为 4000），每 20 秒自动采矿；租客预存租金、电费，按实际产量同步支付，余额不足暂停，支持远程充值和拆回退款。角色出局立即清除其槽位，矿主出局关闭整机并退款；对局结束停产退款，预存计入排名。页面及 Agent 均可操作；协议 15。矿池储量扩至 1500～4000，价格与回本周期待试玩验证。

- [AIverse 总体设计 v0.1](design/game-overview.md)：以玩家自带模型 API 驱动居民，进行生产和交易，最终按金币排名。规则和数值尚待原型验证；地图部分已按决策 0002 调整。
- Python 服务端（与本仓库同级的 `aiverse-server` 目录，[决策 0002](decisions/0002-python-server-and-coordinate-map.md)）：FastAPI WebSocket `/ws`，生成固定布局的 100 × 100 连续坐标地图和 4 名居民，校验坐标与客户端消息。
- 网页客户端（[变更 0005](../changes/0005-coordinate-map.md)）：经 WebSocket 读取地图并校验，Phaser 绘制地图、刻度、居民及指针坐标，侧栏列出地图边长和居民坐标；服务端不可达时显示错误。见 [应用架构](architecture.md)。
- 2.5D 地图（[变更 0006](../changes/0006-perspective-map.md)）：参考《饥荒》的固定透视视角，地块转 45° 并露出土层，居民是带影子的站立小人，按远近缩放和遮挡。
- 操作原语（[变更 0007](../changes/0007-action-primitives.md)）：服务端 `actions.py` 是玩家与 AI 改变世界的唯一入口，首个原语是 `move_to`（即时到达，校验居民存在和目标在地图内）。页面可手动操作：点选居民后填写坐标或点击地面；所有页面共享同一个世界并同步看到变化。
- 居民物品（[变更 0008](../changes/0008-resident-inventory.md)）：每名居民有一个物品栏（物品种类 → 数量），容量无限，只存在于内存中的世界，新开一局即为空。服务端 `inventory.py` 提供存入、移出（不足时整体拒绝）、计数、列出和清空（出局时用）的内部接口，尚未开放为原语，也不在协议中。
- 事件系统框架（[变更 0009](../changes/0009-event-queue.md)）：居民之间的请求（如购买）作为事件进入世界中的队列，等待收件人同意或拒绝，或由发件人撤回。服务端 `events.py` 提供发送、答复、查询收件箱的接口；每种事件是 `EventPayload` 的一个子类，用发送、同意、拒绝三个钩子定义规则。答复原语 `RespondToEvent`、`WithdrawEvent` 已加入 `actions.py`，但尚无具体事件种类，也未进入协议。
- 购买与出售（[变更 0010](../changes/0010-trade-offers.md)）：第一批具体事件。服务端 `trade.py` 定义 `PurchaseOffer` 与 `SaleOffer`，原语 `OfferToBuy`、`OfferToSell` 已加入 `actions.py`：买卖双方任一方都可以先发起，发起方的金币或物品立即预留，对方同意后互换，拒绝或撤回后退回。价格是整批总价，至少 1 金币。尚未进入协议。
- 金币、出局与对局结束（[变更 0011](../changes/0011-coins-leaving-and-game-end.md)）：金币是居民的独立余额，开局每人 10000。服务端 `lifecycle.py` 管理一局的生命周期：居民可用原语 `LeaveGame`（协议中为 `leave_game`）出局，与其有关的报价撤销并退回预留，物品清零、金币保留，之后不能再行动或交易，游戏照常进行；一局从服务端启动起计时，默认 20 分钟（`--duration` 可改），到点撤销所有报价并冻结世界。排名按金币总额（含报价中预留的金币），相同并列。页面显示倒计时、金币排名（结束后为最终排名）、出局标记，可点“退出游戏”。协议版本为 4。
- token 体力与矿池（[变更 0012](../changes/0012-tokens-and-mining.md)）：token 是物品种类 `"token"`，开局每人 200，可用现有买卖原语交易。走路按直线距离每单位 1 token（向上取整），不够则拒绝；token 由正变零（携带加出售报价中预留的）的居民按出局处理。开局时按种子随机放置 6 个矿池（`--seed` 可复现），整局不动，储量有限；站在矿池半径内可用原语 `Mine`（协议中为 `mine`）采矿，10 秒后得 30 token，期间只能退出游戏。服务端 `World.time` 由 `Game.tick` 推进并自动发放到期的采矿。页面显示 token、矿池与采矿状态，可点“采矿”。协议版本为 5。
- 感知与发现（[变更 0013](../changes/0013-perception.md)）：服务端 `perception.py` 的 `begin_turn` 供 AI 在每轮开始时调用，居民注意到周围 20 单位内的矿池、其他居民，以及自上次查看以来别人在附近的移动、开始或完成采矿、出局；见过的矿池记在居民记忆里，走远后仍记得位置和当时的储量。附近的动态来自世界中的活动日志（最近 500 条），由 `perform` 和对局时钟自动记录。尚无调用方，不在协议中。
- 行走速度（[变更 0014](../changes/0014-walking-speed.md)）：`move_to` 不再即时到达，居民按每秒 2.5 地图单位沿直线走过去（服务端 `walking.py`），出发时扣 token，到达前忙碌（只能退出游戏），途中位置对感知和页面可见；花光 token 的行走者到达后出局，中途出局或游戏结束时停在原地。`Game.begin_turn` 供 AI 每轮开始时调用，先推进游戏时间再感知并存回世界。页面按服务端给的目标和剩余时间播放行走，列表标“行走中”。协议版本为 6。
- token 收购点与市场价（[变更 0016](../changes/0016-token-market.md)）：地图中心有一个收购点，代表镇外买家，是除开局资金外金币唯一的新来源。服务端 `market.py`：居民站在收购点半径 5 内，用原语 `SellTokens`（协议中为 `sell_tokens`）卖出携带的 token 换金币；单价随近期卖出量下跌（卖出 100 个时减半）、按 60 秒半衰期回升到 20 金币，一次卖出的收入是单价的积分，拆单不占便宜；卖光拥有的 token 照常出局。矿池离收购点至少 20 单位。感知附带收购点与现价。页面画出收购点，侧栏显示随时间回升的现价，在范围内可输入数量卖出并看到估算收入，卖光前确认。协议版本为 7。
- 芯片（[变更 0017](../changes/0017-mining-chips.md)）：采矿必须携带芯片，开局谁都没有，要在收购点用金币按定价买（服务端 `chips.py`，原语 `BuyChip`，协议中为 `buy_chip`）：MK1 300 金币、每次采 30 token，MK2 1200 金币、60 token，MK3 3000 金币、100 token；有几块时自动用最好的一块。采矿期间居民守着芯片，不能走开或卖掉；芯片是以型号命名的物品，可用报价转手，出局时清空。感知附带芯片价目。页面显示价目、购买按钮、每人持有芯片的贴图与所用芯片，没有芯片时提示先买。协议版本为 8。
- 长期与短期记忆（[变更 0015](../changes/0015-memory.md)）：服务端 `memory.py` 的 `remember` 让驱动居民的 Agent 自己决定记下什么文字、记成长期还是短期，`forget` 忘掉任意一条。长期笔记整局保留，短期笔记写入 120 秒游戏时间后清除；每条最多 300 字符，长期最多 30 条、短期最多 20 条，满了要先忘掉一条。`Game.begin_turn` 的感知结果附带当前的全部笔记。不是原语：不耗 token，行走和采矿中也能写，不广播。尚无调用方，不在协议中。
- 对话（[变更 0018](../changes/0018-speech.md)）：服务端 `speech.py`，原语 `Say`（协议中为 `say`）。不指定对象时当众说，说话那一刻 20 单位内仍在局中的其他居民听到；指定一名居民时是私聊，不论远近只有对方听到。每句 1～100 字符，当众说 2 token、私聊 1 token（[变更 0019](../changes/0019-speech-cost-and-privacy.md)），行走、采矿中也能说；谁听到在说话时定下。`Game.begin_turn` 的感知附带自上次查看以来自己说的和听到的话，世界保留最近 200 句。页面“对话”面板列出最近 50 句当众说的话和选中居民自己的私聊：页面选中居民时以 `view_as` 告诉服务端，服务端只把该居民发出或收到的私聊发给这个页面。选中居民后可当众说或私聊。协议版本为 10。
- AI 居民（[设计文档](design/ai-residents.md)，[变更 0020](../changes/0020-agent-loop.md)，[决策 0003](decisions/0003-event-driven-agents-and-openrouter.md)）：服务端 `agents/` 子包。启动时用 `--agent r1=scripted` 或 `--agent r2=llm[:模型]` 指定居民由 Agent 驱动，每名居民一个事件驱动的循环：感知 → 大脑经绑定该居民的工具执行原语、记笔记 → 等到行走或采矿结束、收到报价、听到别人说话或空闲 20 秒再醒，两轮至少相隔 3 秒。Agent 与网页的操作经同一个入口 `Game.act`/`Game.commit` 执行并广播。脚本机器人按固定策略买芯片、采矿、卖 token；大模型大脑每局每名居民最多 400 次请求（停止或更换 Agent 不重置），接入方式见下一条。大脑或记录出错只记日志，不影响游戏。每轮记录打印到控制台，`--agent-log` 写成 JSONL。协议不变。
- 页面配置大模型（[变更 0022](../changes/0022-llm-config-from-page.md)，[决策 0004](decisions/0004-player-configured-llm-endpoints.md)）：不内置任何厂商，接口须兼容 OpenAI 的 Chat Completions 并支持工具调用。页面“AI 驱动”面板选中居民，填写 API 地址、key 和模型后“交给 AI”，可随时按新配置替换或“停止 AI，改为手动”；所有页面的居民列表标出“AI”。设置按居民记在本机 localStorage。服务端 YAML 配置文件（`--config`，默认读 `agents/config/llm.yml`）的 `override` 可以全局覆盖地址、key、模型，页面上对应的输入框置灰；`--agent r2=llm[:模型]` 的地址和 key 来自配置文件。key 不进状态、日志与记录。协议版本为 11。
- 合约（[设计文档](design/contracts.md)，[变更 0025](../changes/0025-delivery-contracts.md)）：居民可以约定未来的交付与付款。供货方每交付一批物品，买方就付约定的金币，可以是一次或多次（最多 100 次），签订后到期（最长 3600 秒）。任一方提议，对方同意后生效；签订时买方的全部货款托管在合约里，每次交付自动付款，买方不能拒付。只有供货方能取消；到期、出局、游戏结束时合约终止，余款退回买方。托管金币计入排名。供货方可以为每次交付押押金（[变更 0027](../changes/0027-supplier-deposits.md)，数额自由填写，默认 0）：交付一次退一次；到期、取消或供货方出局时没交付的押金赔给买方，买方出局或游戏结束时退回。合约不是因自己的行动而结束时唤醒空闲的一方，观察里有最近结束的合约。服务端原语为 `ProposeContract`、`Deliver`、`CancelContract`，Agent 工具为 `propose_contract`、`deliver`、`cancel_contract`。页面只读显示，见下一条。
- 页面显示报价与合约（[变更 0026](../changes/0026-deals-on-page.md)，[交易报价设计](design/trade-offers.md)）：“交易与合约”面板列出所选居民的生效合约（角色、条款、还要交付的次数、托管的货款和押金、到期倒计时），以及收到和发出的报价与合约提议。和私聊一样，状态只带所选居民参与的部分。页面还不能发起或答复。协议版本为 13（变更 0027 加入押金）。
- 服务端代码结构（[变更 0021](../changes/0021-server-subpackages.md)）：`aiverse_server` 按领域分为 `core/`、`economy/`、`residents/`、`game/`、`server/`、`agents/` 子包，`tests/` 同样分组，见 [代码地图](code-map.md)。只移动文件，行为不变。
- 服务端测试分层（[变更 0031](../changes/0031-server-test-layers.md)）：测试分在 `tests/unit/` 与 `tests/integration/` 两个目录，`uv run pytest tests/unit` 只跑单元测试（约 1 秒）。现有测试已按服务端测试约定改为准备、执行、断言三段，约定补充了“什么算执行”等几条澄清。
- 只做检查的 CI 工作流（仓库检查与 `npm run verify`）。
- Codex 与 Claude Code 共用开发规则、开发与审查 Skill、变更与决策模板。规则与 Skill 在 `.agents/rules/`、`.agents/skills/`；服务端仓库有自己的一套，只描述服务端（[决策 0006](decisions/0006-independent-agent-rules-per-repo.md)，[变更 0030](../changes/0030-independent-agent-rules.md)）。状态、设计、变更说明与决策记录只在本仓库。功能设计按 [设计文档规则](design/README.md)：新功能新建设计文档，调整已有功能时修改原文档；目前 AI 居民、交易报价与合约有独立的设计文档。文件命名与放置按 [文件命名与目录约定](../.agents/rules/conventions.md)（[变更 0023](../changes/0023-naming-conventions.md)，看不出内容的模块名已在 [变更 0024](../changes/0024-descriptive-module-names.md) 改名），尚无自动检查。测试的分层与写法按 [测试约定](../.agents/rules/testing.md)（[变更 0028](../changes/0028-testing-conventions.md)）；端到端仍靠浏览器人工实测。
- 两个独立的 Git 仓库，分支均为 `main`，远程在 GitHub 的 AIverse-game 组织下（`AIverse-client`、`AIverse-server`）。

## 当前可用命令

```sh
# aiverse-server 目录
uv sync
uv run aiverse-server           # 启动服务端，127.0.0.1:8000；一局 20 分钟，--duration 秒数可改，--seed 固定矿池布局
uv run aiverse-server --agent r1=scripted --agent r2=llm:模型名   # 由 Agent 驱动居民；llm 的地址和 key 来自 agents/config/llm.yml（见服务端 README）
make verify                     # ruff、mypy、pytest

# 本仓库
npm install
npm run dev                     # 网页开发服务器，/ws 代理到服务端
npm run verify                  # 类型检查、ESLint（含分层规则）、Vitest、生产构建
python3 scripts/check_repo.py   # 仓库骨架检查
make verify                     # 仓库检查加 npm run verify
```

## 尚未实现或未验证

- 每回合移动距离、中途改道或停下、回合制、地点、物品种类定义与物品的客户端展示、生产、集市委托与撮合、商品的系统收购（token 收购点已有，见变更 0016），以及采集、制作等其余原语：五区域版本的 TypeScript 实现已删除，需要在 Python 服务端重新实现。旧代码见提交 `11d852a`。
- 房间与开局流程：一局从服务端启动开始，重启服务端才能开新局；断线等情况尚不会让居民出局（`leave_game` 已可供系统调用）。设计稿中的面包未实现；体力改为 token，见变更 0012。
- 事件过期（需要回合时钟）、页面发起和答复报价与合约、交付与取消合约：框架、交易与合约已就绪，页面已能只读显示，见变更 0009、0010、0025、0026。
- 交易与合约交付是否要求双方在同一地点或一定距离内尚未决定。
- 合约：页面只能看，不能操作，也不显示已结束的合约；没有违约记录或信用，买方不能取消，也没有双方协商解除；收到非最后一次交付时不唤醒买方；上限与时长未经试玩调参，模型是否会主动使用合约、是否会要求押金尚未观察。
