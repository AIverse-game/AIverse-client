# 当前项目状态

更新：2026-10-27。阶段：权威逻辑改由 Python 服务端负责，已实现正方形坐标地图的生成与渲染、移动与退出游戏的原语、居民之间的买卖报价（服务端内部），以及定时结束的一局与金币排名；生产等其余玩法规则尚未在新服务端中实现。

## 已具备

- [AIverse 总体设计 v0.1](design/game-overview.md)：以玩家自带模型 API 驱动居民，进行生产和交易，最终按金币排名。规则和数值尚待原型验证；地图部分已按决策 0002 调整。
- Python 服务端（与本仓库同级的 `aiverse-server` 目录，[决策 0002](decisions/0002-python-server-and-coordinate-map.md)）：FastAPI WebSocket `/ws`，生成固定布局的 100 × 100 连续坐标地图和 4 名居民，校验坐标与客户端消息。
- 网页客户端（[变更 0005](../changes/0005-coordinate-map.md)）：经 WebSocket 读取地图并校验，Phaser 绘制地图、刻度、居民及指针坐标，侧栏列出地图边长和居民坐标；服务端不可达时显示错误。见 [应用架构](architecture.md)。
- 2.5D 地图（[变更 0006](../changes/0006-perspective-map.md)）：参考《饥荒》的固定透视视角，地块转 45° 并露出土层，居民是带影子的站立小人，按远近缩放和遮挡。
- 操作原语（[变更 0007](../changes/0007-action-primitives.md)）：服务端 `actions.py` 是玩家与 AI 改变世界的唯一入口，首个原语是 `move_to`（即时到达，校验居民存在和目标在地图内）。页面可手动操作：点选居民后填写坐标或点击地面；所有页面共享同一个世界并同步看到变化。
- 居民物品（[变更 0008](../changes/0008-resident-inventory.md)）：每名居民有一个物品栏（物品种类 → 数量），容量无限，只存在于内存中的世界，新开一局即为空。服务端 `inventory.py` 提供存入、移出（不足时整体拒绝）、计数、列出和清空（出局时用）的内部接口，尚未开放为原语，也不在协议中。
- 事件系统框架（[变更 0009](../changes/0009-event-queue.md)）：居民之间的请求（如购买）作为事件进入世界中的队列，等待收件人同意或拒绝，或由发件人撤回。服务端 `events.py` 提供发送、答复、查询收件箱的接口；每种事件是 `EventPayload` 的一个子类，用发送、同意、拒绝三个钩子定义规则。答复原语 `RespondToEvent`、`WithdrawEvent` 已加入 `actions.py`，但尚无具体事件种类，也未进入协议。
- 购买与出售（[变更 0010](../changes/0010-trade-offers.md)）：第一批具体事件。服务端 `trade.py` 定义 `PurchaseOffer` 与 `SaleOffer`，原语 `OfferToBuy`、`OfferToSell` 已加入 `actions.py`：买卖双方任一方都可以先发起，发起方的金币或物品立即预留，对方同意后互换，拒绝或撤回后退回。价格是整批总价，至少 1 金币。尚未进入协议。
- 金币、出局与对局结束（[变更 0011](../changes/0011-coins-leaving-and-game-end.md)）：金币是居民的独立余额，开局每人 10000。服务端 `lifecycle.py` 管理一局的生命周期：居民可用原语 `LeaveGame`（协议中为 `leave_game`）出局，与其有关的报价撤销并退回预留，物品清零、金币保留，之后不能再行动或交易，游戏照常进行；一局从服务端启动起计时，默认 20 分钟（`--duration` 可改），到点撤销所有报价并冻结世界。排名按金币总额（含报价中预留的金币），相同并列。页面显示倒计时、金币排名（结束后为最终排名）、出局标记，可点“退出游戏”。协议版本为 4。
- 只做检查的 CI 工作流（仓库检查与 `npm run verify`）。
- Codex 与 Claude Code 共用开发规则、开发与审查 Skill、变更与决策模板。
- 本地 Git 仓库，分支为 `main`，未配置远程仓库；`aiverse-server` 是独立的 Git 仓库，同样只在本地。

## 当前可用命令

```sh
# aiverse-server 目录
uv sync
uv run aiverse-server           # 启动服务端，127.0.0.1:8000；一局 20 分钟，--duration 秒数可改
make verify                     # ruff、mypy、pytest

# 本仓库
npm install
npm run dev                     # 网页开发服务器，/ws 代理到服务端
npm run verify                  # 类型检查、ESLint（含分层规则）、Vitest、生产构建
python3 scripts/check_repo.py   # 仓库骨架检查
make verify                     # 仓库检查加 npm run verify
```

验证证据见 [变更 0005](../changes/0005-coordinate-map.md)、[变更 0006](../changes/0006-perspective-map.md)、[变更 0007](../changes/0007-action-primitives.md)、[变更 0008](../changes/0008-resident-inventory.md)、[变更 0009](../changes/0009-event-queue.md)、[变更 0010](../changes/0010-trade-offers.md) 与 [变更 0011](../changes/0011-coins-leaving-and-game-end.md)。

## 尚未实现或未验证

- 移动速度与每回合距离（`move_to` 目前即时到达）、回合制、地点、物品种类定义与物品的客户端展示、生产、集市委托与撮合、系统收购、公开消息，以及采集、制作等其余原语：五区域版本的 TypeScript 实现已删除，需要在 Python 服务端重新实现。旧代码见提交 `11d852a`。
- 房间与开局流程：一局从服务端启动开始，重启服务端才能开新局；断线等情况尚不会让居民出局（`leave_game` 已可供系统调用）。设计稿中的其余初始条件（面包、体力）未实现。
- 交易以外的事件种类、事件过期（需要回合时钟）、事件与交易原语在协议与客户端中的展示和答复：框架与交易已就绪，见变更 0009、0010。
- 交易是否要求双方在同一地点或一定距离内尚未决定。
- 操作权限：任何连接都能操作任何居民，尚无“玩家拥有哪名居民”的概念。
- 房间、准备流程、身份认证、Origin 检查、消息大小限制、断线重连、真实大模型接入、事件记录与复盘、正式美术（当前地面和居民都是程序绘制）、镜头旋转与缩放。
- 尚无自动的跨语言协议契约测试，靠客户端运行时校验和端到端实测发现不一致。
- 浏览器实测覆盖 1400 px、520 px 与 390 px 宽度（390 px 只截图检查排版）；触屏、鼠标悬停显示指针坐标、`vite preview` 代理未实测。
- CI 工作流尚未在 GitHub 上实际运行；服务端检查不在本仓库 CI 内。

## 待决定的设计问题

- **移动规则**：每回合可移动的最大距离、是否按直线移动、是否有障碍物，以及 AI 指定目标的方式（坐标还是地点）。
- **地点与经济的关系**：五个功能区域已取消，采集、制作、休息、交易在哪里进行需要重新设计，再决定地点如何放在地图上。
- **他人信息的可见粒度**与**开局权限**：沿用上一版的待定问题，接入回合和房间时需要决定。
