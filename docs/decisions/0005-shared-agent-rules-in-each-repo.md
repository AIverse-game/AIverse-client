# 0005：两个仓库各存一份 Agent 规则

状态：采用。
日期：2026-10-31。

## 背景

开发规则、命名与测试约定、开发与审查 Skill 原先只在客户端仓库，服务端 `AGENTS.md` 第一句就要求读 `../aiverse-client/AGENTS.md`。两个仓库在 GitHub 上分开托管，只 clone 服务端的开发者拿不到这些规则。另外，这些规则和架构、设计、状态一起放在 `docs/`，没有区分“Agent 怎么工作”和“项目是什么”。

## 候选方案

- **合并为一个仓库**：规则、状态、变更说明与决策只存一份，协议改动一次提交。代价是重建 GitHub 仓库、调整 CI 和全部路径。
- **两个仓库各存一份（采用）**：每个仓库都能独立使用。代价是两份可能漂移，改规则要在两边各提交一次。
- **规则单独成仓库，以 submodule 引入**：只有一份，但每次改规则要提交三个仓库，submodule 对新人不友好。

## 决定与依据

- 用户选择保留两个仓库，各存一份规则。
- 规则放进 `.agents/rules/`（`development.md`、`conventions.md`、`testing.md`），与 `.agents/skills/` 并列；`docs/` 只放项目本身的知识：架构、设计、决策、状态与代码地图。
- 两个仓库的 `.agents/rules/` 与 `.agents/skills/` 逐字相同。共用文件只链接彼此和根目录 `AGENTS.md`，提到某个仓库独有的文件时写明仓库并用行内代码写路径，因此放在哪个仓库都没有失效链接。只适用于一个仓库的约定写在该仓库的 `AGENTS.md`。
- 两个仓库位于同级目录时，客户端的 `scripts/check_repo.py` 逐字比较这些文件，缺失、多出或内容不同都报错。

## 影响

- 修改共用规则要在两个仓库各提交一次；只在一个仓库的会话里也要同步另一边，否则下次在客户端运行检查时会失败。
- 服务端没有自己的检查脚本，CI 也不比较两个仓库，漂移只在本地同级运行客户端检查时发现。
- 项目状态、功能设计、变更说明与决策记录仍只在客户端仓库。只有服务端的开发者能读到规则，但读不到这些记录。

重新评估条件：规则漂移反复发生；或者需要服务端开发者也维护状态与设计文档，此时考虑合并仓库。
