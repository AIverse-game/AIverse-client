# 0007：地图渲染由 Phaser 改为 Three.js

状态：采用。
日期：2026-11-08。

## 背景

[决策 0001](0001-web-stack-and-layering.md) 选了 Phaser 画 2D 地图。后来页面要有立体的设施：用户（2026-11-08）把四个 Three.js 参考 demo 放进 `demos/`（广告牌、共享办公空间、出生大厅、方块角色），要求尽可能还原 demo 的效果，“如果必要的话就迁移到 Three.js”。

Phaser 版本（变更 0077 的第一版）已经把 demo 的模型用 `ModelKit` 画成了等距的多边形，但还原不了：旋转的水晶与环绕的方块、上升的光点、流动的光幕、广告轮播与噪点、会随灯光变化的明暗、真正的深度遮挡（高的设施挡住后面的居民）、可旋转的镜头。这些都依赖三维场景。每个设施的静态外观还要靠自写的排序算法才不穿帮，每次重画一个工作空间约 4 毫秒。

## 候选方案

- **继续 Phaser，补一个排序和动画层**：保持现有点击与投影，但动画要逐帧重画整张图形，成本随设施数线性增长，遮挡始终是近似的；demo 的代码也不能直接用。
- **Phaser 和 Three.js 混用**（Three 画设施，叠在 Phaser 画布上）：两套相机和投影必须对齐，点击要分别判断，居民与设施之间的遮挡无法统一。
- **整个地图改用 Three.js**：地面、地块、设施、居民、标签都在同一个三维场景里；demo 的代码几乎可以原样使用；点击改为射线拾取。代价是重写 `MapScene`、地面和居民的绘制，增加 `three` 依赖。

## 决定与依据

整个地图渲染改用 Three.js，删除 Phaser 依赖。React 界面、状态、协议和网络层不变。

- 依赖：`three` 与 `@types/three`，只在 `apps/web` 使用，位于渲染层 `src/render`；层间依赖方向不变。
- 画面：透视相机按原来的视角（45° 偏航、40° 俯角）放置；点击改为射线拾取（居民、设施、地面）；标签与坐标读数用 DOM 覆盖层。地图不再是三倍大小的滚动画布，而是铺满视口、可用滚轮平移、Ctrl 滚轮缩放、右键拖动旋转、左键拖动平移的相机。
- 设施：广告位、工作空间、传送门、出生大厅、方块角色直接用 demo 的建模与动画；游戏厅没有 demo，按变更 0076 的外观用 Three.js 重写。静态几何按材质合并，减少绘制调用。
- 验证：用无头 Chromium 在本机截图核对（Playwright 只装在会话的草稿目录，不是项目依赖）。

## 影响

- 包体变化：Phaser 约 1.2 MB 压缩前，Three.js 约 0.7 MB，整体变小。
- 要重写的渲染文件：`MapScene`、`blockResident`、`facilityModels`、`facilityGeometry`、`floorSurface`、`layout` 的投影、变更 0077 第一版的 `ModelKit` 等；`residentFloat`、`lobbyPatrol`、`npcPose` 继续使用。
- `MapView`、样式和滚动规则改变；`mapScroll.ts` 的换算保留给相机平移。
- 无法在测试里直接渲染 WebGL：几何与相机的计算放进纯函数做单元测试，画面靠无头浏览器截图核对。
- 重新评估条件：设施数量很大时的帧率、需要移动端支持时的性能。
