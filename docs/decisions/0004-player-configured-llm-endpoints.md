# 0004：玩家在页面配置模型接口，服务端配置文件可以覆盖

状态：采用。
日期：2026-10-29。

## 背景

[决策 0003](0003-event-driven-agents-and-openrouter.md) 把 OpenRouter 定为第一家模型服务商。实现中地址写死，key 只从环境变量 `OPENROUTER_API_KEY` 读，模型只能由启动参数指定。游戏的核心设定是“玩家自带模型”，玩家可能用任何一家的 API。

用户决定（2026-10-29）：

- 不内置任何厂商的预设；
- 由用户在页面上配置；
- 服务端增加一个 YAML 配置文件，可以覆盖 API 地址、key 和模型；
- 页面上填的 key 记在本机浏览器；
- 启动参数保留脚本机器人，模型改为 `llm[:模型]`。

## 候选方案

- **接口形式**
  - 每家写一个适配器：能用各家的原生接口，但每多一家就多一份代码，还得维护厂商清单。
  - 只支持 OpenAI 兼容的 Chat Completions 接口，地址、key 和模型全由玩家给：多数厂商和本地推理服务（OpenRouter、DeepSeek、通义千问兼容模式、vLLM、Ollama 等）都提供这种接口，一份代码就够。
- **配置从哪里来**
  - 只用启动参数和环境变量：玩家要能接触服务器才能配置。
  - 页面上配置，经 WebSocket 发给服务端：玩家自己就能配置。
  - 页面配置，服务端配置文件可覆盖：开发或托管时可以用服务端自己的 key 和地址，玩家不必填。
- **覆盖的粒度**：可以按居民分别覆盖，也可以全局覆盖。用户选了全局覆盖，地址、key、模型三项都可以覆盖。
- **配置文件格式**：YAML 或 TOML。TOML 有标准库 `tomllib`，不加依赖；用户指定了 YAML，所以引入 PyYAML。

## 决定与依据

- **只接 OpenAI 兼容的 Chat Completions 接口**（含工具调用），不内置任何厂商。大脑 `ChatCompletionsBrain` 向 `{base_url}/chat/completions` 发请求；不兼容的厂商以后另写适配器，实现同一个 `Brain` 接口即可。
- **页面配置**：选中居民，填写 API 地址、key 和模型，交给 AI。协议增加：
  - `start_agent`：交给 AI，同时替换该居民原有的 Agent；
  - `stop_agent`：停止 AI，改回手动；
  - `agent_result`：对上面两种请求的答复。

  居民视图里的 `agent` 字段标出由 AI 驱动的居民及其模型，所有页面都能看到。目前没有玩家归属，任何页面都能配置任何居民。
- **配置文件**：YAML，用 `--config` 指定，默认读当前目录的 `aiverse.yml`，文件可以不存在。`llm.override` 下填了的项全局代替页面和命令行给的值，没填的仍用玩家给的。`welcome` 只告诉页面哪些项被覆盖，不发送具体的值。`aiverse.yml` 不进仓库，仓库里只放 `aiverse.example.yml`。
- **key 的处理**：
  - 页面把 key 存在 localStorage，这台电脑上用同一浏览器配置的人都读得到；
  - key 经 WebSocket 发给服务端，服务端只放在内存里用来调用接口，不写进状态、日志、`--agent-log` 或错误信息；
  - 服务端和配置文件里的设置在 repr 中都隐藏 key；校验出错时，错误信息不回显输入。
  - key 必须是不含空格的可打印 ASCII，否则 HTTP 客户端的报错会原样带出它；HTTP 客户端的异常不串进日志，服务商在错误信息里回显的 key 替换为 `***`。
- **命令行**：`--agent 居民=llm[:模型]`。地址、key 和没给的模型都来自配置文件；缺项时启动报错。不再读取 `OPENROUTER_API_KEY`。

## 影响

- 服务端新增运行时依赖 PyYAML，开发依赖增加 `types-PyYAML`。
- 协议版本升到 11。
- `Game` 可以在运行中启动、更换和停止 Agent；Agent 停止时关闭自己的 HTTP 客户端。每名居民每局最多 400 次模型请求，计数由 `Game` 按居民累计，停止或更换 Agent 不会重置。
- 尚无鉴权、Origin 检查和玩家归属：能连上服务端的人都可以接管任何居民，也能让服务端用配置文件里的 key 发请求。服务端只能在本机或可信网络上运行。key 在 WebSocket 上明文传输，部署到公网前必须改用 TLS 并加上鉴权。
- 需要重新评估的情况：要接入不兼容 OpenAI 接口的厂商；需要按居民或按玩家分别覆盖；有了玩家归属之后，规定谁能配置哪名居民。
