# 0006：每个仓库有自己的 Agent 规则

状态：采用。替代 [0005](0005-shared-agent-rules-in-each-repo.md)。
日期：2026-10-31。

## 背景

[0005](0005-shared-agent-rules-in-each-repo.md) 让两个仓库的 `.agents/rules/` 与 `.agents/skills/` 逐字相同，并由客户端检查比较两边。为了让同一份文字放在哪个仓库都成立，规则里满是“客户端……”“服务端……”的限定，链接不能指向本仓库自己的文档，服务端的规则里一半是 TypeScript，只和一端有关的规则改动也要在两边各提交一次。

## 决定与依据

- 用户决定把两个仓库当作彼此独立的项目：各自的 `.agents/rules/` 与 `.agents/skills/` 只描述本仓库，链接本仓库自己的文档，示例只用本仓库的代码。
- 通用的软件开发规范（任务闭环、独立审查、提交约定、测试分层与准备—执行—断言的写法）两边可以写得一样，但不作为共用文件维护，也不做逐字比较；一边改了，另一边是否跟进按那边的需要决定。
- 去掉 `scripts/check_repo.py` 中的跨仓库比较。
- 保留 0005 中的目录划分：规则在 `.agents/rules/`，与 `.agents/skills/` 并列；`docs/` 只放项目本身的知识。

## 影响

- 两边的通用部分可能逐渐出现差异，需要时由改动的人顺手对照另一边。
- 服务端仓库不维护状态、设计、变更说明与决策记录，这些仍在本仓库；服务端规则写明这一点，并要求不能访问时把内容写进交接。
